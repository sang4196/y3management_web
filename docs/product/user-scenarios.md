# 핵심 사용자 시나리오

승인된 TO-BE 업무 시나리오다. AS-IS에서 유래한 업무와 새 승인 방향을 근거에 구분한다. 세부 정책의 미정 부분은 실행 규칙으로 확정하지 않는다. 모든 흐름에 Role과 Data Scope를 적용하며 Master Admin은 Organization 전체, Branch Admin은 허용 Branch, Operator는 허용 Branch·업무, Trainer는 Allowed PT Scope에 한정한다. Branch 관계 정책은 MB-001–008을 따른다. [요구사항](requirements.md), [결정](product-decisions.md), [후속 질문](open-questions.md).

## SC-001. 운영 계정으로 담당 업무 시작

Scenario: 운영 계정으로 담당 업무 시작

Actor: Master Admin / Branch Admin / Operator / Trainer

Goal: 허용된 핵심 PT 업무에 접근

Preconditions: 신규 운영 계정 발급 및 해당 권한 설정

Main Flow: 계정으로 접근 → 권한 범위 업무 확인 → 회원/Pass/Session 등 담당 업무 수행

Alternative Flow: 인증 실패·비활성 계정·권한 없는 업무의 상세 처리는 ARCH-001/002에서 정의

Business Rules: 관리자 발급 계정, Trainer v1 로그인, Member 로그인은 Future Scope. Role과 Data Scope 분리 및 Backend Branch 접근 제한

Result: 허용된 업무에만 접근

Related AS-IS Evidence: F01/F57–59; AS-IS 인증; APPROVED-TO-BE PD-001–004/019/022. [기능](../analysis/03-feature-inventory.md), [흐름](../analysis/06-business-flows.md).

Open Questions: ARCH-001/002

2026-10-12 사용자 확정(Operator 업무 허용 지점 수 질문의 1번): v1 Operator 역할의 업무 허용 Branch는 한 시점에 하나만 지정한다. Operator는 그 지정된 단일 Branch에서 명시적으로 허용된 업무를 수행하며 같은 계정의 Operator 권한을 여러 Branch에 동시 부여하지 않는다. Branch당 Operator 한 명이라는 1:1 인원 제한을 추가하지 않으며 하나의 Branch에 여러 Operator가 있을 수 있다. 이 결정은 Operator 역할의 업무 Scope이며 기존에 허용된 겸임 역할의 독립적인 관리/PT 권한이나 Trainer Home Branch를 바꾸지 않는다(BR-OPS-011, PD-001/007, PR-001/003/030, ARCH-001, MB-004).

Operator 역할로 허용 업무를 시작할 때 현재 지정된 단일 Branch를 Backend에서 확인한다. Frontend 지점 선택/직접 ID/중복 Operator 권한 부여로 다른 지점 업무를 허용하지 않는다. 기존에 허용된 겸임 역할은 그 역할의 별도 Scope로 인가하며 Operator Branch를 Trainer Home Branch나 Member Home Branch로 자동 적용하지 않는다. 새 Operator 발급/최초 지점 지정 Actor는 Master Organization 전체/Branch Admin 자기 단일 Branch로 후속 승인됐으며 기존 Operator 지점 변경 Actor는 Master 전용으로 후속 승인됐으며 발급 절차·기존 계정 역할/다른 Scope 변경 권한·Operator 변경 대상/절차와 실제 역할/Caller 계약은 후속이다(BR-OPS-011).

Operator 발급 사례(2026-10-12, BR-OPS-011): 강남 Branch Admin이 강남 업무 Branch의 새 Operator 계정을 발급 → 일회용 최초 비밀번호 설정 링크 전달 → 대상자가 직접 비밀번호 설정 → 후속 요청에서 현재 계정/역할·강남 단일 Scope를 검증해 허용 업무 수행. 같은 관리자의 수원 Operator 발급·다른 역할 생성/기존 계정 권한 변경은 이 흐름의 허용 범위가 아니다. Master는 자기 Organization의 대상 Branch에서 발급 가능하다. 링크 세부 수명·활성화/로그인 계약은 후속이며 사례는 실행 결과가 아니다.

Operator 지점 변경 사례(2026-10-12, BR-OPS-011): 같은 Organization의 강남 Operator를 수원으로 이동하는 변경은 현재 Master만 수행한다. 강남/수원 Branch Admin은 기존 계정의 Branch 변경 불가. 저장 완료 이후 Operator의 업무 Scope는 수원 하나이며 강남 업무는 과거 발급 사실/직접 ID로 유지하지 못한다. 수원 발급용 전체 지점 Member 검색/승인 필드는 기존대로 허용되고 과거 강남 Pass의 Issued Branch·Member/Trainer 소속·과거 PT/지급은 보존한다. 실패 시 기존 강남 Scope 유지, 다른 겸임 역할의 독립 인가는 그대로다. 대상 상태/구체 계약·동시성은 후속이며 실행된 테스트 사례가 아니다.

Trainer 신규 로그인 준비 사례(2026-10-12, BR-OPS-012): 강남 현재 소속 Trainer에 대해 Master 또는 강남 Branch Admin이 허용 Scope/실제 Trainer 소속을 검증해 신규 로그인 계정 발급 → 일회용 최초 비밀번호 설정 링크 전달 → 대상자가 직접 설정 → 후속 실제 Trainer 연결/현재 Caller·허용 PT Scope로 업무 인가. 수원 Branch Admin은 강남 Trainer가 수원에서 지원 수업을 했어도 발급 불가. 발급 자체로 기존 계정의 관리자 역할/Trainer 연결·Home Branch·Compensation Setting·PT/지급 이력을 변경하지 않는다. 프로필 생성/연결·활성화·링크 수명/실제 로그인 계약은 후속이며 구현/검증 결과가 아니다.

2026-10-12 K3 개발 순서: 최초 계정 준비/관리자 로그인·현재 사용자/Scope → 지점 조회/타 지점 ID 차단 → logout/Branch Admin 차단·관리 Scope 변경 반영을 첫 개발 검증 기능으로 준비한다. 복구/추가 Master/Trainer 실제 연결은 후속이며 해당 v1 의무·운영 전 관리자 MFA/비상 복구 검증은 유지한다. 구체 API/저장/계약·인수 방식은 제안이며 코드 작성/운영 개시 승인은 아니다. [2026-10-12 K 일괄 승인](product-decisions.md#review-20261012-k-batch).

<a id="sc-002"></a>
## SC-002. 회원에게 PT Pass 생성하고 이용정보 확인

Scenario: 회원에게 PT Pass 생성하고 이용정보 확인

Actor: Master Admin(Organization 전체) 또는 Branch Admin(자신의 단일 관리 Branch) / Operator(부여된 허용 발급 Branch Scope). Trainer 단독 발급 불가; 발급 역할 겸임은 해당 독립 Scope로 판단(BR-OPS-010, 2026-10-12).

Goal: 회원의 이용 단위와 이력을 관리

Preconditions: 회원·트레이너·상품 등록 및 해당 업무의 Branch Scope 허용. 확정 관계는 BR-OPS-001을 따르며 교차 이용 상세 조건은 MB-001/002/003/005 결정 필요

Main Flow: 회원 검색 또는 신규 등록 → 상품/담당 트레이너와 구매 횟수·생성/시작 정보 확인 → 발급 당시 상품 가격·총횟수·Payment Type을 보존하는 Pass 생성 → 잔여·상태·이력 확인

2026-10-12 사용자 확정: 이 흐름에서 이용하는 Organization 공통 상품의 생성/수정은 Master Admin만 수행한다. Master 권한 없는 Branch Admin·Operator·Trainer는 공통 상품을 직접 변경할 수 없다. 공통 상품 준비와 개별 Member의 Pass 발급은 별도 업무이며 이번 상품 권한 결정으로 Pass 발급 Actor/조회 권한의 잔여 정책을 확정하지 않는다. 상품 수정 후 발급하는 새 Pass에는 변경 조건을 사용하고 기존 Pass는 발급 당시 조건을 보존한다(PR-006, BR-PAY-001, MB-007 CLOSED).

상품 판매 중단 사례(2026-10-12 사용자 확정): Master가 Product A의 판매를 중단하면 A로 새 Pass를 발급하는 요청은 거부한다. 판매 중단 전에 발급한 A의 Pass가 잔여 5회이고 다른 사용 조건을 충족하면 계속 이용하며 정상 수업 등록 후 잔여 4회가 된다. 판매 중단 자체로는 그 5회나 사용 상태/발급 조건·과거 수업/지급/정산을 변경하지 않는다. 이미 잔여 0이거나 수동 만료 등 다른 사용 불가 사유가 있으면 판매 중단 정책으로 이를 면제하지 않는다. 기존 Pass 조건 보존과 권한/선택 우선순위·지급 규칙을 유지한다(PR-006/003, BR-PAY-001/006, PD-011).

Alternative Flow: 이전 종료 Pass는 보존한다. 복수 사용 가능 Pass에서 FIXED_AMOUNT 우선 사용은 확정이며 추가 횟수·중단·재개 등만 후속이다.

수동 만료 흐름(2026-10-12 사용자 확정): 별도 만료일을 입력하거나 시간 경과로 자동 만료시키지 않는다. 권한 있는 관리자가 대상 Pass의 추가 이용을 수동 만료 처리하고 사유/처리 이력을 남긴다(기존 수동 운영 변경 원칙 동일 적용). 종료 Pass와 과거 수업/지급·정산 이력은 보존한다. 수동 만료의 관리 범위는 Master Organization 전체/Branch Admin 현재 관리 Branch=Issued Branch이며 잔여 횟수는 유지하고 사용만 차단한다(2026-10-12 사용자 확정). 예를 들어 잔여 5회는 만료 후에도 5회이고 양수 잔여라는 이유로 자동 재개하지 않는다. 잘못된 수동 만료는 같은 관리 범위의 관리자가 사유/이력을 남기고 같은 Pass에서 해제할 수 있다(2026-10-12 사용자 확정). 기존 만료 이력과 잔여는 보존하며 해제 자체로 5회를 늘리거나 새 Pass를 만들지 않는다. 해제 후 잔여 > 0 등 기존 사용 조건을 충족하면 다시 사용한다. 잔여 0 등 다른 차단 사유는 해제하지 않는다. 만료 전 실제 수업 당시 사용 가능했던 Pass는 현재 만료여도 기존 PT 권한·정산·현재 잔여 조건 충족 시 별도 해제 없이 늦게 등록/1회 차감할 수 있으며 현재 만료 상태·이력을 유지한다(2026-10-12 사용자 확정, BR-OPS-004). 별도 취소 복원/조정 연계·다른 종료 사유/시점·이력 사실 판정은 BR-001/002/007·ARCH-003 후속이다.

Business Rules: 회원 현재 PT 필드 덮어쓰기 모델을 복제하지 않음; 구매와 잔여 정책 별도. 상품 변경은 새 Pass부터 적용하며 기존 Pass의 발급 당시 가격·총횟수·Payment Type과 잔여를 덮어쓰지 않음(BR-011 CLOSED)

Result: 회원에게 연결된 명시적인 Pass와 조회 가능한 이용 이력

Related AS-IS Evidence: F02–06; B02; APPROVED-TO-BE PD-007/011. [기능](../analysis/03-feature-inventory.md), [흐름](../analysis/06-business-flows.md).

Open Questions: BR-001/002, ARCH-003, LEGAL-001

회원 신규 등록의 전화번호 필수 조건(2026-10-12 사용자 확정, BR-OPS-006): 이 흐름에서 신규 Member를 등록할 때 번호를 입력해야 하며 누락·빈 문자열·공백만이면 등록을 완료하지 못한다. 등록/수정 업무 인가를 받은 Actor에게 적용하는 입력 조건이며 이번 결정으로 Actor 권한을 추가하지 않는다. 일반 정보 수정으로 필수 번호를 비우지 않는 원칙은 기존 사용자 일관성 지시를 적용하고 다른 정보만 수정할 때는 기존 번호를 유지한다. 번호 형식·중복/인증·다른 필수 필드·보존/필요 삭제 및 계약은 후속이다. 실제 운영 연락처를 예시/로그에 복사하지 않는다.

회원 공유 연락처 사례(2026-10-12 사용자 확정, BR-OPS-006): 같은 Organization의 가족 Member A와 B가 가상 동일 번호 P를 쓰더라도 각각 별도 식별자로 등록할 수 있다. 번호 중복만으로 B를 거부하거나 A의 Pass·PT 이력·담당/지원 권한을 B와 합치지 않는다. 전화번호를 수정할 권한이 있는 Actor도 A의 번호를 B의 번호와 같게 바꿀 수 있다(사용자 일관성 지시 적용). 필수 입력·기존 인가는 유지한다. 번호 검색을 제공할 경우 A/B 중 현재 Caller가 조회할 수 있는 회원만 각각 반환하며 미인가 상대 회원 존재를 중복 안내로 노출하지 않는다. 번호 형식/검증·정규화·추가 경고/병합 기능·보존/필요 삭제는 별도이며 실제 운영 번호는 예시로 사용하지 않는다.

기존 이용권의 담당 교체 사례(2026-10-12 사용자 확정, BR-OPS-008): 담당 A의 20회 Pass를 5회 진행한 뒤 담당 B로 교체해도 같은 Pass/잔여 15회와 발급 당시 조건·Issued Branch를 유지한다. 기존 수업의 실제 수행 Trainer A 및 확정 지급/정산을 B로 바꾸거나 현재 B 보상 설정으로 재계산하지 않고, 취소/재발급·횟수 복원/재차감을 수행하지 않는다. 기존 원칙 적용으로 일반 교체는 저장 완료 후 반영하고 전후 담당/Actor·시점 이력·감사를 남긴다. 담당 관계를 인정하는 Pass에 대해 이후 Member 조회는 현재 B와 다른 유효한 담당/지원/관리 관계로 판단하며 A의 과거 PT 기록 조회는 기존 별도 Scope를 따른다. 교체 권한은 Master Organization 전체/Branch Admin 처리 시점 Member 현재 Home Branch로 확정(2026-10-12). 수원 발급/강남 현재 소속 Member는 강남 관리자 또는 Master가 교체하며 수원 발급 사실만으로는 불가하다. Member가 다시 이동하면 다음 교체는 새 현재 소속 기준이다. 비관리자 Operator/Trainer·범위 밖 직접 ID/위조 Scope는 거부하고 관리자 겸임은 관리자 Scope로 판단한다. 수동 만료/해제는 기존 Issued Branch 기준이고 Trainer 보상 설정 접근은 기존 Trainer Home Branch 기준이다. 교체 대상은 같은 Organization의 다른 지점 Trainer도 허용(2026-10-12). 강남 Member의 담당 B가 수원 소속이어도 교체할 수 있고 소속/Issued Branch·잔여·과거 기록은 유지한다. 담당 지정만으로 일반/지원 보상을 결정하지 않으며 실제 수원 소속 B가 수원에서 진행하면 일반 PT, 강남에서 진행하면 지원 수업으로 기존 규칙을 적용한다. B의 보상 설정 접근 권한이 강남 관리자에게 생기는 것은 아니다. 교체 전 실제 본인 수업은 이전 담당 A가 직접 누락 등록 가능(2026-10-12, BR-OPS-003/008): 9월 5일 A 수업/9월 6일 B 교체/9월 7일 A 등록에서 당시 A 담당/본인 수행·현재 Caller/Organization와 기존 Pass/정산 조건을 검증한다. 실제 수행 A·실제 수업 당시 소속/지점으로 보상 구분, 신규 일반 지급은 9월 7일 A 설정을 사용하며 B 설정/담당으로 바꾸지 않는다. 현재 B 담당 관계와 A의 회원 목록/상세·전화번호 조회 비복원·기존 확정 월 처리/Pass 우선순위는 유지한다. 교체 후 새 수업을 과거 담당 사실만으로 허용하지 않는다. 잔여를 모두 사용해 0인 Pass도 담당 A→B로 교체 가능(2026-10-12, BR-OPS-008). 잔여는 0이고 과거 수업/지급·발급 조건을 유지하며 새 담당 B는 기존 Member 기본 조회/허용 전화번호로 응대를 이어간다. 잔여 0 제외 필터를 켰을 때 Member 전체 Pass가 0이면 제외하고 다른 담당 Pass에 10회가 남으면 표시한다. 교체만으로 상태를 재개하거나 수업 차감을 허용하지 않는다. 교체 수동 만료/취소 등 다른 종료 사유의 상태·과거 담당/수행 사실 확인 불가/정정과 최소 식별/응답·선택 정보/계약·경합은 후속 결정이다.

2026-10-12 사용자 확정(이용권 횟수의 수동 조정 권한 질문의 1번): Pass 횟수의 수동 조정은 Master Admin의 Organization 전체 범위 또는 처리 시점 현재 관리 Branch가 해당 Pass의 Issued Branch인 Branch Admin에게 허용한다. 수원 발급/현재 강남 소속 Member의 이용권은 수원 Branch Admin 또는 Master가 조정하며, 강남 Branch Admin은 Member의 현재 소속만을 근거로 조정할 수 없다. 회원 소속이나 담당 Trainer가 바뀌어도 Issued Branch 기준은 유지한다. 이용권 수동 만료/해제와 같은 발급 지점 기준이며 담당 교체의 Member 현재 Home Branch 기준과 구별한다(BR-OPS-004/008/009, PD-007/010, PR-003/030).

수동 조정 사례: 후속 확정될 수량/목적/상태 조건을 충족한 수원 발급 Pass의 잔여를 수원 Branch Admin 또는 Master가 사유와 함께 조정하면 전후 잔여/증감량·Actor/Role/Branch Context·시점 이력/감사를 남긴다. 현재 Member가 강남 소속이어도 강남 관리자는 그 사실만으로 조정할 수 없다. 사유 누락·비관리자/범위 밖 직접 ID/위조 Scope 요청과 저장 실패는 직전 잔여/업무 이력을 유지한다. 과거 PT/지급·정산과 발급 조건/담당/소속을 다시 쓰지 않으며 실제 수업 취소의 자동 복원은 별도 기존 업무 규칙을 따른다(BR-OPS-009).

2026-10-12 사용자 확정(다른 지점에서 새 이용권 구매·발급 질문의 1번): Member는 같은 Organization의 Home Branch 밖 지점에서도 새 PT Pass를 구매·발급받을 수 있다. 수원 소속 회원이 강남에서 발급받으면 Member Home Branch는 수원으로 유지하고 새 Pass의 Issued Branch는 강남으로 기록한다. Member Home Branch와 Issued Branch가 같아야 한다는 제한을 두지 않는다. 기존 Member 식별자/소속·보유 Pass와 과거 PT/지급·정산 이력은 유지하며 타 지점 발급을 위해 Member를 지점별로 복제하거나 소속을 자동 이동하지 않는다(BR-OPS-001/010, PD-004/007, PR-002/003/030).

발급 사례: 승인된 Master·Branch Admin·Operator 발급 권한/실제 강남 Branch Scope와 후속 확정될 대상 활성/초기 조건을 충족한 Caller가 기존 수원 소속 Member를 허용된 최소 경로로 식별하고 판매 중이면서 허용된 공통 상품의 새 Pass를 강남에서 발급한다. 기존 Member는 수원 소속이고 새 Pass는 강남 Issued Branch/발급 당시 상품 조건을 가진다. 기존 수원 Pass나 과거 수업/보상은 변경하지 않는다. 새 강남 Pass의 만료/해제·수동 횟수 조정은 강남 발급 지점 관리 기준이고 담당 교체는 Member 현재 Home Branch 기준이다. 발급 업무를 위해 지점별 Member 복제/소속 자동 이동·전체 타 지점 회원/전화번호·다른 Pass 공개를 요구하지 않는다. 새 Operator 발급 절차·기존 계정 역할 부여·Master 전용 Operator 지점 변경의 대상/절차·추가 공개 정보·Member 선택용 최소 식별 응답/계약 및 실패/재시도·동시성은 후속이며 실제 구현/검증 사례가 아니다(BR-OPS-010).

2026-10-12 사용자 확정(새 이용권 발급 Actor 질문의 1번): 새 PT Pass 발급은 Master Admin·Branch Admin·Operator에게 각자의 허용된 실제 Issued Branch 범위에서 허용한다. Master는 Organization 전체, Branch Admin은 자신의 단일 관리 Branch, Operator는 부여된 허용 발급 Branch Scope에서 처리한다. 같은 Organization의 Member는 Home Branch가 발급 지점과 달라도 대상이 될 수 있으며 기존 Member/Home Branch를 유지하고 새 Pass에 실제 Issued Branch를 기록한다(BR-OPS-010, PD-004/007, PR-003/030).

발급 권한 사례: 강남 Branch Admin과 강남 발급 Scope를 부여받은 Operator는 나머지 발급/식별 조건을 충족하면 수원 소속 Member에게 강남 Issued Pass를 발급한다. Master는 Organization 범위에서 허용된다. 수원 Branch Admin이 강남 발급 지점을 직접 지정하거나 강남 Scope 없는 Operator가 강남 ID를 요청하면 거부한다. Trainer 역할만의 요청은 거부하고 Operator·Trainer 겸임자는 부여된 발급 Scope로 판단한다. 강남 Operator가 발급했더라도 기존 Pass 수동 횟수 조정/만료/해제·담당 교체나 공통 상품 수정/보상 설정 권한을 얻지 않는다. 발급용 같은 Organization 전체 지점 이름·전화번호 일부 검색은 후속 2번 승인으로 해결됐고 추가 공개 정보·Member 선택용 최소 식별 응답/계약과 새 Operator 발급 절차·기존 계정 역할/Scope 변경 정책은 후속이며 이 사례는 검증 계획이지 실행 결과가 아니다(BR-OPS-010).

2026-10-12 사용자 확정(발급용 타 지점 회원 검색 질문의 2번): Branch Admin·Operator는 자신의 허용된 실제 Issued Branch에서 새 PT Pass를 발급하기 위해 같은 Organization 전체 지점의 Member를 이름·전화번호 일부로 검색할 수 있다. 전화번호 전체 일치만을 요구하지 않으며 Member Home Branch가 Caller의 관리/발급 Branch와 다르다는 이유만으로 검색 후보에서 제외하지 않는다. Master의 기존 Organization 전체 범위는 유지한다. 검색은 기존 Member를 선택하여 실제 발급 지점의 새 Pass를 만드는 흐름이며 Member 소속 이동/복제나 기존 Pass·PT·지급·정산 변경을 수행하지 않는다(BR-OPS-010, PD-004/007/022, PR-002/003/030).

발급용 검색 사례: 실제 강남 발급 Scope가 있는 Branch Admin/Operator가 이름 일부 또는 가상 전화번호 일부를 검색하면 같은 Organization의 수원 소속 일치 Member도 발급 후보로 찾을 수 있다. 수원 소속이라는 이유만으로 제외하거나 전화번호 전체 일치를 요구하지 않는다. 같은 번호의 가족 A/B는 각각 별도 Member로 표시/선택하며 선택한 기존 Member의 소속을 유지한 채 강남 Issued Pass를 발급한다. 검색/선택만으로 소속 이동·자동 병합이나 회원 상세/다른 Pass/PT·보상 열람을 허용하지 않는다. 검색 결과 이름·전체 전화번호·현재 Member Home Branch 공개는 후속 1번 사용자 승인을 적용하며 추가 공개 정보·Member 선택용 최소 식별 응답/계약·나머지 대상/검색 조건은 후속이며 이 사례는 구현/실행 결과가 아니다(BR-OPS-006/010).

2026-10-12 사용자 확정(발급용 검색 결과 표시 정보 질문의 1번): 새 PT Pass 발급용 Member 검색 결과에는 이름·전체 전화번호·소속 지점을 표시한다. 소속 지점은 해당 Member의 현재 Home Branch이며 Caller 관리 지점/Pass Issued Branch/수업 Performed Branch와 구별한다. 같은 Organization의 타 지점 회원 검색 결과에도 동일하게 적용하고 부분 마스킹된 번호만 표시하도록 제한하지 않는다. 기존 이름·전화번호 일부의 Organization 전체 지점 검색과 현재 발급 역할/실제 Issued Branch Scope 인가는 유지한다(BR-OPS-010, PD-004/007/022, PR-002/003/030, NFR-001/005).

표시 사례: 허용된 강남 발급 업무에서 수원 소속 Member를 이름 또는 전화번호 일부로 검색하면 일치한 기존 Member의 이름·전체 전화번호·현재 소속 수원을 보여준다. “강남에서 발급”을 Member 소속 강남으로 표시하지 않는다. 공유 번호의 Member A/B는 각각 별도로 선택하고 선택한 기존 Member에 강남 Issued Pass를 발급한다. 일반 상세·다른 이력/보상 정보 조회, 회원/번호 수정·내보내기는 별도 권한이며 검색/선택만으로 업무 데이터를 변경하지 않는다. 실제 운영 번호 대신 가상 데이터를 사용하는 예정 사례로 구현/검증 완료가 아니다(BR-OPS-006/010).

2026-10-12 Operator 단일 지점 사례(BR-OPS-011): 강남으로 지정된 Operator는 강남 Issued Pass만 발급한다. 발급용 검색에서는 수원 소속 Member도 이름/전화번호 일부로 찾고 이름·전체 전화번호·현재 소속 수원을 확인/선택하여 기존 소속을 유지한 강남 Pass를 발급한다. 요청 Branch ID를 수원으로 바꾸거나 Operator 업무 지점 여러 개를 동시에 보유하여 수원 발급을 수행할 수 없다. 강남 일반 업무/새 Pass 발급의 다른 허용 조건과 관리자 전용 업무 제한은 그대로이며 실제 구현/검증 결과가 아니다.

발급 오류 흐름(M1): 잘못 발급한 미사용 Pass 식별 → 현재 Issued Branch 기반 만료 권한/사유 검증 → 잔여·원본 정보/이력 보존한 수동 만료 → 별도 기존 정상 발급 권한/대상/상품/활성 담당/최초 횟수 검증 → 올바른 새 Pass 발급. 원본 Member/조건/잔여 덮어쓰기나 별도 발급 취소 기능은 없다. 단계별 실패/재시도·관련성 조회 계약은 후속이다(BR-OPS-025; [M 승인](product-decisions.md#review-20261013-m-batch)).

T1/T2 발급/사용 시작: 허용된 관리자가 정상 신규 Pass 발급을 완료하면 Backend가 그 시각을 발급 시각으로 기록한다. 별도 시작일 없이 기존 잔여/상태·인가 조건을 충족할 때 사용하고 미래 시작일을 지정하지 않는다. 10월 3일 구매/10월 5일 시스템 발급이면 그 Pass를 10월 3일 실제 수업에 쓰지 못하며 과거 발급 날짜를 입력해 바꾸지 않는다. 미사용 발급 오류의 만료 후 정상 새 발급에도 새 시각/별도 원본을 적용한다(BR-OPS-031; [T 승인](product-decisions.md#review-20261013-t-batch); V-120/121 미구성·미실행).

U1 만료 담당 교체: 수원 발급/강남 Home Member의 만료·잔여 5회 Pass를 강남 Branch Admin 또는 Master가 같은 Organization 실제 활성 B에게 교체한다. 같은 Pass는 만료/잔여 5회·원래 발급 시각/조건과 과거 A의 실제 수업/지급·정산을 유지한다. B는 M2 현재 담당 Member 조회/응대를 이어가고 A는 다른 유효 관계 없이 일반 조회를 유지하지 않는다. 이 교체만으로 강남 관리자에게 수원 발급 Pass의 만료 해제/조정 권한이 생기거나 새 수업에 사용할 수 있게 되지 않는다. 기존 교체/감사를 적용한다(BR-OPS-008/005; [U 승인](product-decisions.md#review-20261013-u-batch); V-122 미구성·미실행).

## SC-003. Smartphone에서 Trainer의 PT 진행 등록(수업 완료 기록)

Scenario: Trainer의 현장 Smartphone 주요 업무; Desktop/Tablet에서도 수행 가능

Actor: 직접 로그인한 Trainer; 허용된 운영자 등록도 유지

Goal: 진행 사실을 남기고 Pass 잔여에 반영

의미: 기존 회원에게 실제 수행한 수업을 기록한다. 상품/Pass 생성이나 미래 예약·시간표 생성이 아니며 사전 Reservation은 필수가 아니다. 진행일과 시스템 기록 시점은 구별한다. 아래 지급 계산은 서버 내부 처리이고 Trainer에게 보상 설정을 표시하는 단계가 아니다.

Preconditions: Trainer 로그인 및 Allowed PT Scope 확인, 실제 Branch·Member·사용 가능한 Pass 확인. 미정 교차 Branch 정책은 MB-001/002/003/005 결정 후 적용

회원 검색·조회 사례(2026-10-12 사용자 확정): Trainer A는 본인이 담당 Trainer로 지정된 Pass를 가진 Member M을 검색/조회할 수 있다. 같은 지점이라도 미담당이고 지원 허용도 없는 Member N은 목록/검색/직접 ID 상세에서 조회할 수 없다. 타 지점 Member S는 A에 대한 개별 지원 허용이 확인되면 조회할 수 있지만 타 지점 전체 목록이 열리지는 않는다. Backend가 검증된 Trainer 연결/Organization Scope와 관계 사실을 확인하고 실제 PT 등록에는 기존 Actor/PT·Pass·정산 조건을 별도 적용한다. 관리자 겸임자의 별도 관리 Scope와 민감 보상 제한을 유지한다. 담당 관계 인정·지원 지정/철회/기간·공개 정보는 후속이다(BR-OPS-005, PR-002/029/030).

지원 대상 지정 사례(2026-10-12 사용자 확정): 수원 Home Branch Member S가 강남점에서 강남 Trainer A의 지원 수업을 받는다. 수원 Branch Admin 또는 Master는 A/S를 개별 지원 조회 대상으로 지정할 수 있다. 수원 Member 소속을 관리하지 않는 강남 Branch Admin은 수행 지점/Trainer 소속·Pass 발급 지점만을 근거로 지정할 수 없다. Backend는 현재 Actor 관리 Scope와 Member Home Branch·A/S의 Organization 관계를 확인하고 중요 권한 변경 감사를 남긴다. 허용된 A/S 관계만 반영하며 지점 전체 열람·Home Branch 변경·Trainer 보상/월 정산 권한은 추가하지 않는다. 기간/철회 주체·소속 이동 후 기존 허용·지정/철회 절차/대상 상태·공개 항목은 후속이다(BR-OPS-005, PR-002/029/030, NFR-004).

지원 조회 허용 유지 사례(2026-10-12 사용자 확정): 같은 Trainer A/Member S의 지원 조회 허용은 다음 날/다음 달이나 반복 지원 수업 이후에도 기간 연장 없이 유지한다. 수동 해제는 기존 지정과 같은 현재 Member Home Branch 관리 Scope의 Branch Admin 또는 Master만 처리한다(2026-10-11 사용자 일관성 지시). 별도의 담당/관리 권한이 없는 A는 해제 성공 후 해당 지원 허용만을 근거로 S를 다시 검색/조회할 수 없다. 다른 지원 관계와 기존 수업·Pass 차감·보상/정산은 이 해제만으로 바뀌지 않는다. Member/Trainer의 소속 이동 시 기존 허용 유지/종료는 아직 결정하지 않았다(BR-OPS-005, PR-002/029/030, NFR-004).

회원 소속 이동 후 지원 조회 사례(2026-10-12 사용자 확정): 수원 Member S가 강남 Home Branch로 이동해도 Trainer A/S의 기존 개별 지원 조회 허용은 재지정 없이 유지한다. Backend는 후속 조회에 현재 Caller/대상 관계를 확인하고 강남 Branch Admin/Master에게 현재 관리 범위의 지정/해제를 허용하며 이전 수원 관리자에게 과거 지정 사실만으로 허용하지 않는다. 이후 A의 Trainer Home Branch만 바뀌어도 같은 A/S 허용을 유지한다(사용자 일관성 지시 적용); A의 새 소속 관리자라는 이유만으로 S의 허용 관리 권한을 주지 않는다. 현재 Member 소속과 실제 관리 Scope가 기준이다. 기존 감사 이력·PT/Pass/지급·정산을 보존하고 일반/지원 보상 구분은 실제 수업 당시 Trainer 소속/수행 지점으로 계속 판단한다. 이동 자체의 승인/권한·시점/이력·다른 상태/필드 조건은 별도다(BR-OPS-005, PR-002/029/030).

잔여 0 회원 조회 사례(2026-10-12 사용자 수정 확정): Trainer A가 담당한 단일 Pass Remaining 0의 Member M과 Remaining 1의 Member N은 기존 인가/관계 조건을 충족하면 기본 목록·검색에 모두 나타나고 상세 조회할 수 있다. A가 “잔여 0인 회원 제외” 필터를 선택하면 결과에서 M을 숨기며 필터를 끄면 다시 포함한다. M의 조회 권한/담당 관계·과거 PT 내역은 바뀌지 않으며 미담당/미허용 회원은 어느 설정에서도 공개하지 않는다. 사용 가능한 Pass가 없는 M의 새 PT 등록/차감은 기존 Remaining > 0 조건에 따라 불가하다. 여러 이용권/지원 대상의 필터 잔여 집계 범위와 수동 만료/취소 등 다른 상태의 조회 영향은 후속이다(BR-OPS-005, PR-002/029/030).

여러 이용권의 잔여 필터 사례(2026-10-12 사용자 확정): Trainer A에게 조회 허용된 Member M의 A 담당 Pass는 0회지만 다른 Trainer B 담당/타 지점 발급 Pass에 10회가 남아 있으면 회원 전체 잔여가 있으므로 “잔여 0인 회원 제외”를 켜도 M을 표시한다. 전체 Pass의 집계 잔여가 0인 N은 필터 선택 시만 제외하며 기본/권한 있는 직접 상세 조회는 유지한다. A 담당 Pass가 없고 개별 지원 허용만 있는 S도 S 전체 Pass 잔여로 같은 판단을 한다. 수동 만료로 보존된 5회는 0이 아니므로 그 잔여만 있는 인가된 회원을 0 제외 조건으로 숨기지 않지만 현재 만료 Pass를 새 수업에 사용할 수는 없다. 실제 보유 Pass 없음이 확인된 허용 회원은 필터 집계 0회이며 조회 실패/미확인을 0회로 대체하지 않는다. 집계 대상만 넓어지는 것이며 미인가 회원/다른 Trainer 개별 내역 공개나 과거 기록/지급 변경은 없다. 다른 종료 상태별 잔여 정의·공개 필드/계약은 후속이다(BR-OPS-005, PR-002/029/030).

Trainer 전화번호 조회 사례(2026-10-12 사용자 확정): Trainer A는 현재 담당 관계가 확인되는 Member M과 A에 대해 개별 지원 조회가 허용된 Member S의 등록된 전화번호를 전체 번호로 조회한다. M의 잔여가 모두 0이어도 기존 조회 권한이 유지되면 번호도 조회할 수 있다. 같은 지점이라도 미담당/미허용 Member N의 번호는 직접 ID·검색·필드 선택으로 공개하지 않는다. S의 지원 허용이 해제되고 다른 담당/관리 권한이 없으면 후속 조회에서 S의 번호도 공개하지 않는다. 회원/Trainer Home Branch 이동 후 유지된 기존 지원 관계도 같은 인가 기준을 따른다. 번호 수정·내보내기·다른 개인정보 공개는 별도 권한이며 필수 입력/형식·중복·보존 정책을 이번 조회 승인으로 결정하지 않는다. 예시는 가상 정보만 사용한다(BR-OPS-005, PR-002/029/030, NFR-001/005, LEGAL-001).

Main Flow(일반 Session Payment 적용 대상): Smartphone 로그인 → 허용 Member/PT 정보 조회 → 실제 진행 Branch·날짜 확인 → 자신이 실제 수행한 Session 등록 → 사용할 Pass 결정(FIXED_AMOUNT 우선, 동일 Payment Type FIFO) → Pass 횟수 차감 → Pass 발급 당시 Product Payment Type 확인 → 권한 있는 관리자 저장 완료 이후 신규 Session에 적용되는 수행 Trainer Rate/Fixed Amount 적용 → Session Payment 계산·확정(RATE 1,000원 단위 올림; FIXED_AMOUNT 그대로) → 자신의 Session·잔여 반영 결과 확인 → 유효 Session Payment의 월 집계 대상 확인(지점 귀속은 MB-010 결정 필요)

Alternative Flow: 타 지점 수업 보상 전체는 SC-016의 추가실적 처리를 따른다. 지원 수업은 금액 없이도 기록·차감을 먼저 완료하고 관리자 건별 금액 저장 시 보상 확정한다. 미입력은 확정 0원과 구분·추적하며 위 일반 지급 흐름으로 대체하지 않는다. 미입력 건이 남으면 해당 Trainer·월 정산 확정을 차단한다. 월 귀속·마감/정정·연계 상세는 관련 OPEN이다. 같은 날 별개 수업은 각각 기록/차감하며, 해당 Trainer/실제 진행 월 정산이 미확정인 과거 수업도 기존 Allowed PT Scope에서 Trainer가 직접 등록한다(BR-OPS-002/003). 잔여 부족·종료 Pass 등 나머지 사용 조건과 시간대/월 경계는 관련 OPEN이다. 여러 날짜 일괄 입력은 I3으로 v1 보류/UX-001 CLOSED이며 실제 수업별 개별 등록이다

수업 구분 사례(2026-10-11 사용자 확정): 수원 소속일 때 강남에서 실제 수업한 뒤 강남으로 이동하고 기록을 등록해도 지원 수업이다. 반대로 수원 소속일 때 수원에서 수업하고 이동 후 등록해도 일반 PT이며, Rate/Fixed Amount는 기록 생성 시점 설정을 사용한다. 당시 소속 사실 확인 예외와 소급 등록 범위는 MB-001/BR-008의 잔여 OPEN이다.

타 지점 Pass 이용 사례(2026-10-11 사용자 확정): 수원에서 발급한 사용 가능한 Pass로 강남 수업을 기록할 때 별도 승인 대기 없이 기존 Pass 선택/차감을 수행한다. 사용 가능한 수원 발급 FIXED_AMOUNT와 강남 발급 RATE가 함께 있다면 FIXED_AMOUNT를 우선한다. Issued Branch와 Trainer/Member Home Branch는 유지하고 Performed Branch는 실제 강남으로 기록한다. 허용된 Actor/Member 조회/PT 업무 검증은 별도이며 타 지점 전체 회원 목록 조회를 자동 허용하지 않는다.

동일 일자 복수 수업 사례(2026-10-11 사용자 확정): 같은 회원이 오전/오후에 실제로 각각 PT를 받았다면 수업 2건을 따로 기록하고 기존 사용 가능 조건/우선순위에 따라 각 1회씩 차감한다. 같은 사용 가능 Pass의 잔여가 20회면 결과는 기록 2개/잔여 18회다. 날짜가 같다는 이유로 합치거나 거부하지 않는다. 첫 수업 저장 요청을 재전송한 것은 추가 수업이 아니며 추가 차감/지급을 만들지 않는다. 구체 재시도 식별 방식은 후속이다(BR-OPS-002).

과거 수업 등록 사례(2026-10-11 사용자 확정): 10월에 본인이 실제 수행한 9월 수업 누락을 발견했고 해당 Trainer/9월 정산이 미확정이면 기존 Allowed PT Scope에서 직접 등록한다. 당월/최근 N일 제한이나 월 변경을 이유로 관리자 대행을 요구하지 않는다. 일반 수당은 10월 신규 기록 생성 시점 Rate/Fixed Amount, 일반/지원 구분은 9월 실제 수업 당시 Home Branch와 Performed Branch 기준을 따른다. 기존 Pass 사용/차감 조건도 충족해야 한다. 확정 월은 Trainer가 임의로 반영하지 않고 기존 관리자 해제 후 반영/같은 월 재확정 원칙을 따른다(BR-OPS-003).

과거 수업의 이용권 후보 사례(2026-10-12 사용자 확정): 9월 20일 수업을 10월 5일 등록할 때 9월 1일 발급 RATE와 10월 1일 발급 FIXED_AMOUNT를 보유하고 있더라도, 수업 후 발급된 FIXED_AMOUNT는 후보에서 제외한다. 9월 발급 RATE가 기존 사용 조건을 충족하면 해당 후보를 사용한다. 일반 수당의 신규 기록 생성 시점 설정 적용은 유지한다. 나머지 상태/발급 사실 확인 조건은 후속이다(BR-PAY-006).

만료 전 수업 지연 등록 사례(2026-10-12 사용자 확정): 9월 20일 수업 당시 사용 가능했던 Pass를 9월 30일 관리자가 수동 만료하고 10월 5일 누락을 등록한다. 해당 Trainer/9월 미확정 등 기존 PT 권한·정산·현재 잔여 조건을 충족하면 사전 만료 해제 없이 후보에 포함한다. 기존 FIXED_AMOUNT 우선/FIFO로 그 Pass가 선택되고 현재 만료/잔여 5회라면 등록 후 만료/잔여 4회다. 만료 상태·처리 이력은 유지하며 실제 수업 1회 차감만 반영한다. 현재 잔여 0이면 등록을 위해 음수 차감을 허용하지 않고, 수업 후 발급 Pass를 대신 후보에 넣지도 않는다. 신규 일반 지급/지원 수업 처리와 기존 확정 월 해제 후 반영/재확정 조건은 유지한다(BR-PAY-006, BR-OPS-003/004).

Business Rules: BR-PAY-001–013의 일반 Session Payment 적용 범위와 BR-PAY-015/016을 구분한다. Session 등록 권한과 보상 설정 접근 권한은 별개이며 BR-PAY-010을 따른다. 타 지점 수업은 일반 PT 수당 대신 해당 수업의 보상 전체를 Additional Performance로 처리하며 일반 Session Payment와 중복 합산하지 않는다(MB-009 CLOSED). 타 지점 지원 수업은 기록·차감을 먼저 완료하고 관리자 건별 금액 저장 시 보상 확정한다. 미입력은 확정 0원과 구분·추적한다. 미입력 지원 수업이 남으면 해당 Trainer·월 정산 확정을 차단한다. 월 귀속·마감/정정 등은 BR-013, 업무 접근·귀속은 관련 OPEN을 따른다. 작은 화면에서 주요 정보와 터치 Action을 실질적으로 지원해야 한다. FIXED_AMOUNT 2회 + RATE 10회에서 3회 진행하면 FIXED → FIXED → RATE. 실제 날짜별 1회 원본이며 잔여 일관성과 감사는 유지한다.

Trainer 소속 이동 후 누락 수업 등록 사례(2026-10-12, BR-OPS-013): Master가 같은 Organization의 Trainer T를 수원→강남으로 일반 이동 처리하면 저장 후 현재 소속은 강남이다. 이동 전에 수원 소속으로 강남에서 실제 수행한 수업을 나중에 등록해도 당시 소속 수원/실제 강남 수행에 따라 지원 수업이며 현재 강남 소속만으로 일반 PT로 바꾸지 않는다. 기존 Pass 선택/차감·관리자 수동 추가실적·미입력과 0원 구별·월 정산 조건을 유지한다. 다른 겸임 관리/Operator Scope·현재 담당/개별 지원 관계와 과거 수업/보상은 자동 변경하지 않는다. 당시 소속 확인 불가/소급 정정 및 구체 계약/경합은 후속이며 실행 결과가 아니다.

2026-10-12 I1/I3 수용 사례: 과거 수업의 날짜만 알고 시작 시각은 모르면 확인한 뒤 실제 시작 날짜/시각으로 개별 등록한다. 임의의 00:00/현재 시각이나 ‘시각 미상’ 관리자 대행 기록으로 통과시키지 않는다. 같은 날 실제 오전/오후 두 수업은 각각 개별 입력/1회 차감이며 여러 날짜 일괄 입력은 v1 보류다. 기존 실제 날짜/월·발급/담당 사실·현재 인가/잔여/정산 조건과 생성 시점 일반 지급은 유지한다. [2026-10-12 I 일괄 승인](product-decisions.md#review-20261012-i-batch). 사례는 승인된 기대 결과이며 실행 검증 기록이 아니다.

금액 비공개 사례(N1): 비관리자 Trainer가 본인 PT를 등록/조회하면 기존 인가된 진행 기록/잔여 반영 결과를 확인하되 일반 지급/지원 수업 연결 보상 금액은 응답하지 않는다. 내부 확정 지급/지원 보상 원본과 정산 입력은 보존하고 가짜 0원으로 표시하지 않는다. 관리자 겸임자의 금액 조회는 별도 기존 행위별 관리 Scope로 확인한다(BR-PAY-021; [N 승인](product-decisions.md#review-20261013-n-batch)).

O1 사례: 허용된 회원의 A 담당 RATE 10회/B 담당 FIXED_AMOUNT 2회가 모두 적격일 때 A가 본인 실제 수업을 등록하면 B 담당 FIXED_AMOUNT가 1회로 차감되고 RATE 10회/담당 B는 유지된다. 일반 지급은 실제 수행 A의 생성 시점 설정으로 확정한다. 이후 발급/잔여0/부적격 Pass는 제외하고 등록 응답의 비공개 금액은 전달하지 않는다(BR-OPS-026; [O 승인](product-decisions.md#review-20261013-o-batch); V-110 미구성·미실행).

T1 과거 수업 후보: 10월 3일 수업을 10월 6일 늦게 등록해도 10월 5일 시스템 발급 Pass는 후보가 아니다. 10월 3일 이전 이미 발급된 다른 적격 Pass가 있다면 기존 FIXED_AMOUNT 우선/FIFO·현재 잔여/만료 예외·인가/정산 조건을 적용한다. 적격 후보가 없으면 새 Pass로 소급 대체하거나 실제 수업 시각을 임의 변경하지 않는다. 실제 당시 Home/Performed 보상 구분·새 PT 기록 생성 시점 설정은 별도로 유지한다(BR-OPS-031; [T 승인](product-decisions.md#review-20261013-t-batch); V-120 미구성·미실행).

## SC-004. 잘못된 Session 정정 또는 취소

Scenario: 잘못된 Session 정정 또는 취소

Actor: Master Admin 또는 실제 Performed Branch가 관리 Branch인 Branch Admin. Operator 역할만으로는 정정/취소 불가(2026-10-11 사용자 확정). Trainer 역할만으로는 본인 PT 진행 기록도 정정/취소 불가(2026-10-11 사용자 확정); 관리자 겸임자는 해당 업무의 관리 권한으로 판단

Goal: 오류를 바로잡으면서 업무 이력을 보존

Preconditions: 대상 Session 확인 및 정정 권한 보유. Performed Branch 자체 오류 정정은 Master Admin 전용이며 Branch Admin도 불가(2026-10-11 사용자 확정). Master Admin은 Organization 전체, Branch Admin은 해당 기록의 실제 Performed Branch가 관리 Branch인 경우 담당(2026-10-11 사용자 확정). Trainer의 Home Branch만으로 권한을 부여하지 않으며 금액 입력/전체 정산 권한은 별도 검증

Main Flow: 대상 기록/영향 확인 → 허용된 정정 또는 취소 수행 → Pass 잔여와 정산 반영 결과 확인 → 감사 가능한 변경 이력 확인

Alternative Flow: Operator 역할만으로 요청한 기록 정정/취소 또는 Trainer 역할만으로 요청한 본인 기록 정정/취소는 정산 확정 전후 모두 거부하며 PT 진행 기록·Pass 잔여·기존 지급/정산 결과를 변경하지 않는다. 다른 권한 없는 처리도 허용하지 않는다. 이미 검토한 정산·종료 Pass·비활성 회원 관련 기대 결과는 BR-007

확정 후 타 지점 수업 취소 흐름(2026-10-11 사용자 확정): 현재 수원 소속 Trainer의 강남 수업이 확정된 월 정산에 포함됐다면 수원 Branch Admin이 해당 Trainer·월을 해제 → 강남 Branch Admin이 PT 기록 취소 → 수원 Branch Admin이 같은 월을 재확정한다. 각 단계는 기존 관리 권한으로 처리하고 Master는 전체 흐름을 수행할 수 있다. 이전 확정본/이력과 기존 해제 사유/감사·재확정 조건을 유지한다. 수업 지점에 해당 Trainer 전체 정산/금액 입력 권한을 추가하지 않으며 구체 지급/추가실적 연동·복원 예외·단계 실패/재시도는 후속 대상이다.

수업 보상 연동(2026-10-11 사용자 확정): 허용된 기록 취소와 함께 그 수업 보상으로 입력한 추가실적을 자동 무효 처리하고 유효 정산/지점 비용에서 제외한다. 원래 보상 금액과 취소 이력을 보존하며 수행 지점의 기록 권한으로 다른 금액을 임의 수정하지 않는다. 확정 월은 기존 해제 → 취소/보상 무효 → 같은 월 재확정 순서를 따른다.

수행 지점 오류 정정 사례(2026-10-11 사용자 확정): 수원 소속 당시 수원 수업을 강남으로 잘못 등록했다면 Master가 같은 기록의 지점을 수원으로 정정하고 일반 PT 보상 방식으로 바로잡는다. 기존 Pass 차감은 유지하고 취소/재등록·복원/재차감하지 않는다. 기존 지원 보상은 원래 금액/이력을 보존하되 유효 합산에서 제외한다. 반대 전환도 지원 수업의 기존 관리자 수동 보상/미입력 월 확정 차단을 따른다. 확정 월은 기존 해제 → 정정 → 같은 월 재확정과 이전 확정본 보존을 동일 적용한다(사용자 일관성 지시). 일반 PT로 전환할 때 적용할 지급 설정 기준 시점은 MB-005/BR-007의 잔여 OPEN이다.

지원→일반의 적용 설정 사례(2026-10-11 사용자 확정): 최초 PT 기록 생성 시 Rate 50%, 수행 지점 정정 시 60%라도 50%로 일반 수당을 계산한다. FIXED_AMOUNT도 최초 생성 시 설정이 15,000원, 정정 시 20,000원이면 15,000원을 사용한다. 최초에 일반 지급을 계산하지 않았어도 당시 적용 설정을 확인해야 하며 현재 값으로 대체하지 않는다(BR-PAY-011).

Business Rules: 단순 row 삭제 금지; Pass 잔여·정산 일관성 및 이력 유지

Result: 정정 결과와 영향이 일치하고 과거 변경을 확인 가능

Related AS-IS Evidence: F20/21; B03; APPROVED-TO-BE PD-010/011/022. [기능](../analysis/03-feature-inventory.md), [흐름](../analysis/06-business-flows.md).

Open Questions: BR-007/009, ARCH-001/MB-005; 다른 정정의 지급/추가실적 연동·나머지 정정 조건·취소 시 잔여 복원 예외·최초 생성 시점 설정 근거 확인/저장·담당자 간 단계 계약/실패·재시도 상세

2026-10-12 K1 수용 사례: 같은 적격 RATE Pass의 1회 단가 50,000원/원래 기록 Rate 50%에서 실제 시작 날짜를 잘못 입력했다면 허용 관리자가 기존 기록을 취소·보존하고 실제 시점 조건을 검증해 올바르게 재등록한다. 재등록 생성 시점 Rate 60%라면 원래 25,000원은 보존/유효 합산 제외, 새 일반 지급은 30,000원이다. 소비 복원/새 Pass 우선 재선택·현재 잔여 1회 차감과 원본/새 기록 연결을 추적한다. 바뀐 각 실제 월이 확정이면 기존 관리자 인가/사유로 각각 해제·처리·재확정하고 이전본을 보존한다. 새 지원 수업은 기존 별도 관리자 수동 보상/미입력 차단을 따른다. Performed Branch 값 정정의 기록 유지/최초 생성 기준과 구별한다. [2026-10-12 K 일괄 승인](product-decisions.md#review-20261012-k-batch). 실행 결과가 아닌 승인된 기대 사례다.

W1 예: Trainer 과거 Home을 정정하니 기존 지원 수업이 일반 수업으로 바뀐다. Master가 사유/전후·이전 보상 이력을 보존하며 같은 PT/기존 Pass 차감·최초 생성 시각으로 명시적 정정한다. 최초 기록 생성 때 Rate 50%, 정정 때 60%이면 50%와 기존 소비 Pass 발급 조건을 사용한다. 기존 지원 보상은 유효 합계 제외/이력 보존한다. 반대 전환은 기존 관리자 Scope에서 지원 금액을 수동 입력하고 일반 지급 자동 복사/자동 0원을 하지 않는다. 실제 Member/수행자/시작 오류의 취소 재등록은 별개다(BR-OPS-033; [W 승인](product-decisions.md#review-20261013-w-batch); V-124 미구성·미실행).

<a id="sc-005"></a>
## SC-005. 월별 트레이너 지급액 검토

Scenario: 월별 트레이너 지급액 검토

Actor: Master Admin / 허용 Branch의 Branch Admin / 정산 조회 권한을 가진 Operator

Goal: 진행 실적과 지급액의 계산 근거 확인

Preconditions: 대상 Trainer·월의 적용 기본급, 유효 Session Payment 및 추가실적 확인. 기본급 적용 시작 월은 관리자가 미확정인 과거 월을 포함해 지정하고 변경이 적용되는 수동 지정 없는 기존 미확정 정산의 기본급·합계는 자동 반영한다. 미래 적용 월의 입력 범위 등 기본급의 남은 정책·지점 귀속·공개·추가실적 상세는 해당 OPEN 결정 필요. 타 지점 수업의 보상 전체 추가실적 처리는 MB-009 CLOSED이며 일반 Session Payment와 중복 합산하지 않는다.

Main Flow: Backend에서 관리 Scope와 대상 Trainer 현재 Home Branch 확인 → 허용 Trainer/월 선택 → 해당 월 적용 기본급 + 유효 Session Payment 합계 + 유효 추가실적 합계 및 구성 내역 구분 → 타 지점 지원 수업 보상까지 포함한 월 정산 전체 검토. Branch Admin은 조회 시점 자기 지점 소속 Trainer에 대해 이 흐름을 수행한다(2026-10-11 사용자 확정). 조회 대상 월·이전 확정본/세부 계산 근거·감사 공개의 남은 상세는 MB-006, 지점 귀속은 MB-010 OPEN이다.

Alternative Flow: 확정된 월의 기본급 오류는 해당 Trainer·월의 확정 해제 → 해당 월 적용 기본급 정정 → 동일 월 재확정으로 처리하고 이전 확정본은 이력으로 보존한다. 현재 설정 변경에 따른 자동 갱신과 구별한다. 기본급 오류 정정의 확정 해제·재확정은 Master Admin에게 Organization 전체, Branch Admin에게 각 처리 시점 대상 Trainer의 현재 Home Branch가 자신의 관리 Branch인 경우 허용한다. 관리 범위 안 본인 건도 포함하며 별도 Master 승인 없이 처리한다. 확정된 월의 기본급 오류 정정에서 확정 해제와 해당 월 기본급 수정 모두 사유가 필수다. Master Admin·Branch Admin 및 관리 범위 안 본인 건에 동일하게 적용한다. 해제 사유·해제자·시점과 변경 전후 기본급·수정 사유·수정자·시점을 이력으로 남긴다. 사유 없는 각 요청은 해당 작업을 거부하고 요청 직전 상태·금액·확정본을 유지한다. 기본급 오류 정정은 대상 Trainer의 해당 월 정산에만 적용하며 현재·미래 기본급 설정과 다른 월 정산은 유지한다. 지속적인 기본급 변경은 별도로 적용 시작 월을 지정하는 기존 흐름을 따른다. 미래 적용 월의 입력 범위 등 남은 정책은 BR-012 OPEN이다. 현재 설정이 바뀌어도 과거 확정 Session Payment를 유지한다. 지원 수업 보상 금액 오류는 해당 Trainer·월의 확정 해제 → 금액 정정 → 해당 월 재확정으로 처리하고 이전 확정본을 보존한다. 지원 수업 보상 금액 오류 정정의 월 정산 확정 해제·재확정은 Master Admin은 Organization 전체 Trainer, Branch Admin은 자신의 관리 Branch를 Home Branch로 가진 Trainer에 대해 허용한다. Branch Admin이 자신의 관리 Branch를 Home Branch로 가진 Trainer의 지원 수업 보상 정정을 위해 월 정산을 확정 해제·재확정할 때는 Master의 별도 승인을 두지 않는다. Master 승인 대기 단계 없이 관리 범위 안에서 직접 처리하며 이전 확정본과 해제·재확정 이력 및 감사를 유지한다. 지원 수업 보상 정정의 월 정산 확정 해제에는 사유가 필수이며, 사유 없이 해제할 수 없다. 사유·해제자·시점을 이력으로 남긴다. 과거 지원 수업 보상 정정·해당 월 정산 확정 해제/재확정에서 Branch Admin의 권한은 각 업무 처리 시점의 Trainer 현재 Home Branch를 기준으로 검증한다. 이전 소속만으로 권한을 유지하지 않으며 Master Admin의 Organization 전체 권한은 유지한다. 다른 오류 정정/취소의 반영은 BR-007/009/013 후속이다. RATE는 정상 등록 시 Session별 1,000원 단위 올림하여 확정했으므로 월 합계에 다시 올림하지 않는다.

Business Rules: Monthly Settlement = 해당 월 적용 Base Salary + 유효한 Session Payment 합계 + 유효한 Additional Performance 합계다. Trainer·대상 월·적용 기본급·Session 수·Session Payment 합계·추가실적 내역/합계·월 정산 합계를 구분한다. 2,500,000원 + 1,200,000원 + 150,000원 = 3,850,000원이며 여러 지점 수업으로 동일 월 기본급을 중복 가산하지 않는다. 타 지점 수업의 보상 전체는 Additional Performance로 반영하며 일반 Session Payment를 별도로 합산하지 않는다(MB-009 CLOSED, 2026-10-10 사용자 정정). 보상 설정 노출은 BR-PAY-010을 따른다. 현재 기본급 변경으로 과거 확정 정산을 자동 변경하지 않는다. 12개월 고정 평균은 요구하지 않는다.

최초 확정 흐름(2026-10-11 사용자 확정): 월 정산의 최초 확정은 Master Admin에게 Organization 전체 Trainer, Branch Admin에게 확정 처리 시점 대상 Trainer의 현재 Home Branch가 자신의 관리 Branch인 경우 허용한다. 관리 범위 안 본인 건도 포함하며 별도 Master 승인 없이 직접 확정한다. Backend에서 현재 관리 범위와 승인된 확정 조건을 확인한 뒤 해당 Trainer·월을 확정한다. 예를 들어 9월 수원 소속 Trainer가 10월 강남으로 이동한 뒤 아직 미확정인 9월 정산을 처음 확정하면, 현재 소속 기준으로 강남 Branch Admin은 허용 대상이고 별도 Master 권한이 없는 수원 Branch Admin은 거부한다. 금액 미입력 지원 수업이 남은 경우에는 권한이 있어도 확정하지 않는다. 최초 확정 권한으로 전체 월별 상세 공개나 비용 귀속을 자동 결정하지 않는다(MB-006/010).

정산 조회 수용 사례(2026-10-11): 수원점 소속 Trainer의 해당 월 적용 기본급 2,500,000원·유효 일반 지급 1,200,000원·유효 추가실적 150,000원 중 강남점 지원 수업 보상 30,000원이 포함되어 있다면, 수원점 Branch Admin은 지원 수업 보상을 포함한 구성 내역과 전체 합계 3,850,000원을 확인한다. 지원 수업 30,000원을 숨기거나 별도의 일반 Session Payment로 다시 더하지 않는다. 강남점 Branch Admin에게는 수행 지점만을 근거로 해당 Trainer의 전체 월 정산을 공개하지 않는다. 비용을 어느 Branch에 귀속할지는 이 예시로 결정하지 않는다.

이동월 기본급 비용 수용 사례(2026-10-11 사용자 확정): 10월 중 수원→강남으로 이동하고 10월말 Home Branch가 강남이면 해당 월 적용 기본급 2,500,000원 전액을 강남점 비용으로 집계한다. Trainer 월 정산에는 기본급을 한 번 가산하고 지점별 분할/일할 계산으로 지급액을 바꾸지 않는다. 10월에 수동 적용 기본급 1,500,000원을 지정했다면 비용도 그 적용액 전액이며 일반 설정액으로 덮어쓰지 않는다. 11월 다른 지점으로 이동해도 10월말 소속에 따른 과거 귀속을 유지한다. 현재 Home Branch 기준의 정정/확정/조회 권한은 기존 규칙대로 검증한다. 월말 소속을 식별할 수 없는 상황이나 비용 보고 공개/집계 상세를 이 예시로 확정하지 않는다.

일반 PT 수당 비용 수용 사례(2026-10-11 사용자 확정): 월중 수원→강남으로 이동한 Trainer의 해당 월 일반 지급이 수원점 수업 200,000원·강남점 수업 300,000원이라면 수원점 비용 200,000원·강남점 비용 300,000원으로 집계하고 Trainer 일반 수당 합계는 500,000원이다. 월말 Home Branch가 강남이어도 일반 수당 전액을 강남 비용으로 옮기지 않는다. 이미 확정된 수업별 지급액을 합산하며 현재 Rate/Fixed Amount 재계산이나 합계의 추가 올림은 하지 않는다. 이동월 기본급의 월말 소속 전액 귀속과 지원 수업 보상의 일반 지급 중복 합산 금지·기존 권한을 유지한다. 이후 소속 이동만으로 과거 수업의 비용 지점을 바꾸지 않는다.

지점별 비용 보고서의 별도 조회 흐름(2026-10-11 사용자 확정): Master Admin은 Organization 범위의 지점별 비용 보고서를 조회한다. Master 권한 없는 Branch Admin이 자기 지점 비용 합계를 요청해도 이 보고서는 공개하지 않으며 Operator·Trainer도 동일하다. Master·Trainer 겸임은 허용하지만 Branch Admin·Trainer 겸임만으로는 허용하지 않는다. 직접 ID·목록·검색·집계 경로에 Backend 인가를 적용한다. 앞의 Branch Admin 자기 소속 Trainer 해당 월 정산 전체 검토 흐름은 그대로 허용한다. 이 보고서 역할 결정으로 비용 귀속·금액·정정/확정 권한이나 보고서 항목·대상 월·집계/완전성·버전 등 남은 상세를 변경/확정하지 않는다(MB-006/010).

Result: 세 구성 요소를 설명 가능한 월 정산. 예시 합계 3,850,000원, 여러 지점 수업에도 기본급 중복 없음.

Related AS-IS Evidence: F26/27; APPROVED-TO-BE PD-009/012. [기능](../analysis/03-feature-inventory.md), [흐름](../analysis/06-business-flows.md).

Open Questions: BR-007/008/009/010/012/013, MB-006/010. 지급 이체/고객 결제 시나리오가 아니다.

입사·퇴사·휴직 월의 대안 흐름(2026-10-10 사용자 확정): 입사·퇴사·휴직이 있는 달의 적용 기본급은 관리자가 해당 Trainer·월의 금액을 직접 지정한다. 예를 들어 월 기본급 설정이 2,500,000원이어도 해당 월만 1,500,000원을 적용할 수 있으며, 이 지정으로 현재·미래 기본급 설정과 다른 월 정산은 변경하지 않는다. 나머지 유효 정산 구성 금액이 같을 때, 기본급 2,500,000원 대신 1,500,000원을 지정하면 해당 월 합계는 1,000,000원 감소한다. 기본급 한 번 가산·정산 자동 확정 없음·확정 월 변경의 기존 해제/정정/재확정 조건을 유지한다. 월별로 수동 지정한 기본급은 이후 일반 기본급 설정이 변경되어도 유지한다. 일반 설정 변경의 미확정 정산 자동 반영은 수동 지정이 없는 월에 적용하며, 수동 지정 월의 금액을 바꾸려면 관리자가 해당 월 금액을 직접 수정한다. 미확정 월의 기본급을 최초 수동 지정하거나 다시 수정할 때 모두 사유가 필수다. 사유가 없는 요청은 거부하고 요청 직전의 수동 지정 여부·적용 금액·월 합계를 유지한다. 대상 Trainer·월, 지정/수정 전후 금액·사유·처리자·처리 시점을 이력으로 남긴다. 미확정 월 기본급의 최초 수동 지정·수정은 Master Admin의 Organization 전체, Branch Admin의 각 처리 시점 대상 Trainer 현재 Home Branch가 관리 Branch와 일치하는 범위에서 허용한다. 관리 범위 안 본인 건도 포함하며 별도 Master 승인 없이 직접 처리한다. 추가 사용자 확정(2026-10-11): 해당 월 기본급은 권한 있는 관리자가 사유를 남기면 0원으로 명시적으로 수동 지정할 수 있다. 수동 지정한 0원은 미입력과 구분하며, 미입력이나 누락된 일반 설정을 자동으로 0원으로 대체하지 않는다. 해당 월 기본급에만 적용하고 다른 유효 지급·추가실적은 기존 규칙대로 합산한다. 미래 적용 월의 입력 범위와 월별 수동 지정 금액의 나머지 입력 제약 등은 BR-012/BR-010 OPEN이다.

시간 조건 시나리오(L1): 한국 시간 10월 31일 23:59에 10월 정산 확정 요청 → Master를 포함해 거부/미확정 조회·검토만 허용 → 11월 1일 00:00 이후 현재 관리자 Scope·지원 보상 미입력/필수 구성 등 모든 확정 조건을 다시 검증 → 충족 시 기존 확정/감사·이전본 정책에 따라 처리한다. 월 종료 자동 확정/비관리자 Trainer 월 정산 공개는 추가하지 않는다(BR-PAY-020; [L 승인](product-decisions.md#review-20261013-l-batch)).

S1 이전 정산 이력: 수원 소속 Trainer가 강남으로 이동한 뒤 강남 Branch Admin은 해당 Trainer의 수원 소속 시기 확정본/해제·재확정 이력과 정정 이유를 조회한다. 이전 수원 Branch Admin은 과거 소속/Performed·직접 ID만으로 조회하지 못한다. 당시 확정 금액/구성·이전 버전/변경자/시점을 보존하며 조회만으로 확정 해제/정정하거나 Master 전용 지점 비용 보고를 열지 않는다(BR-PAY-023; [S 승인](product-decisions.md#review-20261013-s-batch); V-118 미구성·미실행).

W2 예: 과거 Home 오류 영향 수업/보상·비용 중 정정 미완료 건이 있으면 해당 Trainer·월은 최초 확정/재확정할 수 없다. 다른 Trainer·월은 기존 조건으로 진행한다. 기존 확정본은 소속 정정만으로 자동 해제/변경하지 않고 필요한 월의 기존 권한/사유·해제/명시적 정정/같은 월 재확정·이전본 보존을 따른다. 종료 월·지원 보상 미입력 차단 등 기존 조건도 유지한다(BR-PAY-024; [W 승인](product-decisions.md#review-20261013-w-batch); V-125 미구성·미실행).

Y1/Y2 지점 비용 보고 예: Master가 종료된 9월을 조회한다. A의 미완료 영향 없는 최신 유효 9월 확정본은 비용 합계에 반영하고, B의 미확정/해제 중 또는 소속 오류 영향 정정 대기 9월은 합계에서 제외해 미완료 현황으로 표시한다. 이 합계를 전체 9월 비용 완성으로 안내하지 않으며 B를 0원 지급으로 표시하거나 이전 확정본을 끌어와 합산하지 않는다. 정정/재확정 완료 뒤에는 B의 현재 유효 최신본을 한 번 반영한다. 원본 확정본/감사는 보존하며 당월 지점 잠정 비용 보고는 제공하지 않되 기존 당월 Trainer 월 정산 조회·검토는 유지한다(BR-PAY-025; [Y 승인](product-decisions.md#review-20261013-y-batch); V-127/128 미구성·미실행).

Z1 보고서 검산 예: Master가 포함 가능한 Trainer A의 9월 비용을 조회한다. 기본급 2,500,000원은 월말 강남, 일반 PT 수원 200,000원/강남 300,000원, 지원 수업 강남 80,000원, 기타 실적 수원 50,000원이면 수원에서 A의 기여액은 250,000원·강남에서는 2,880,000원이다. 합계 3,130,000원을 각 지점에 다시 더하지 않는다. 지점별 항목/Trainer 내역을 대조하고 Y1/Y2 미완료 제외/표시·최신 유효 확정본/현재 Master Org 인가를 동일 적용한다. 원본/이전본 보존과 최소 조회/역사 비용/동시성 계약은 후속이다(BR-PAY-025; [Z 승인](product-decisions.md#review-20261013-z-batch); V-129 미구성·미실행).

## SC-010. 빈 운영 데이터에서 준비하고 일괄 전환

Scenario: 빈 운영 데이터에서 준비하고 일괄 전환

Actor: Master Admin 및 운영 전환 책임자(책임 배정 TBD)

Goal: 신규 웹 시스템으로 실제 운영 시작

Preconditions: 운영 준비 및 acceptance criteria 확인; 구체 준비 계획 OPS-001

Main Flow: 초기 Master Admin·Organization/Branch 준비 → 운영 및 Trainer 계정/기준정보·지급 정책 설정 → 필요한 회원/트레이너/Pass 새로 생성 → 준비 및 수용 기준 확인 → 일괄 전환

Alternative Flow: 짧은 준비/검증 기간은 별도 계획. 준비 미충족 상태에서 운영 전환을 완료로 보지 않음

Business Rules: 기존 데이터·계정·암호 이관 및 장기 이중 입력 없음. 최초 보상 설정도 Master Admin 또는 대상 Home Branch의 Branch Admin만 수행하며 감사 대상이다. 전환 책임자라는 이유로 권한이 생기지 않는다.

Result: 새로 생성한 데이터로 운영 시작

Related AS-IS Evidence: APPROVED-TO-BE PD-017/018/019; 기존 설정 F55는 AS-IS 센터 정보 변경의 참고. [기능](../analysis/03-feature-inventory.md), [흐름](../analysis/06-business-flows.md).

Open Questions: ARCH-002, OPS-001, PD-021; 전환 책임자는 새 로그인 Role 확정이 아님

## SC-011. 비활성화 이후 과거 이력 확인

Scenario: 비활성화 이후 과거 이력 확인

Actor: 해당 변경/조회 권한을 가진 운영자

Goal: 업무 대상 사용을 중단하되 과거 진행과 정산 보존

Preconditions: 회원·트레이너·Pass 및 연결 이력 존재

Main Flow: 대상 확인 → 허용된 비활성화/상태 변경 → 과거 Session과 정산 이력 조회

Alternative Flow: 남은 횟수·진행 중 Pass의 종료 조건은 BR-001/002. 법적 필요 삭제는 LEGAL-001 별도

Business Rules: Hard Delete가 기본 운영 기능이 아님; 과거 이력 조회 가능

Result: 비활성 업무 대상과 과거 결과를 구분하여 확인

Related AS-IS Evidence: F06/F10; APPROVED-TO-BE PD-011. [기능](../analysis/03-feature-inventory.md), [흐름](../analysis/06-business-flows.md).

Open Questions: BR-001/002/007, LEGAL-001

추가 승인 흐름(2026-10-12, BR-OPS-014): 관리자·Trainer 겸임자의 Trainer를 허용된 경로로 비활성화 → Trainer 역할에 따른 후속 PT 진행/회원 개인정보 접근 차단 → 독립 관리자 역할/Scope의 업무 계속 수행. 같은 계정 전체 차단은 별도다. 기존 인가된 운영자의 과거 이력 조회는 유지하되 비활성 Trainer 본인의 조회 예외를 부여하지 않는다. 승인된 재활성화/비활성 전용 로그인 정책의 나머지 상태 조합·개별 지원 관계 처리와 기술 계약은 ARCH-001/002·MB-001 후속이다.

Trainer 비활성화 Actor/대안 흐름(2026-10-12, BR-OPS-014): Master는 같은 Organization 전체, Branch Admin은 처리 시점 현재 자기 지점 소속 Trainer를 대상으로 한다. 대상이 이전에 자기 지점 소속이었거나 자기 지점 지원 수업을 했다는 사실만으로는 불가하다. 허용 시 Trainer 권한만 중단/겸임 관리자 업무 유지, 범위 밖 거부 시 직전 상태/권한/이력 유지. 재활성화/전체 계정 차단과 개별 지원 관계/재활성화 처리의 미정은 별도 게이트다.

잔여 Pass 유지 흐름(2026-10-12, BR-OPS-008/014): Trainer A 담당 20회권의 잔여가 15회인 상태 → 허용된 관리자가 A 비활성화 → 같은 Pass의 담당 A/잔여 15회/발급 조건·이력 유지, A의 Trainer 역할 회원 조회/PT 등록 차단. 사전 일괄 담당 교체 없이 비활성화를 완료할 수 있다. 이후 필요하면 Member 현재 Home Branch 기준의 권한 있는 관리자가 같은 Pass를 B로 교체하며 기존 교체 조건·잔여/이력을 유지한다. A의 Home Branch 관리자라는 사실만으로 이 후속 교체를 허용하지 않는다. 개별 지원·재활성화는 후속이다.

신규 지정/기존 유지 구분(2026-10-12, BR-OPS-008/014): 비활성 A의 기존 담당 Pass는 A/잔여/이력을 유지하되 A의 Trainer 업무 접근은 차단한다. 권한 있는 관리자가 담당을 B로 교체할 때 실제 활성 B만 허용하며 다른 Home Branch여도 같은 Organization/기존 조건이면 가능하다. B를 선택한 뒤 저장 전에 비활성화가 먼저 확정되면 교체를 거부/기존 A·잔여/이력 유지한다. B 지정이 먼저 완료된 뒤 비활성화되면 기존 B 담당 정보를 유지한다. 최초 담당 필수는 해결됐고 나머지 상태/재활성화·과거 PT 예외/경합 구현은 후속이다.

비활성화 전 누락 수업 대행 흐름(2026-10-12, BR-OPS-015): A가 실제 수업 수행 → A 비활성화(현재 Pass 담당 유지 또는 기존 권한으로 B 교체) → 누락 발견 → 관리자가 현재 인가/비활성화 전 수행 사실·기존 Pass/정산 조건 확인 → 실제 수행 A/과거 수업일·입력 관리자/현재 생성 시점으로 새 PT 기록/1회 차감·필요 지급 확정. A의 비활성/계정·현재 Assigned Trainer는 유지하며 재활성화/재배정하지 않는다. 일반 지급은 생성 시점 A 설정, 지원 수업은 기존 별도 관리자 수동 보상, 확정 월은 기존 해제/등록/같은 월 재확정 경로다. 대행 인가의 현재 사실 검증·역사 사실/선택 계약·실패/경합은 후속이고 A 본인 접근은 복구하지 않는다.

2026-10-12 사용자 확정(비활성화 전 누락 수업 대행 등록의 Branch Admin 기준 질문 1번): Master Admin은 자신의 Organization 전체, Branch Admin은 처리 시점 현재 관리 Branch가 실제 수업의 Performed Branch인 경우에만 대행 등록할 수 있다. Trainer 현재 Home Branch가 다른 지점이어도 실제 수업이 자신의 관리 지점에서 진행됐다면 허용한다. Trainer Home Branch·Member Home Branch·Pass Issued Branch 또는 과거 관리자 Scope만으로 대행 권한을 얻지 않는다(BR-OPS-015).

2026-10-12 일괄 승인 수용 사례: Master/현재 Trainer Home Branch 관리자가 Trainer를 재활성화할 수 있다. 다른 활성 역할 없는 비활성 Trainer는 로그인 불가이며 관리자 겸임의 독립 관리 업무는 유지한다. 계정 전체 복구는 별도 Master 전용이다. 기존 Member/Trainer/Pass가 있는 Branch도 Master가 비활성화할 수 있으나 새 배정/발급/실제 수업은 차단하고 기존 소속/Pass/잔여/이력을 보존한다. 비활성 지점의 과거 수업 누락/정정 경로는 남은 사실/상태 조합 게이트를 별도 확인한다. [2026-10-12 일괄 승인](product-decisions.md#review-20261012-batch).

2026-10-12 J2/J3 Member 흐름: Member M의 사용 가능 Pass 잔여가 10회인 상태에서 Master 또는 현재 M Home Branch의 Branch Admin이 회원 자체를 비활성화하면 M/Pass/잔여 10회·관계/과거 PT/지급·정산은 보존된다. M의 새 Pass 발급과 비활성 기간 실제 수업 등록은 다른 Branch에서도 거부한다. 허용 관리자가 같은 M을 재활성화한 뒤 Pass가 수동 만료되지 않았고 잔여/실제 Trainer·Performed Branch·현재 권한 등 기존 조건을 충족하면 기존 Pass를 사용한다. Pass가 수동 만료였다면 회원 복귀만으로 만료를 해제하지 않는다. Operator/Trainer 단독 상태 변경과 현재 Home 범위 밖 관리자는 거부한다. 잔여 0인 회원의 기존 기본 조회/선택 제외 필터와 과거 수업의 별도 규칙은 유지한다. [2026-10-12 J 일괄 승인](product-decisions.md#review-20261012-j-batch). 승인된 기대 사례이며 실행 검증 기록이 아니다.

수동 만료 후 담당 조회(M2): 유효 Trainer A가 현재 담당한 Pass만 수동 만료 → Member/기존 허용 전화번호 조회 유지 → 만료 후 실제 새 수업의 해당 Pass 사용은 거부. 만료 잔여 5회는 전체 잔여 선택 필터에서 0으로 바꾸지 않는다. 이후 담당이 바뀌거나 Trainer 자체 비활성/계정·역할/인증 철회 시 기존 현재 접근 제한을 적용하며 다른 독립 담당/지원/관리 근거는 각각 확인한다. 만료 전 실제 수업의 늦은 등록은 기존 예외/Pass/정산 조건을 따른다(BR-OPS-005/004; [M 승인](product-decisions.md#review-20261013-m-batch)).

V1 과거 Home 오류: Master는 자기 Organization Trainer/Member의 잘못 기록된 과거 Home 이력을 사유를 남겨 정정하고 원래 기록/정정 전후·Actor/시점을 보존한다. Member 현재 Home 관리자라도 Branch Admin은 이 과거 정정을 수행하지 못한다. 일반 이동은 즉시 적용을 유지하며 확인 불가 과거를 현재 Home으로 대체하지 않는다. 영향받은 PT/지급/정산 원본은 자동 갱신하지 않고 기존 권한/정정·필요한 월 해제/동일 월 재확정·이전본 보존으로 처리한다. 일반/지원 분류가 바뀌는 기존 PT의 구체 정정/지급 기준은 후속이다(BR-OPS-032; [V 승인](product-decisions.md#review-20261013-v-batch); V-123 미구성·미실행).

<a id="sc-012"></a>
## SC-012. 트레이너 지급 정책 설정·변경

Scenario: 트레이너 지급 정책 설정·변경

Actor: Master Admin 또는 대상 Trainer Home Branch의 Branch Admin

Goal: 트레이너별 적절한 지급 기준 관리

Preconditions: 대상 Trainer 등록과 보상 설정 권한 확인. 관리자·Trainer 겸임자는 보유한 관리 권한 범위 안이면 본인도 대상이 될 수 있다. 수원점 소속 Trainer의 세 항목은 수원점 Branch Admin이 접근 가능하며 강남점 지원 수업 이력은 강남점 Admin의 권한을 만들지 않는다.

Main Flow: Backend에서 Actor 권한·대상 Home Branch 확인 → Rate/Fixed Amount/Base Salary 조회·설정/변경(Base Salary 변경 시 적용 시작 월 지정, 미확정인 과거 월도 허용) → 별도 Master 승인 없이 저장 → 대상·항목·전후 값·Actor·권한/Branch Context·시점 감사 → Rate/Fixed Amount는 이후 신규 등록 Session에 적용 → Base Salary 변경이 적용되는 수동 지정 없는 기존 미확정 정산의 기본급·합계 자동 반영(별도 반영 작업 및 정산 자동 확정 없음) → 과거 확정 지급·정산 불변 확인

Alternative Flow: 관리 범위 밖 Branch Admin 및 관리자 권한 없는 Operator·Trainer는 직접 ID 요청과 감사 등 다른 경로로도 설정에 접근 불가. Branch Admin·Trainer 겸임자도 본인 Home Branch가 관리 지점과 다르면 본인 설정에 접근 불가. Base Salary 변경 시 미확정인 과거 월도 적용 시작 월로 지정할 수 있다. 예를 들어 10월에 아직 미확정인 9월부터 변경할 수 있다. 변경이 적용되며 월별 기본급을 수동 지정하지 않은 미확정 정산의 기본급·합계는 자동 반영한다. 미입력 지원 수업 등 기존 확정 차단 조건은 유지하며 정산을 자동 확정하지 않는다. 미래 적용 월의 입력 범위 등은 BR-012 결정 후 상세화한다. 이미 확정된 월 정산의 적용 기본급·합계는 자동 변경하지 않는다.

Business Rules: BR-PAY-009/010/011/014. 보상 설정 변경의 승인 생략은 BR-PAY-010을 따른다. 추가실적은 BR-PAY-015에서 별도로 확정했으며 Branch Admin의 본인이 아닌 소속 Trainer 직접 등록에 별도 Master 승인이 없다. 관리 범위 안이면 본인 추가실적 직접 등록과 별도 승인 없음도 허용한다. 동일한 감사 요구를 유지하며 월 마감/확정 절차의 남은 상세는 OPEN이다. Trainer의 별도 추가실적 신청·승인 흐름은 v1에서 제외한다(2026-10-11).

Result: 트레이너별 설명 가능한 정책과 과거 계산 기준

Related AS-IS Evidence: F14–16은 개별 지급률 참고; APPROVED-TO-BE PD-009/022. [기능](../analysis/03-feature-inventory.md), [흐름](../analysis/06-business-flows.md).

Open Questions: BR-010/012, ARCH-001. 설정 권한·기본급 적용 시작 월의 관리자 지정·미확정 과거 월 지정 허용·수동 지정 없는 기존 미확정 정산 자동 반영은 확정이며 미래 적용 월의 입력 범위·입력/구현 상세는 후속.

Rate 입력 시나리오(L2): 현재 인가된 관리자의 0/50/100% 정수 설정은 기존 감사/신규 지급 적용 규칙을 따른다. -1/101/50.25%는 거부하고 값 보정/절사·감사/기존 지급 변경이 없어야 한다. 명시적 0%는 일반 RATE 지급 0원이며 누락 설정을 0%로 채우지 않는다. FIXED/지원 수업 수동 보상·과거 확정 지급 규칙은 유지한다(BR-PAY-018; [L 승인](product-decisions.md#review-20261013-l-batch)).

Q1/Q2 사례: 허용된 관리자가 새 Trainer의 Rate 50%·Fixed Amount 0원·Base Salary 0원과 적용 시작 월을 명시하면 기존 인가/최초 감사와 함께 등록 완료할 수 있다. 어느 필수 항목이 누락되면 임의 0원/예시 값/현재 월로 채워 완료하지 않는다. 일반 FIXED 수업은 실제 설정 0원, 해당 월 기본급 0원+유효 지급 100,000원+실적 20,000원은 120,000원이다. 서비스라는 이유로 설정 누락을 0원 처리하거나 과거 확정 지급/정산을 바꾸지 않는다. 이후 이름/연락처 수정에 보상 재입력/초기화를 요구하지 않는다(BR-OPS-028/PAY-022; [Q 승인](product-decisions.md#review-20261013-q-batch); V-114/115 미구성·미실행).

R1 Trainer 기본정보: 허용된 관리자가 신규 Trainer의 전화번호와 Q 필수 보상 값을 입력해 등록하며 전화번호 누락/null/빈 값은 완료하지 않는다. 이름만 수정하면 기존 전화번호/보상 값을 유지하고 IAM Login ID/역할·계정 연결/보상/과거 지급을 자동 변경하지 않는다(BR-OPS-029; [R 승인](product-decisions.md#review-20261013-r-batch); V-116 미구성·미실행).

S2 보상 변경 이력: 같은 이동 뒤 현재 강남 Branch Admin은 이전 수원 시기의 Rate/Fixed Amount/Base Salary 변경 전후 값·변경자·시점도 조회한다. 이전 수원 관리자는 별도 현재 권한 없이 조회하지 못하고 Operator/Trainer 단독은 본인 이력도 불가다. 원래 변경 Role/Branch Context·최초 값 없음/명시적 0을 보존한다. 현재 설정 변경이나 과거 지급 재계산을 수행하지 않으며 로그인·계정 관리 감사는 Master 전용이다(BR-PAY-023; [S 승인](product-decisions.md#review-20261013-s-batch); V-119 미구성·미실행).

## SC-013. Master Admin의 Branch 관리

Actor: Master Admin

Goal: Organization의 여러 운영 지점을 조회·등록·관리

Main Flow: Organization의 Branch 목록 조회 → Branch 등록 또는 정보 관리 → 허용 Branch 업무 데이터 조회 → Branch별 Session/Settlement 확인

Business Rules: Branch 구조 관리 주체는 Master Admin. Branch Admin은 Organization 구조 및 다른 Branch 생성/수정 불가. 활성/비활성 가능성을 고려하되 상태·처리 규칙은 MB-008 결정 전 확정하지 않음. 중요 관리 행위의 Actor·Role·Branch Context 감사.

Open Questions: MB-004/007/008. [PR-020](requirements.md#pr-020), PD-004/022.

R2 자기 지점 수정: 강남 관리 Branch Admin은 강남 지점명/대표 연락처를 수정하고 감사를 남길 수 있다. 수원 Branch ID 직접 요청이나 함께 전송한 운영 상태/관리자 Scope 필드로 권한을 넓힐 수 없다. 현재 관리 Branch가 바뀌면 후속 요청은 새 현재 Scope로 검증한다. 같은 Branch 식별과 과거 Home/Issued/Performed·잔여/확정 보상/정산은 유지한다(BR-OPS-030; [R 승인](product-decisions.md#review-20261013-r-batch); V-117 미구성·미실행).

<a id="sc-014"></a>
## SC-014. Branch 간 무단 접근 차단

Actor: Branch A만 허용된 Branch Admin

Goal: 자신의 Branch 업무를 수행하면서 다른 Branch의 정보 보호

Main Flow: Branch A Member/Trainer/Pass/Session/운영 데이터/Settlement의 허용 업무 수행 → Branch A 범위 결과만 확인

Alternative Flow: 허용되지 않은 Branch B Member 등의 ID로 조회·수정 시도하면 Backend에서 금지. 목록·검색·집계·정산에서도 허용하지 않은 Branch 자료를 제공하지 않음. 메뉴를 숨기는 것만으로 통과하지 않음.

Business Rules: 단일 Branch Admin Scope를 Backend에서 강제한다. 자기 Branch 소속 Trainer 보상 설정은 허용되나 타 지점 Trainer의 지원 수업만으로는 접근 불가다. 특정 교차 업무 허용 조건과 타 지점 전체 목록 조회는 구별한다. 현재 자기 지점 소속 Trainer의 해당 월 정산 전체 금액·구성 내역에는 타 지점 지원 수업 보상도 포함해 공개한다(2026-10-11 사용자 확정). 다른 현재 소속 Trainer의 전체 정산은 수행 지점만으로 공개하지 않는다. 남은 공개 상세는 MB-006 OPEN이다.

Result: 허용 Branch 범위의 운영 결과와 타 Branch 접근 차단

Related requirements: [PR-030](requirements.md#pr-030), NFR-001; PD-001/004.

Open Questions: MB-002/003/004/005/006. Branch Admin 단일 Branch 관리는 확정이다.

회원 소속 이동 인가 사례(2026-10-12 사용자 확정, BR-OPS-007): 현재 수원 Home Branch의 Member M은 Master 또는 수원 Branch Admin이 같은 Organization의 강남 Branch로 이동시킬 수 있고 받는 강남 관리자의 별도 승인은 필요하지 않다. 이동 전에는 강남 관리자라는 사실만으로 M을 이동시킬 수 없다. 새 Home Branch가 반영된 이후에는 강남 관리자/Master가 현재 관리 범위에서 후속 변경/지원 지정·해제를 처리하며, 별도 현재 권한 없는 이전 수원 관리자가 과거 소속/처리자라는 이유로 다시 이동할 수 없다. Backend는 직접 ID/위조 role·source/target Branch를 통한 우회를 막는다. 기존 Trainer의 개별 지원 허용은 유지하고 기존 Pass의 발급 지점/잔여·과거 PT/지급/정산은 바꾸지 않는다. 이전 지점의 발급 Pass/수행 수업 등 다른 독립 업무 권한은 기존 기준으로 별도 판단한다. 중요 변경 이력/감사 원칙을 적용하며 적용 시점·이력 정정/대상 Branch 상태·계약/경합 상세는 후속이다.

회원 소속 이동 즉시 적용 사례(2026-10-12 사용자 확정, BR-OPS-007): 수원 관리자의 수원 Member M → 강남 Home Branch 변경을 성공적으로 저장하면 그 시점부터 M의 현재 소속은 강남이다. 성공 이후 시작되는 후속 요청의 Home Branch 기반 관리/지원 지정·해제는 강남 관리자/Master 범위이며, 별도 독립 권한 없는 이전 수원 관리자가 예전 화면/ID로 다시 이동시킬 수 없다. 재로그인이나 다음 날까지 기다리는 조건은 없다. 미래 적용일 예약 이동은 v1에서 지원하지 않는다. 저장 실패 시 수원 Home Branch를 유지하며 기존 지원 허용·Pass/과거 PT/확정 지급/정산을 보존한다. 과거 소속 이력 정정/대상 Branch 상태 및 진행 중 요청·동시 이동/실패 일관성은 후속 계약 검증 대상이다.

회원 이동의 대상 지점 활성 검증 사례(2026-10-12 사용자 확정, BR-OPS-007): 기존 이동 권한을 가진 Master/수원 Branch Admin도 비활성 강남 Branch로 Member M을 이동시킬 수 없다. UI에 보이는 선택 여부나 요청의 활성값·직접 Branch ID와 무관하게 Backend가 현재 대상 상태/동일 Organization을 확인하고 거부하며 M의 기존 수원 Home Branch·개별 지원 허용·Pass/과거 이력은 그대로다. 같은 Organization의 활성 Branch는 기존 인가/나머지 조건을 충족하면 저장 즉시 이동 가능하다. Branch 비활성화 자체의 기존 회원/이용권 처리·비활성 출발 지점 업무·상태 변경/이동 경합은 이번 대상 조건 승인과 별도 후속이다.

<a id="sc-016"></a>
## SC-016. 타 지점 수업과 추가실적

Actor: 허용된 PT 업무 범위의 Trainer; 추가실적 직접 등록은 Organization 전체 Trainer에 대한 Master Admin 또는 대상 Trainer의 Home Branch를 관리하는 Branch Admin. 관리자·Trainer 겸임자는 관리 범위 안에서 본인 직접 등록 가능. 본인 직접 등록 건도 별도 승인 없음. Trainer의 별도 추가실적 신청·승인 흐름은 v1에서 제외(2026-10-11)

Goal: 실제 수업·Pass 사용 이력과 타 지점 수업의 전체 보상을 추적하고 중복 정산을 방지

추가실적 등록 흐름 경계(2026-10-11 사용자 확정): v1 추가실적은 권한 있는 관리자의 직접 등록만 지원하고 Trainer의 시스템 내 별도 신청·승인/반려 흐름은 두지 않는다. Trainer는 실적 내용을 관리자에게 전달하며 기존 Master Admin/Branch Admin이 허용된 관리 범위에서 입력한다. 회원 유지 등 수업과 무관한 실적도 관리자 직접 입력 흐름을 따른다. 아래 Trainer의 지원 수업 PT 진행 기록·Pass 차감은 그대로 수행하며 별도 보상 신청이나 승인 대기를 거치지 않는다. 관리자·Trainer 겸임자는 기존 관리 범위 안에서 본인 실적을 직접 등록할 수 있고 감사는 유지한다.

지원 수업 외 실적의 등록 수용 사례(2026-10-11 사용자 확정): 회원 유지 등 지원 수업 외 실적은 기존 권한 있는 관리자가 내용과 금액을 함께 입력해야 등록이 완료된다. 금액 없는 요청은 등록 완료/정산 입력으로 반영하지 않고 자동 0원이나 일반 지급 계산식으로 채우지 않는다. 금액 미정 실적의 선등록/후입력 흐름은 두지 않는다. 아래 지원 수업의 실제 PT 기록/차감 선완료·관리자 금액 후입력 흐름은 그대로 유지한다. 관리자 대상 범위·관리 범위 안 본인 등록·승인 생략·감사·발생 당시 Home Branch 비용 귀속은 유지하며 0원 허용·나머지 입력 제약·정산 월·정정/취소는 별도 OPEN이다.

지원 수업 외 실적 금액 수용 사례(2026-10-11 사용자 확정): 회원 유지 등 비지원 실적을 기존 권한 있는 관리자가 등록할 때 금액 0원·음수·누락 요청은 거부하고 유효 실적/정산 입력으로 반영하지 않는다. 사유를 입력해도 0원 등록은 불가하다. 허용된 양수 금액과 실적 내용을 함께 입력해야 등록이 완료된다. 아래 실제 지원 수업의 사유 필수 0원 확정 허용은 그대로 유지하며 두 범위를 혼동하지 않는다. 기존 권한·본인 등록·승인 생략·감사 및 발생 당시 Home Branch 비용 귀속과 나머지 입력 제약/정정·취소 OPEN은 유지한다.

Master는 Organization 범위, Branch Admin은 본인 Trainer Home Branch가 관리 Branch일 때 허용하고 다르면 거부한다. 본인 건도 별도 승인 없이 처리하며 동일한 감사 대상이다. 관리 범위 검증과 Actor/대상 동일인 추적은 유지한다. 지원 수업 외 실적의 금액 외 정보 수정/취소의 소속 이동 시 권한 기준 시점 등은 BR-013 OPEN이다. 월 정산 확정으로 승인 생략을 확대하지 않는다. 등록 주체 결정으로 정산 비용 귀속·공개나 타 지점 전체 열람 범위를 정하지 않는다.

Result: 실제 기록·Pass 차감과 감사를 유지하며 타 지점 수업의 보상 전체는 Additional Performance로 처리한다(MB-009 CLOSED, 2026-10-10 사용자 정정). 동일 수업의 일반 Session Payment를 정산에 별도로 합산하지 않는다. 진행 기록 저장 시점에 금액 미입력이어도 기록·차감은 완료하며 보상 확정은 관리자 금액 저장 시 이뤄진다. 미입력은 확정 0원이 아니다. 해당 Trainer의 해당 월 정산 대상 지원 수업에 금액 미입력 건이 하나라도 있으면 그 Trainer·월 정산을 확정할 수 없다. 타 지점 지원 수업 보상은 권한 있는 관리자가 사유를 기록하면 0원으로 명시적으로 확정할 수 있다. 사유 없는 0원 입력은 보상 확정이 불가하다. 사유를 남기고 확정한 0원은 금액 미입력이 아니므로 그 건으로 월 정산 확정을 차단하지 않는다. 다른 미입력 건이 남으면 기존 차단 조건을 유지한다. 월 정산 확정 전 지원 수업 보상 금액 수정은 Master Admin에게 Organization 전체, Branch Admin에게 대상 Trainer Home Branch가 자신의 관리 Branch인 경우 허용한다. 관리 범위 안의 본인 건도 허용하고 변경 이력을 남긴다. 월 정산 확정 전 지원 수업 보상 금액 수정은 Master Admin·Branch Admin 모두 관리 범위 안에서 본인 건을 포함해 별도 승인 없이 저장 성공 즉시 반영한다. Master나 다른 관리자의 승인 대기를 두지 않으며 권한 검증과 변경 이력을 유지한다. 월 정산 확정 전 지원 수업 보상 금액의 모든 수정에는 변경 사유가 필수다. 양수 간 변경·0원에서 양수로 변경·양수에서 0원으로 변경 모두 적용하며, 사유 없이는 금액을 수정할 수 없다. 변경 전후 금액·변경 사유·수정자·수정 시점을 이력으로 남긴다. 확정된 월 정산에서 지원 수업 보상 금액 오류를 발견하면 해당 Trainer·월 정산의 확정을 해제하고 금액을 정정한 뒤 해당 월 정산을 다시 확정한다. 이전 확정본은 이력으로 보존한다. 지원 수업 보상 금액 오류 정정의 월 정산 확정 해제·재확정은 Master Admin은 Organization 전체 Trainer, Branch Admin은 자신의 관리 Branch를 Home Branch로 가진 Trainer에 대해 허용한다. Branch Admin이 자신의 관리 Branch를 Home Branch로 가진 Trainer의 지원 수업 보상 정정을 위해 월 정산을 확정 해제·재확정할 때는 Master의 별도 승인을 두지 않는다. Master 승인 대기 단계 없이 관리 범위 안에서 직접 처리하며 이전 확정본과 해제·재확정 이력 및 감사를 유지한다. 지원 수업 보상 정정의 월 정산 확정 해제에는 사유가 필수이며, 사유 없이 해제할 수 없다. 사유·해제자·시점을 이력으로 남긴다. 과거 지원 수업 보상 정정·해당 월 정산 확정 해제/재확정에서 Branch Admin의 권한은 각 업무 처리 시점의 Trainer 현재 Home Branch를 기준으로 검증한다. 이전 소속만으로 권한을 유지하지 않으며 Master Admin의 Organization 전체 권한은 유지한다. 남은 정정·취소 절차는 BR-009/013 등 관련 OPEN을 따른다. 미입력 건을 제외하거나 0원으로 간주한 확정은 허용하지 않는다. 이미 기록한 진행 내역·Pass 차감은 유지한다. 월 귀속·마감/정정·추적 표현·진행 기록 연계 상세·지원 수업 외 실적의 남은 입력 제약은 BR-009/013 등 관련 OPEN이다.

Open Questions: MB-001/002/003/005의 교차 허용 조건, BR-013 추가실적 처리, MB-010 정산 귀속. MB-009 지급 구성은 해결됨.

수행 지점/보상 공개 분리(N2): 현재 수원 Home Trainer A의 강남 지원 수업 보상 30,000원이 확정돼도 강남 Branch Admin에게 금액을 공개하지 않는다. 강남의 허용 PT 기록 조회/정정과 금액 열람은 별도다. 비관리자 A의 본인 PT 내역에서도 금액은 비공개다(N1). 현재 수원 관리자의 기존 정산 구성/보상·정산 업무와 Master Organization 범위는 유지하며 다른 지점 PT 기록 전체 조회를 추가하지 않는다. 현재 Home 이동/역할 철회 후 각 후속 조회를 현재 사실로 인가한다(BR-PAY-021; [N 승인](product-decisions.md#review-20261013-n-batch)).

O2 사례: 수원 Home Trainer A를 강남 Home 회원 M의 개별 지원 대상으로 허용하면 A 담당 Pass가 없어도 조회와 A 본인의 실제 수업 등록이 가능하다. Member 전체 적격 Pass를 기존 우선순위로 차감한다. 수원에서 실제 수업하면 일반, 강남에서 하면 타 지점 지원 보상으로 구분하며 지원 지정 표시만으로 분류하지 않는다. 지정/해제는 M 현재 Home 관리자 또는 Master가 하고 금액 공개/정정/취소/발급 권한은 추가되지 않는다. 지원 지정 전/해제 후 과거 등록은 BR-OPS-027(P1/P2)의 확정 조건을 따른다(BR-OPS-026; [O 승인](product-decisions.md#review-20261013-o-batch); V-111 미구성·미실행).

P1/P2 사례: 5일 본인 수업 → 6일 지원 지정 → 7일 등록은 현재 유효 지원으로 허용하며 지정일은 6일 그대로다. 1일 지정 → 5일 본인 수업 → 6일 해제 → 7일 등록은 실제 허용 기간의 본인 수업에 한해 허용하되 Member 일반 목록/상세·전화번호를 다시 공개하지 않는다. 해제 후 새 수업은 이 과거 예외에 포함하지 않는다. 현재 유효 계정/Trainer·실제 수행/필요한 허용 이력과 기존 Pass/현재 잔여/정산·금액 비공개를 유지한다(BR-OPS-027; [P 승인](product-decisions.md#review-20261013-p-batch); V-112/113 미구성·미실행).
