# 사용자 및 역할

2026-09-17 Multi-Branch 변경 승인 반영. 아래는 Product 개념이며 RBAC/ABAC 기술 모델이나 Permission 목록이 아니다. AS-IS 계정·특수 메뉴 및 실제 권한 운영 미검증 사실은 [AS-IS 인증](../analysis/08-auth-and-permissions.md), [VAL-001](validation-needed.md#val-001)에 구분한다.

## Role과 Data Scope

Role은 어떤 행위를 수행할 수 있는가, Data Scope는 그 행위를 어느 데이터 범위에서 수행할 수 있는가다. Product 개념 예로 Master Admin과 Branch Admin 모두 Role ADMIN이며 Data Scope는 각각 ORGANIZATION과 BRANCH다. 실제 기술 표현은 Architecture에서 결정한다.

2026-10-10 사용자 확정 — 역할 겸임: Master Admin 또는 Branch Admin이 Trainer를 겸할 수 있으며, 한 계정으로 관리 업무와 본인의 PT 진행 기록을 모두 수행한다. 아래 Actor는 사람을 상호 배타적으로 분류한 목록이 아니다. 관리자에게 부여된 관리 Branch와 Trainer의 Home Branch는 별개 개념이다. 후속 최종 정정에 따라 관리 권한 범위 안이면 본인의 보상 설정도 조회·변경할 수 있다. 앞선 “본인은 Master만 가능” 답변은 대체한다. 보상 설정 이외 행위의 미정 권한을 자동 허용하지 않으며, 행위별 인가와 감사의 기술 표현은 ARCH-001 상세 설계에서 정한다.

Master Admin의 전체 업무 관리도 최소 개인정보·감사·이력 보존 규칙을 따른다. 관리 권한은 무제한 물리 삭제를 뜻하지 않는다. Branch Admin은 단일 Branch만 관리하며 중간 다지점 관리자 역할을 추가하지 않는다. Product는 Organization 공통이며 생성/수정은 Master Admin만 허용한다(2026-10-12 사용자 확정, MB-007 CLOSED). Master 권한 없는 Branch Admin·Operator·Trainer는 생성/수정할 수 없다. 상품 조회·Pass 발급 등 별도 업무 권한과 구별하며 자기 단일 관리 Branch의 지점명·대표 연락처 수정은 BR-OPS-030으로 확정됐고 다른 필드/계정 Scope·지점 상태/절차는 MB-004/008 후속이다.

2026-10-12 사용자 확정(관리자·Trainer 겸임 계정의 Trainer 비활성화 질문의 1번): Trainer 비활성화는 Trainer 역할에 따른 권한만 중단하며, 같은 계정에 독립적으로 부여된 관리자 역할/Scope와 그 범위의 업무는 유지한다. 계정 전체 로그인 차단은 별도 업무다(BR-OPS-014, PD-011/019, PR-005/026, NFR-001/004, ARCH-001/002, MB-001).

Trainer 역할의 중단을 계정 전체 중단으로 취급하지 않는다. 관리자 업무는 현재 독립 관리 Scope로 계속 인가하고 Trainer 역할에만 의존한 PT/회원 개인정보 접근은 실제 비활성 상태로 차단한다. 기존에 허용된 다른 역할의 독립 Scope 유지에는 사용자 일관성 지시를 적용하며 새 겸임 조합/권한을 추가하지 않는다. 비활성화 Actor는 Master Organization 전체/Branch Admin 처리 시점 Trainer 현재 Home Branch이며 재활성화·Trainer 단독 계정 로그인은 미정이다.

2026-10-12 사용자 확정(Trainer 비활성화 권한 질문의 1번): Master Admin은 자신의 Organization 전체 Trainer, Branch Admin은 비활성화 처리 시점 대상 Trainer의 현재 Home Branch가 자신의 단일 관리 Branch인 경우 Trainer를 비활성화할 수 있다. 타 지점 Branch Admin·Operator/Trainer 단독은 불가하며 겸임자는 독립된 현재 관리자 역할/Scope로 판단한다(BR-OPS-014, PD-011/019, PR-005/029/030, NFR-001/004, ARCH-001/002, MB-001).

현재 Trainer Home Branch를 Backend에서 검증하며 타 지점 지원/과거 소속·발급 사실로 권한을 대신하지 않는다. 겸임 대상의 독립 관리자 역할/Scope는 유지하고 전체 계정 차단/재활성화 권한을 추가하지 않는다.

2026-10-12 사용자 확정(잔여가 남은 담당 이용권이 있는 Trainer의 비활성화 질문의 1번): 잔여가 남은 담당 PT Pass가 있어도 Trainer 비활성화를 허용하며 기존 Assigned Trainer 정보는 유지한다. 비활성화 전에 모든 Pass를 다른 Trainer에게 교체하도록 요구하지 않고 자동 담당 해제/재배정도 하지 않는다. 이후 필요할 때 권한 있는 관리자가 BR-OPS-008의 기존 조건/Scope로 담당을 교체한다(BR-OPS-014, PD-007/011, PR-003/005, NFR-001/004, ARCH-001/002, MB-001/003/005, BR-001).

담당 Pass/Member 관계가 남아 있어도 비활성 Trainer 역할의 접근은 차단한다. 비활성화는 Trainer 현재 Home Branch 기반 관리자 인가, 나중 담당 교체는 Member 현재 Home Branch 기반 인가로 분리하며 관리자 겸임자의 독립 Scope는 유지한다. 개별 지원 관계 처리/재활성화는 후속이다.

2026-10-12 사용자 확정(담당 Trainer를 새로 지정할 때의 조건 질문의 1번): PT Pass의 담당 Trainer를 새로 지정할 때는 실제 활성 Trainer만 허용한다. 기존 Pass의 담당 교체 및 허용된 새 Pass 발급 흐름에서 담당을 최초 지정하는 경우 모두 적용하며 비활성 Trainer를 미리 배정하지 않는다(BR-OPS-008/014, PD-007, PR-003/005/029/030, NFR-001, ARCH-001, MB-001/003/005, BR-001).

담당 교체 Actor는 Member 현재 Home Branch 기준이고 새 지정 대상은 같은 Organization의 실제 활성 Trainer여야 한다. 다른 Home Branch라는 이유로 배제하지 않으며 Operator에게 기존 Pass 교체 권한을 추가하지 않는다. 기존 비활성 담당 정보 유지와 그 Trainer 역할의 접근 차단은 계속 적용한다. 최초 담당 필수는 해결됐고 계정/Branch 상태 조합 및 구체 선택 정보는 후속이다.

2026-10-12 사용자 확정(비활성화 전 진행했지만 누락된 PT 수업 등록 질문의 1번): Trainer 비활성화 전에 실제로 수행한 미등록 PT 수업은 관리자가 대행 등록하는 경로를 허용한다. 대상 Trainer의 비활성 상태를 유지하며 잠시 재활성화/본인 로그인·담당 재배정을 선행 요구하지 않는다. 실제 수행 Trainer·실제 수업일과 기존 Pass 잔여/정산 조건을 그대로 적용한다(BR-OPS-015, PD-008/011, PR-008/029/030, BR-OPS-003/008/014, BR-PAY-006/011/012).

대행 입력 관리자와 실제 수행 Trainer는 별도다. 현재 Master Organization/Branch Admin 실제 Performed Branch Scope와 실제 대상 사실을 Backend에서 확인해야 한다. Trainer 비활성화/담당 교체 Scope를 대행에 자동 재사용하지 않는다. Operator/Trainer 단독의 권한을 추가하지 않고 비활성 Trainer 접근·계정 상태/독립 역할은 유지한다. 과거 실제 수행자 참조는 새 Assigned Trainer 지정과 구분한다.

2026-10-12 사용자 확정(비활성화 전 누락 수업 대행 등록의 Branch Admin 기준 질문 1번): Master Admin은 자신의 Organization 전체, Branch Admin은 처리 시점 현재 관리 Branch가 실제 수업의 Performed Branch인 경우에만 대행 등록할 수 있다. Trainer 현재 Home Branch가 다른 지점이어도 실제 수업이 자신의 관리 지점에서 진행됐다면 허용한다. Trainer Home Branch·Member Home Branch·Pass Issued Branch 또는 과거 관리자 Scope만으로 대행 권한을 얻지 않는다(BR-OPS-015).

M1/M2 후속: 미사용 Pass 발급 오류의 수동 만료는 기존 Master Organization/Branch Admin Issued Branch Scope로, 새 Pass 발급은 기존 발급 Actor/실제 Issued Branch/대상 조건으로 각각 인가한다. 별도 Pass 발급 취소 기능은 v1 제외다. 수동 만료 Pass의 현재 담당 Trainer는 유효한 현재 권한/연결을 전제로 Member/허용 전화번호 조회를 유지하며 만료 자체로 관계를 해제하지 않는다. 비활성 Trainer·계정 차단/역할 회수·담당 교체/지원 해제의 기존 제한과 실제 PT 사용 조건은 유지한다. 수동 만료 Pass 담당 교체 허용은 별도다(BR-OPS-025/004/005; [M 승인](product-decisions.md#review-20261013-m-batch)).

수업별 금액 제한(N1/N2): 비관리자 Trainer의 본인 PT 내역에는 일반 지급/지원 수업 연결 보상 금액을 공개하지 않는다. 현재 다른 Home Branch Trainer가 자신의 Branch에서 수업했어도 Performed Branch Admin에게 해당 금액을 공개하지 않는다. 허용된 기록 조회/정정은 유지하며 현재 Home 기반 기존 관리자 보상·정산 업무·Master Organization/겸임 독립 권한을 별도 검증한다. 다른 PT 기록 전체·보상 설정/월 정산/지점 비용 보고의 기존 제한은 유지한다(BR-PAY-021; [N 승인](product-decisions.md#review-20261013-n-batch)).

## Backend 보안 경계

Trainer의 “Session 등록”은 기존 회원의 실제 수업 완료를 기록하는 PT 진행 등록이다. 사전 예약은 필수 조건이 아니며 진행 내역의 정정/취소는 미래 예약 취소와 별개다. 서버가 인가된 진행 업무 안에서 지급액을 계산한다는 사실만으로 Trainer에게 Rate / Fixed Amount / Base Salary 조회 권한을 주지 않는다. 관리자 겸임자의 설정 조회는 별도의 관리 권한·대상 Scope 검증을 거친다.

2026-10-12 사용자 확정: Trainer 회원 조회는 본인 담당 Pass의 Member 또는 개별 허용된 지원 Member로 제한한다(BR-OPS-005). Backend는 목록·검색·직접 ID 상세에서 검증된 Trainer 연결/Organization Scope와 대상별 허용 사실을 확인하며 같은 지점 소속·지원/Branch 표시 등 요청값으로 권한을 부여하지 않는다. 관리자 겸임자의 별도 관리 열람은 기존 권한/Scope로 판단하고 회원 조회 허용만으로 모든 Pass/PT 정보·보상 설정/등록·정정 권한을 공개하지 않는다. 지원 지정/철회·기간/절차·담당 관계 인정·공개 필드는 후속이다.

2026-10-12 사용자 확정: Trainer에 대한 지원 대상 지정은 Master Organization 전체/Branch Admin 지정 시점 현재 관리 Branch=Member 현재 Home Branch에서만 허용한다(BR-OPS-005). 회원 정보를 관리하는 지점이 기준이며 Trainer Home/Performed/Pass Issued Branch로 대체하지 않는다. 대상 Trainer가 타 지점 소속이어도 그 Trainer의 전체 프로필/Compensation Setting·추가실적/정산 관리 권한을 부여하지 않는다. 비관리자 Operator/Trainer는 지정할 수 없고 직접 ID/위조 Context·과거 소속/지정 사실로 우회할 수 없다. NFR-004 중요 권한 변경 감사와 기존 관리 업무 Scope를 유지하며 기간/철회 주체·이동 후 기존 허용·절차는 후속이다.

2026-10-12 사용자 확정: 개별 지원 조회 허용은 관리자가 해제할 때까지 유지하며 고정 종료일/기간 경과 자동 종료·반복 연장은 두지 않는다. 해제 Actor/Scope는 기존 지정 권한과 같은 Master Organization/Branch Admin 처리 시점 Member 현재 Home Branch 기준을 적용한다(2026-10-11 사용자 일관성 지시 적용). Backend 현재 권한/대상 Organization 검증과 NFR-004 감사를 유지한다. 해제는 해당 지원 관계의 조회 근거만 종료하며 별도의 담당/관리 권한과 기존 PT·Pass·지급/정산은 그대로 판단한다. 소속 이동 후 기존 허용·대상 상태/담당 관계 인정·절차/공개 정보는 후속이다(BR-OPS-005).

2026-10-12 사용자 확정: Member Home Branch 변경만으로 기존 개별 지원 조회 허용을 해제하거나 재지정하지 않고 유지한다. 이동 후 지정/해제는 Master Organization 또는 각 처리 시점 Member 현재 Home Branch 관리 Branch Admin이 담당하며 이전 소속/과거 지정 Actor만으로 권한을 유지하지 않는다. 동일 Organization 내 Trainer Home Branch만 변경된 경우도 같은 유지 원칙을 적용한다(2026-10-11 사용자 일관성 지시). 현재 Caller/대상 관계 검증과 기존 감사 이력·별도 담당/관리 Scope를 유지한다. 과거 수업/Pass/지급/정산 변경이나 일반/지원 구분 고정은 없고 수업 당시 Trainer 소속 기준을 따른다. 이동 자체의 권한/시점/이력·다른 대상 상태·담당 관계/공개 필드/절차·계약/저장은 후속이다(BR-OPS-005, MB-001/002/003/005).

2026-10-12 사용자 수정 확정(잔여 0 회원 조회와 제외 필터): 본인이 담당한 이용권의 잔여가 모두 0이어도 그 사실만으로 담당 회원의 목록·검색·상세 조회를 차단하지 않는다. 기본 조회에는 잔여 0 회원도 포함하고 선택 기능인 “잔여 0인 회원 제외” 필터를 제공한다. 필터 미사용 시 포함/사용 시 해당 조건의 회원을 결과에서 제외하며 조회 권한이나 담당/지원 관계·회원 상태를 변경하지 않는다. Backend의 현재 Caller/Organization·담당 또는 개별 지원 관계 인가는 필터와 독립적으로 유지한다. 조회 허용이 Remaining > 0 등 기존 PT 등록/차감 조건을 면제하지 않는다. 여러 이용권의 잔여 집계 범위·개별 지원 회원 등 담당 이용권 없는 대상의 판정과 수동 만료/취소·담당 변경 등 다른 상태의 조회 영향/공개 필드는 후속이다(BR-OPS-005, PR-002/029/030, MB-001/003/005).

2026-10-12 사용자 확정(잔여 제외 필터의 집계 기준 질문의 1번): “잔여 0인 회원 제외”는 조회 권한이 확인된 Member의 전체 이용권 잔여를 기준으로 판단한다. 조회 Trainer가 담당한 Pass만으로 제한하지 않으며 동일 Organization 내 다른 Trainer 담당/다른 Issued Branch의 Pass도 해당 Member의 집계 범위에 포함한다. 내 담당 Pass 0회+다른 Trainer 담당 Pass 10회인 Member는 필터를 켜도 표시하고 전체 집계 잔여가 0이면 제외한다. 개별 지원 회원도 자기 담당 Pass 존재 여부와 관계없이 같은 Member 전체 기준을 적용한다. 필터 미사용의 기본 조회/개별 상세 권한은 그대로이며 다른 회원/개별 Pass·다른 Trainer PT/보상 정보를 자동 공개하지 않는다. 집계 범위는 확정됐고 나머지 종료 상태의 잔여 취급·담당 변경/비활성·공개 필드 및 계약/저장/조회 일관성은 후속이다(BR-OPS-005, PR-002/029/030, MB-001/003/005).

2026-10-12 사용자 확정(Trainer의 회원 전화번호 조회 질문의 1번): Trainer는 기존 조회 권한이 확인된 담당 회원과 개별 허용 지원 회원의 등록된 전체 전화번호를 조회할 수 있다. 부분 마스킹된 번호만 허용하는 정책으로 제한하지 않는다. 담당 Pass 잔여가 모두 0이어도 기존 회원 조회 권한이 유지되면 전화번호도 같은 범위에서 조회한다. Backend는 전화번호를 반환하는 조회마다 현재 Caller/Organization·담당 또는 지원 관계를 검증하고 미담당/미허용 회원·타 Organization 번호를 공개하지 않는다. 지원 해제 후 별도의 유효한 담당/관리 권한이 없으면 해당 번호도 공개하지 않는다. 관리자 겸임자의 별도 관리 Scope는 유지한다. 이번 승인은 전화번호 읽기이며 수정/일괄 내보내기·다른 개인정보/개별 Pass·다른 Trainer PT/보상 공개 권한을 추가하지 않는다. 전화번호 필수 수집/형식·중복/검증과 나머지 필드/보존·조회 계약은 후속이다(BR-OPS-005, PR-002/029/030, NFR-001/005, LEGAL-001).

**Branch-scoped authorization MUST be enforced server-side.** Branch A Admin이 허용되지 않은 Branch B 업무 데이터의 ID를 알아도 조회·변경할 수 없어야 한다. 허용된 특정 Member/Pass/Session 교차 업무와 타 지점 전체 목록 접근은 별개이며 구체 조건은 MB-001/002/003/005다. 메뉴 숨김이나 Frontend 필터만으로 충족하지 않는다. Member·Trainer·Pass·Session·운영 데이터·Settlement·통계/집계에 허용 Data Scope를 적용하며 남은 귀속/교차 이용 조건은 MB-001–010에 남긴다. Cross-Branch unauthorized access는 금지한다.

2026-10-12 사용자 확정(회원 소속 지점 변경 권한 질문의 1번): 동일 Organization 안에서 Member의 Home Branch는 Master Admin 또는 변경 요청 처리 시점 Member의 현재 Home Branch를 관리하는 Branch Admin이 변경할 수 있다. 받는 지점의 별도 승인 없이 처리한다. Master는 Organization 전체 범위이며 Branch Admin은 변경 전 현재 관리 Member만 대상으로 한다. 받는 지점 관리자라는 이유나 과거 소속·이전 변경자/지원 지정자·Pass Issued Branch·수업 Performed Branch 사실만으로 다른 현재 소속 Member를 이동시킬 수 없다. 관리자 권한 없는 Operator·Trainer는 수행할 수 없고 관리자 겸임자는 해당 관리 권한으로 판단한다(BR-OPS-007, PD-004, PR-002/030, MB-002, NFR-001).

기존 결정 적용: 변경된 Home Branch가 반영된 이후의 Member 관리 및 개별 지원 지정/해제는 각 요청의 현재 Home Branch와 관리 Scope를 따른다. 이전 지점 관리자는 이전 소속/처리자라는 사실만으로 Home Branch 기반 관리 권한을 유지하지 않는다. 기존 담당·개별 지원 조회 허용과 별도의 Pass 발급 지점/수업 수행 지점 기준 업무 등 독립적으로 인가되는 권한은 각각 기존 규칙을 적용한다. 이동 자체로 개별 지원 허용을 해제/재지정하지 않고, Pass의 Issued Branch·발급 조건·잔여/담당 정보, Trainer Home Branch와 과거 PT 기록/Performed Branch·확정 지급/정산을 자동 변경하지 않는다(BR-OPS-001/004/005).

2026-10-12 사용자 확정(회원 소속 변경의 적용 시점 질문의 1번): v1의 Member Home Branch 변경은 저장 완료 즉시 적용만 지원한다. 변경이 성공한 시점부터 새 Home Branch가 현재 소속이 되며, 미래 적용일을 지정해 소속 변경을 예약하는 기능은 제공하지 않는다. 성공한 저장 이후 시작하는 후속 요청의 Home Branch 기반 관리 및 지원 지정/해제는 새 소속 기준으로 인가한다. 저장에 실패하면 변경 전 Home Branch를 유지한다. 기존 Master Organization 전체/변경 전 Member 현재 Home Branch 관리 Branch Admin 권한과 받는 지점 별도 승인 없음은 유지한다(BR-OPS-007, PD-004, PR-002/030, MB-002, NFR-001/004).

2026-10-12 사용자 확정(회원 이동 대상에 비활성 지점을 허용할지 질문의 1번): Member Home Branch의 이동 대상은 동일 Organization 안에서 운영 중인 활성 Branch만 허용한다. 비활성 Branch로의 이동은 허용하지 않으며 Master Admin과 Branch Admin에 동일하게 적용한다. Backend에서도 대상 Branch의 활성 여부를 검증하고 비활성 대상 요청은 거부한다. 거부 시 기존 Member Home Branch·지원 허용·Pass·과거 업무 이력은 유지한다(BR-OPS-007, PD-004, PR-002/030, MB-002/008, NFR-001).

기존 회원 조회 원칙 적용(BR-OPS-005): 담당 관계를 인정하는 Pass의 현재 담당이 바뀌면 후속 회원 목록/검색/직접 ID·전화번호 공개도 Backend에서 변경된 현재 담당 관계와 별도의 개별 지원/관리 권한으로 판단한다. 이전 담당이라는 사실만으로 영구적인 Member 조회 권한을 부여하지 않는다. 새 담당은 기존 담당 회원 범위에서 인가하며 이전 담당도 다른 담당 Pass나 개별 지원/관리 권한이 있으면 그 독립 근거로 판단한다. 본인이 실제 수행한 과거 PT 기록 조회는 기존 별도 업무 Scope를 따르고, 이를 다른 Member/Pass/PT·보상 설정의 무제한 공개로 확대하지 않는다. 잔여 0만으로 담당 회원 조회를 막지 않는 규칙도 유지한다.

2026-10-12 사용자 확정(담당 교체 권한의 기준 지점 질문의 1번): 기존 Pass의 Assigned Trainer 교체는 Master Admin의 Organization 전체 범위 또는 처리 시점 Member의 현재 Home Branch를 관리하는 Branch Admin에게 허용한다. 수원 발급 Pass의 회원이 현재 강남 소속이면 강남 Branch Admin 또는 Master가 교체할 수 있으며, 수원 Branch Admin은 Issued Branch만을 근거로 교체할 수 없다. 회원 소속이 다시 변경되면 각 교체 요청은 변경된 현재 Home Branch 기준으로 인가한다. 이용권 수동 만료/해제의 Issued Branch 기준은 그대로 유지한다(BR-OPS-004/008, PD-007, PR-003/030).

Backend는 검증된 현재 Caller의 관리자 권한/Organization·관리 Branch Scope, 실제 Pass→Member 관계와 Member 현재 Home Branch를 확인한다. 직접 Pass/Member ID·클라이언트 role/Branch/Member 소속 값·과거 소속/담당 또는 이전 처리 Actor·Trainer Home Branch·수업 Performed Branch만으로 교체 권한을 인정하지 않는다. 관리자 권한 없는 Operator/Trainer는 수행할 수 없으며 관리자·Trainer 겸임자는 해당 관리자 Scope로 판단한다. 권한 거부/실패 시 기존 담당·잔여/발급 조건·업무 이력을 유지한다. 기존 범위 내 관리자 직접 처리 원칙을 동일 적용하여 별도 Master 승인 대기를 추가하지 않는다(2026-10-11 사용자 일관성 지시 적용). 교체 권한은 대상 Trainer의 Compensation Setting 조회/변경 권한이나 다른 지점 전체 Trainer/Member 정보 열람 권한을 부여하지 않는다. 기존 즉시 적용·전후 담당/Actor/Branch Context·시점 이력/감사·현재 관계 기반 조회와 과거 수업/보상 보존 원칙은 유지한다.

2026-10-12 사용자 확정(교체할 Trainer의 소속 지점 질문의 1번): 기존 Pass의 담당 교체 대상은 같은 Organization의 Trainer이며 Member 현재 Home Branch와 다른 지점 소속 Trainer도 허용한다. 강남 회원의 담당을 수원 소속 Trainer로 바꿀 수 있다. Member와 같은 지점 소속이어야 한다는 제한을 두지 않으며 다른 Organization Trainer는 지정할 수 없다. 교체 요청의 Actor 권한은 기존대로 Master Organization 전체 또는 Branch Admin 처리 시점 Member 현재 Home Branch 기준이다(BR-OPS-008, PD-007, PR-003/029/030).

교체 전 실제 본인 수업의 이전 담당 직접 누락 등록은 허용(2026-10-12, BR-OPS-003/008)됐으며 현재 Caller/본인 Trainer 연결·Organization와 당시 담당/수행 사실·기존 Pass/정산 조건을 검증한다. 현재 회원 조회는 별도의 현재 담당/지원/관리 관계로 판단하고 과거 담당이라는 이유만으로 복원하지 않는다. 잔여 소진 외 수동 만료/취소 등 나머지 Pass 상태·과거 담당/수행 사실 확인 불가/정정과 최소 식별/응답/Trainer 선택 정보·구체 계약/경합은 ARCH-001·MB-001/003/005·BR-008 등의 후속이다. 담당 지정과 실제 수업의 일반/지원 보상 구분은 별개이며 Home Branch와 보상 설정/정산 접근 권한은 바꾸지 않는다.

2026-10-12 사용자 확정(잔여 0회인 이용권의 담당 교체 질문의 1번): Remaining이 0인 기존 Pass도 Assigned Trainer를 교체할 수 있다. 잔여를 모두 사용해 이용이 끝난 Pass도 포함한다. 같은 Pass에서 담당 A를 B로 바꾸며 Remaining 0·발급 조건/Issued Branch·과거 실제 수행 Trainer/PT 기록·확정 지급/정산 이력은 유지한다. 새 담당 B는 기존 현재 담당 관계에 따른 Member 조회·응대를 이어갈 수 있다. 기존 Master Organization 전체/Branch Admin 처리 시점 Member 현재 Home Branch 권한과 같은 Organization의 다른 지점 Trainer도 대상 허용 원칙은 유지한다(BR-OPS-005/008, PD-007, PR-003/029/030).

이 승인으로 Trainer 역할에 교체 명령 권한이 생기는 것은 아니다. 새 현재 담당의 회원 조회와 이전 담당의 다른 현재 관계/자기 과거 PT·한정 누락 등록은 각각 기존 Scope로 판단한다. 잔여 0·과거 기록/보상과 선택 제외 필터/민감 설정 제한은 유지한다.

2026-10-12 사용자 확정(이용권 횟수의 수동 조정 권한 질문의 1번): Pass 횟수의 수동 조정은 Master Admin의 Organization 전체 범위 또는 처리 시점 현재 관리 Branch가 해당 Pass의 Issued Branch인 Branch Admin에게 허용한다. 수원 발급/현재 강남 소속 Member의 이용권은 수원 Branch Admin 또는 Master가 조정하며, 강남 Branch Admin은 Member의 현재 소속만을 근거로 조정할 수 없다. 회원 소속이나 담당 Trainer가 바뀌어도 Issued Branch 기준은 유지한다. 이용권 수동 만료/해제와 같은 발급 지점 기준이며 담당 교체의 Member 현재 Home Branch 기준과 구별한다(BR-OPS-004/008/009, PD-007/010, PR-003/030).

수동 조정의 현재 관리자/실제 Issued Branch 검증·사유/이력·감사와 범위 밖 거부는 BR-OPS-009를 따른다. PT 취소 복원은 기존 Performed Branch 기준 취소 업무의 별도 처리이고 담당 교체는 Member 현재 Home Branch를 기준으로 한다. 수량/상태·조정/감사 저장 계약과 동시성은 후속이다.

2026-10-12 사용자 확정(다른 지점에서 새 이용권 구매·발급 질문의 1번): Member는 같은 Organization의 Home Branch 밖 지점에서도 새 PT Pass를 구매·발급받을 수 있다. 수원 소속 회원이 강남에서 발급받으면 Member Home Branch는 수원으로 유지하고 새 Pass의 Issued Branch는 강남으로 기록한다. Member Home Branch와 Issued Branch가 같아야 한다는 제한을 두지 않는다. 기존 Member 식별자/소속·보유 Pass와 과거 PT/지급·정산 이력은 유지하며 타 지점 발급을 위해 Member를 지점별로 복제하거나 소속을 자동 이동하지 않는다(BR-OPS-001/010, PD-004/007, PR-002/003/030).

발급 Actor는 Master·Branch Admin·Operator로 확정됐으며 각각 Organization 전체/자신의 단일 관리 Branch/부여된 허용 발급 Branch Scope를 검증한다. Trainer 단독은 불가하고 겸임은 독립적인 발급 역할/Scope로 판단한다. 새 Operator 발급 절차·기존 계정 역할 부여·Master 전용 Operator 지점 변경의 대상/절차은 후속이며 이 결정으로 Member 소속 지점을 벗어난 전체 일반 조회 권한을 부여하지 않는다. 발급용 같은 Organization 전체 지점 Member의 이름·전화번호 일부 검색은 후속 2번 사용자 승인으로 해결됐다. 추가 공개 정보·Member 선택용 최소 식별 응답/계약은 별도 게이트로 유지한다. 수원 소속/강남 Issued Pass의 만료/해제·수동 횟수 조정은 강남 Issued Branch 기준, 담당 교체는 수원 Member 현재 Home Branch 기준이다. 소속/과거 이력·민감 설정 제한은 유지한다(BR-OPS-010).

2026-10-12 사용자 확정(새 이용권 발급 Actor 질문의 1번): 새 PT Pass 발급은 Master Admin·Branch Admin·Operator에게 각자의 허용된 실제 Issued Branch 범위에서 허용한다. Master는 Organization 전체, Branch Admin은 자신의 단일 관리 Branch, Operator는 부여된 허용 발급 Branch Scope에서 처리한다. 같은 Organization의 Member는 Home Branch가 발급 지점과 달라도 대상이 될 수 있으며 기존 Member/Home Branch를 유지하고 새 Pass에 실제 Issued Branch를 기록한다(BR-OPS-010, PD-004/007, PR-003/030).

권한 경계: Trainer 역할만으로는 새 Pass를 발급할 수 없다. Trainer를 겸하는 계정에 Master·Branch Admin·Operator의 발급 권한이 있으면 해당 역할의 독립적인 발급 Scope로 판단하며 별도 계정을 요구하지 않는다. Operator의 새 발급 권한은 공통 상품 생성/수정, 기존 Pass 수동 횟수 조정·만료/해제·담당 교체, Member 소속 이동, PT 정정/취소·Compensation Setting·Additional Performance·월 정산의 별도 권한을 추가하지 않는다. 발급 대상 식별을 타 지점 전체 Member 목록/전화번호·다른 Pass/PT/민감 보상 정보의 일반 조회 허용으로 확대하지 않는다. 기존 보상 설정 접근 제한과 Trainer의 담당/개별 지원 회원 조회는 그대로다.

Backend는 각 발급 요청에서 검증된 현재 Caller의 발급 역할/Organization·허용 실제 Issued Branch와 Member/Product/Branch의 실제 Organization 관계를 확인한다. 범위 밖 발급 지점·다른 Organization·Trainer 단독 권한·직접 ID/위조 role/Branch 값으로는 발급할 수 없으며 역할/Scope가 철회·축소되면 후속 발급 요청에도 현재 권한을 적용한다. 거부/실패 시 기존 Member/Home Branch·Pass·업무 이력을 유지한다. 발급 권한과 발급 이후의 관리 권한은 별도이므로 과거 발급 Actor였다는 사실만으로 후속 관리자 권한을 얻지 않는다.

2026-10-12 사용자 확정(발급용 타 지점 회원 검색 질문의 2번): Branch Admin·Operator는 자신의 허용된 실제 Issued Branch에서 새 PT Pass를 발급하기 위해 같은 Organization 전체 지점의 Member를 이름·전화번호 일부로 검색할 수 있다. 전화번호 전체 일치만을 요구하지 않으며 Member Home Branch가 Caller의 관리/발급 Branch와 다르다는 이유만으로 검색 후보에서 제외하지 않는다. Master의 기존 Organization 전체 범위는 유지한다. 검색은 기존 Member를 선택하여 실제 발급 지점의 새 Pass를 만드는 흐름이며 Member 소속 이동/복제나 기존 Pass·PT·지급·정산 변경을 수행하지 않는다(BR-OPS-010, PD-004/007/022, PR-002/003/030).

검색 인가/정보 공개 경계: 이 허용은 이용권 발급용 Member 검색의 후보 범위·검색 방식과 이름/전체 전화번호/현재 Member Home Branch 공개다. Backend는 매 검색/선택/발급 요청에서 현재 Caller의 발급 역할/Organization·허용 실제 Issued Branch와 대상 Member의 실제 Organization을 검증한다. 검색 Branch Context를 위조하거나 과거 검색 결과/선택 Member ID로 철회된 역할·Scope 또는 다른 Organization을 우회할 수 없다. 같은 전화번호/이름의 여러 Member는 별도 식별자로 구분하여 선택하며 번호만으로 병합하거나 첫 결과를 자동 선택하지 않는다. 이 세 항목의 읽기 허용이 회원 정보/전화번호 수정·일반 Member 상세·전체 무조건 목록/일괄 내보내기, 다른 개인정보/Pass/PT/보상 정보 열람 권한을 추가하지 않는다. Trainer 단독의 담당/개별 지원 Member 검색 및 기존 전체 전화번호 공개는 유지하고 발급 역할 겸임은 그 독립 발급 업무 Scope로 판단한다. 응답은 승인된 공개 범위 안에서 구성하며 Member 선택용 최소 식별 응답/계약과 추가 공개 정보는 후속이다. 실제 운영 연락처/검색어를 문서·일반 로그에 복사하지 않는다.

회원 식별의 기존 원칙 적용: 같은 전화번호/이름으로 여러 Member가 일치하면 별도 Member 식별자로 구분하여 발급할 대상을 선택한다. 번호 일치/첫 결과만으로 자동 병합·동일 회원 취급·소속 이동 또는 다른 Member 이력/권한 공유를 하지 않는다(BR-OPS-006). 잔여 0만으로 회원을 제외하지 않는 기존 조회 원칙은 유지하며 발급용 검색을 Trainer 전용 선택 제외 필터/담당 회원 집합으로 제한하지 않는다. 비활성 Member/Branch 등 나머지 대상 조건·검색어/빈 검색 처리·추가 공개 정보·최소 선택 응답/계약·선택/발급 일관성은 후속이다. 검색 자체는 업무 데이터를 변경하지 않으며 검색 성공만으로 발급 완료나 발급 이후 관리자 권한을 얻지 않는다.

2026-10-12 사용자 확정(발급용 검색 결과 표시 정보 질문의 1번): 새 PT Pass 발급용 Member 검색 결과에는 이름·전체 전화번호·소속 지점을 표시한다. 소속 지점은 해당 Member의 현재 Home Branch이며 Caller 관리 지점/Pass Issued Branch/수업 Performed Branch와 구별한다. 같은 Organization의 타 지점 회원 검색 결과에도 동일하게 적용하고 부분 마스킹된 번호만 표시하도록 제한하지 않는다. 기존 이름·전화번호 일부의 Organization 전체 지점 검색과 현재 발급 역할/실제 Issued Branch Scope 인가는 유지한다(BR-OPS-010, PD-004/007/022, PR-002/003/030, NFR-001/005).

검색 인가/정보 공개 경계: 이 허용은 이용권 발급용 Member 검색의 후보 범위·검색 방식과 이름/전체 전화번호/현재 Member Home Branch 공개다. Backend는 매 검색/선택/발급 요청에서 현재 Caller의 발급 역할/Organization·허용 실제 Issued Branch와 대상 Member의 실제 Organization을 검증한다. 검색 Branch Context를 위조하거나 과거 검색 결과/선택 Member ID로 철회된 역할·Scope 또는 다른 Organization을 우회할 수 없다. 같은 전화번호/이름의 여러 Member는 별도 식별자로 구분하여 선택하며 번호만으로 병합하거나 첫 결과를 자동 선택하지 않는다. 이 세 항목의 읽기 허용이 회원 정보/전화번호 수정·일반 Member 상세·전체 무조건 목록/일괄 내보내기, 다른 개인정보/Pass/PT/보상 정보 열람 권한을 추가하지 않는다. Trainer 단독의 담당/개별 지원 Member 검색 및 기존 전체 전화번호 공개는 유지하고 발급 역할 겸임은 그 독립 발급 업무 Scope로 판단한다. 응답은 승인된 공개 범위 안에서 구성하며 Member 선택용 최소 식별 응답/계약과 추가 공개 정보는 후속이다. 실제 운영 연락처/검색어를 문서·일반 로그에 복사하지 않는다.

2026-10-12 사용자 확정(Operator 업무 허용 지점 수 질문의 1번): v1 Operator 역할의 업무 허용 Branch는 한 시점에 하나만 지정한다. Operator는 그 지정된 단일 Branch에서 명시적으로 허용된 업무를 수행하며 같은 계정의 Operator 권한을 여러 Branch에 동시 부여하지 않는다. Branch당 Operator 한 명이라는 1:1 인원 제한을 추가하지 않으며 하나의 Branch에 여러 Operator가 있을 수 있다. 이 결정은 Operator 역할의 업무 Scope이며 기존에 허용된 겸임 역할의 독립적인 관리/PT 권한이나 Trainer Home Branch를 바꾸지 않는다(BR-OPS-011, PD-001/007, PR-001/003/030, ARCH-001, MB-004).

인가 경계: Backend는 검증된 현재 Caller의 Operator 역할/Organization·지정된 단일 업무 Branch와 해당 요청의 실제 업무 Branch를 확인한다. 직접 Branch ID·클라이언트 branch_id/role/선택 지점·과거 업무/발급 지점만으로 다른 Branch의 업무를 수행할 수 없다. 동일 계정에 Operator 권한을 중복 부여하거나 여러 Branch 중 하나를 임의 선택하는 방식으로 단일 지점 제한을 우회하지 않는다. 현재 역할/Scope 철회·축소 이후 후속 요청은 현재 권한을 적용한다. 지정이 없거나 복수 지정된 상태를 유효한 Operator 업무 권한으로 간주하지 않되 구체 계정/역할 저장·활성화 제약과 오류 계약은 후속 Architecture다.

기존 발급/검색 규칙 유지: Operator의 새 Pass 발급은 자신의 지정된 단일 Branch를 실제 Issued Branch로 사용한다. 그 발급 업무에서는 같은 Organization 전체 지점 Member를 이름·전화번호 일부로 검색하고 결과의 이름·전체 전화번호·현재 Member Home Branch를 조회/선택할 수 있다(BR-OPS-010). Member Home Branch가 Operator 업무 Branch와 다르다고 검색/발급을 거부하거나 회원 소속을 자동 이동하지 않는다. 전체 지점 Member 검색이 다른 Branch의 Pass 발급이나 일반 회원 상세/다른 Pass/PT·보상/수정·일괄 내보내기 권한을 부여하지 않는다. 기존 Master 전용 공통 상품 변경 및 관리자 전용 Pass 수동 조정·만료/해제·담당 교체/보상 업무 제한은 유지한다.

남은 결정: 새 Operator 발급/최초 Branch 지정 Actor는 Master Organization 전체/Branch Admin 자기 단일 Branch, 기존 Operator 업무 Branch 변경 Actor는 Master Organization 범위 전용으로 해결됐다. 변경은 기존 저장 후 현재 Scope 반영/실패 보존·감사 원칙을 적용한다. 발급 절차·기존 계정 역할 추가/변경·Operator 지점 변경의 대상 Branch/계정 상태·세부 절차/감사 계약 및 나머지 운영 행위 권한은 MB-004·ARCH-001/002 후속이다. 한 계정의 Operator 동시 허용 지점 수나 신규 발급/지점 변경 Actor를 다시 OPEN으로 두지 않는다. 실제 발급 대상·초기 조건/선택 응답·역할/Scope 저장·Caller/인가 계약·실패/재시도/경합은 관련 Product/Architecture 후속이다. IAM-001 S1에 Operator 구현을 추가하거나 기존 PROPOSED 인증/모듈/저장 설계를 승인한 것은 아니다.

2026-10-12 사용자 확정(Trainer 소속 지점(Home Branch) 변경 권한 질문의 1번): Trainer의 Home Branch 변경은 Master Admin만 자신의 Organization 범위에서 수행한다. Branch Admin은 변경 전/후 지점 관리자 또는 해당 Trainer 계정 발급자여도 변경할 수 없다. Operator·Trainer 단독은 본인 포함 불가하며 관리자/Trainer 겸임도 현재 Master 권한이 있을 때만 해당 Organization Scope로 처리한다. Branch Admin의 자기 지점 Trainer 신규 로그인 계정 발급 권한(BR-OPS-012)은 유지하며 이를 소속 변경 권한으로 확대하지 않는다(BR-OPS-013, PD-004, PR-005/029/030, NFR-001/004, MB-001/004/005, ARCH-001).

일반 소속 이동은 기존 저장 후 새 현재 소속 반영·실패 보존/감사 원칙을 적용한다. 보상 설정·월 정산/Trainer 발급의 현재 Home Branch 기준 인가는 새 소속을 사용하고 과거 소속/처리 사실만으로 이전 관리자에게 권한을 유지하지 않는다. 같은 계정의 관리 Branch/Operator 업무 Branch·Trainer 연결은 별개이며 기존 담당/지원 관계·과거 수업 당시 소속/확정 보상은 보존한다. Trainer 비활성화·과거 소속 이력 정정/소급/확인 불가와 구체 계약은 후속이다(BR-OPS-013).

2026-10-12 G1–G5 모두 1번 승인: Branch 비활성만으로 유효한 계정/역할의 로그인과 기존 권한 내 조회를 중단하지 않는다. 계정 전체 차단·비활성 Trainer/철회 역할·만료/폐기 인증 제한은 유지한다. 비활성화 전 실제 수업의 소급 등록·정정·취소는 기존 업무별 권한과 실제 시점/Pass/정산 조건으로 허용한다. Branch Admin의 PT 정정/취소·대행은 실제 Performed Branch, 정산 해제/재확정은 현재 Trainer Home Branch이며 한쪽 권한이 다른 업무 권한을 주지 않는다. Trainer 직접 등록/정정 금지·비활성 Trainer 관리자 대행 등의 기존 구분도 유지한다.

G3/G4는 다른 활성 지점에서 기존 Pass/인가·담당/개별 지원 조건을 충족하는 Member·활성 Trainer 수업을 허용한다. Issued/Home Branch 변경을 선행 요구하지 않고 지원 보상/민감 설정 제한을 유지한다. G5는 같은 Organization 활성 지점으로 Member를 Master 또는 변경 전 현재 Home Branch 관리자, Trainer·Operator는 Master가 명시적으로 이동하는 흐름이다. 신규 업무 차단·독립 겸임/담당/지원/과거 이력·현재 Scope 검증은 유지하며 지점 재활성화/미결정 신규 배정·다른 상태 상세는 후속이다. [2026-10-12 G 일괄 승인](product-decisions.md#review-20261012-g-batch).

2026-10-12 J1–J3 승인: Member 등록/이름·전화번호 수정과 관리자 비활성화/재활성화는 실제 대상/현재 역할·Home Branch 기준으로 각각 인가한다(BR-OPS-021/022). 타 지점 Pass 발급/최소 검색이나 Trainer 담당/지원 조회로 회원 수정·상태 변경 권한을 얻지 않는다. Member 자체 비활성은 새 Pass/비활성 기간 실제 수업을 차단하고 잔여/기존 관계·과거 결과를 보존한다. 같은 Member 재활성화 후에도 독립 Pass·Trainer/Branch·현재 권한 조건을 검증한다. Member는 v1 로그인 Actor가 아니며 계정 전체 차단/Trainer 업무 중단과 구별한다. [2026-10-12 J 일괄 승인](product-decisions.md#review-20261012-j-batch).

2026-10-12 K1/K2: 날짜/시각 오류의 취소/재등록 인가와 각 영향받는 정산 월의 해제/재확정 인가를 구분한다(BR-OPS-023). Trainer 기본정보 관리는 BR-OPS-024의 Master Organization/Branch Admin 지정·현재 Trainer Home 기준이며 계정/보상·Home 이동 권한으로 자동 확장하지 않는다. K3로 첫 개발은 관리자 인증/지점 접근 제어의 개발 검증부터 진행하며 Trainer 직접 로그인/실제 연결의 후속 v1 의무는 유지한다. [2026-10-12 K 일괄 승인](product-decisions.md#review-20261012-k-batch).

PT 등록 성공/목록/검색/상세/직접 ID·중첩 결과 등 제공되는 경로에도 BR-PAY-021의 수업별 금액 제한을 적용한다. UI 숨김만으로 끝내거나 비공개 금액 대신 가짜 0원을 반환하지 않는다. 내부 계산/보존·정산용 소비는 외부 열람 권한과 구별하며 현재 Caller·실제 Trainer 현재 Home/기존 행위별 Scope를 확인한다. 응답 생략/분리·상태/계산 근거·오류 계약은 후속이다. [N 승인](product-decisions.md#review-20261013-n-batch).

O1/O2 확정: Trainer는 기존 담당/개별 허용 지원 회원의 본인 실제 수업을 등록할 수 있고, 서버는 본인 담당 여부와 관계없이 해당 Member 전체 적격 Pass에서 FIXED_AMOUNT 우선/FIFO로 차감한다. 자기 담당 Pass 없는 개별 지원 회원도 포함한다. 지원 지정/해제는 각 처리 시점 Member 현재 Home의 Branch Admin/Master Organization 범위이며 Trainer Home/Performed/Issued가 대체하지 않는다. 현재 Caller/관계·기존 실제 시점/현재 잔여·상태/정산 조건과 N 금액 비공개를 유지한다. 이 결정은 다른 Trainer 대행·다른 Member/Pass/PT/보상 무제한 공개나 정정/취소/발급 권한 추가가 아니다. 지원 관계의 시간 정책은 BR-OPS-027(P1/P2)을 따르며 관리자 겸임의 독립 관리 Scope는 유지한다(BR-OPS-026; [O 승인](product-decisions.md#review-20261013-o-batch)).

P1/P2 과거 수업 명령: 현재 유효한 지원 허용으로 지정 전 실제 본인 수업도 등록할 수 있으며, 해제 후에는 실제 허용 기간의 본인 수업만 늦게 등록할 수 있다. 지정 이력은 소급 변경하지 않고 해제 후 일반 Member/전화번호 조회를 복원하지 않는다. 현재 계정/Trainer·실제 수행/필요한 과거 허용 사실과 기존 Pass/정산 조건을 검증하며, 회원 조회 인가와 이 제한된 등록 명령을 구별한다. 최소 과거 대상 식별/공개 계약은 후속이다(BR-OPS-027; [P 승인](product-decisions.md#review-20261013-p-batch); V-112/113 미구성·미실행).

R1/R2: Trainer 전화번호는 필수이며 기존 신규 지정/수정 현재 Home 관리자 Scope를 검증한다. 전화번호 필수 수집만으로 Trainer/Operator의 변경·다른 전화번호 조회나 IAM/보상 권한을 부여하지 않는다. Branch Admin은 현재 자기 단일 관리 Branch의 지점명/대표 연락처 두 필드만 수정할 수 있고 Master Organization 권한은 유지한다. 타 Branch/Organization·과거 Scope/요청 role로 우회할 수 없으며 지점 생성/운영 상태/관리자 배정/계정 Scope 변경은 포함하지 않는다. 기존 중요 변경 감사·겸임 독립 Scope·과거 지점 사실을 유지한다(BR-OPS-029/030; [R 승인](product-decisions.md#review-20261013-r-batch)).

T1/T2 시간 경계: 기존 발급 권한은 시스템에서 현재 신규 Pass를 발급할 권한이며 과거 발급 날짜 입력/소급 발급·기존 발급 시각 수정 권한을 포함하지 않는다. Master/Branch Admin/Operator도 현재 발급 사실/실제 수업 시각을 임의 변경해 과거 후보 조건을 우회할 수 없다. 별도 시작일 없이 발급부터 기존 사용 조건을 적용하되 발급 자체가 Member/PT 조회·차감/정정·보상/정산 권한을 부여하지 않는다(BR-OPS-031; [T 승인](product-decisions.md#review-20261013-t-batch)).

U1 만료 담당 교체: Master Organization/각 처리 시점 Member 현재 Home Branch Admin은 수동 만료 Pass의 담당도 같은 Organization 실제 활성 Trainer로 교체한다. Issued Branch·Trainer Home/Performed·과거 Scope/처리자만으로 교체하지 못하며 Operator/Trainer 단독은 불가다. 새 담당 조회/M2·이전 담당의 다른 유효 관계 없는 일반 조회 종료와 독립 관리자 Scope를 유지한다. 교체만으로 만료 해제/횟수 조정·새 수업 사용·보상/계정 관리 권한을 부여하지 않는다(BR-OPS-008/005; [U 승인](product-decisions.md#review-20261013-u-batch)).

V1 과거 소속 오류 정정: Trainer/Member의 이미 기록된 과거 Home 이력은 현재 Master가 자기 Organization 범위에서 사유/원래 이력을 보존하며 정정한다. Branch Admin은 Member 현재 Home 관리자/이동 전후 지점 관리자여도 불가하며 Operator/Trainer 단독도 불가다. 겸임은 현재 Master의 독립 Scope로 판단한다. 일반 Member 이동 권한·현재 인가/기존 업무별 정정·보상 비공개는 유지하며 과거 권한/계정 감사·담당/지원 이력을 자동 재작성/복원하지 않는다(BR-OPS-032; [V 승인](product-decisions.md#review-20261013-v-batch)).

W1/W2 경계: 과거 Trainer Home 오류에 따른 기존 수업 분류·보상 정정은 현재 Master 자기 Organization 전용이다. Branch Admin의 현재 Trainer Home/Performed 관리만으로 이를 수행하지 못한다. 전환 후 지원 금액 입력/기존 정산 해제·확정은 각 행위의 기존 Master Organization/현재 Trainer Home Branch Admin 범위를 적용하고 수업별 금액 비공개·C7 인증 감사 Master 전용을 유지한다. 영향 정정 미완료 Trainer·월은 확정/재확정 불가하며 과거 권한/직접 ID/겸임·관리자 경고 확인으로 우회하지 못한다(BR-OPS-033/PAY-024; [W 승인](product-decisions.md#review-20261013-w-batch)).

## Trainer Compensation Setting 조회·변경

Trainer 기준 Rate(RATE 지급률), Fixed Amount(FIXED_AMOUNT 회당 지급액), Base Salary(월 고정 기본급)에 동일 정책을 적용한다. Product별 Trainer 지급 값이나 같은 테이블 저장을 요구하지 않는다.

| Actor / 대상 범위 | Rate 조회·변경 | Fixed Amount 조회·변경 | Base Salary 조회·변경 |
| --- | --- | --- | --- |
| Master Admin / 본인 포함 Organization 전체 Trainer | 허용 | 허용 | 허용 |
| Branch Admin / 본인 포함 자기 Branch가 Home Branch인 Trainer | 허용 | 허용 | 허용 |
| Branch Admin / 다른 Home Branch의 Trainer | 불가 | 불가 | 불가 |
| 관리자 권한 없는 Operator / 모든 Trainer | 불가 | 불가 | 불가 |
| 관리자 권한 없는 Trainer / 본인 포함 모든 Trainer | 불가 | 불가 | 불가 |

Rate / Fixed Amount / Base Salary 세 항목의 조회·설정·변경은 Master Admin은 Organization 전체 Trainer, Branch Admin은 자신의 단일 Branch를 Home Branch로 가진 Trainer에게만 허용한다. 관리자와 Trainer를 겸하는 계정은 관리 권한 범위 안이면 본인의 세 항목도 조회·변경할 수 있다. Master Admin은 본인 포함 허용하며, Branch Admin은 본인 Trainer의 Home Branch가 관리 Branch일 때 본인도 허용한다. 관리자 권한이 없는 Operator·Trainer 계정은 본인 포함 모든 Trainer 설정 조회·변경이 불가하다. 타 지점 지원 수업은 보상 설정 접근 권한을 부여하지 않는다. Backend에서 대상 Trainer의 Home Branch를 검증하며 직접 ID 요청과 감사·정산 등 우회 경로에도 제한을 적용한다.

수원점 소속 Trainer A가 강남점에서 수업해도 수원점 Branch Admin만 A의 보상 설정에 접근 가능하다. 강남점 Branch Admin은 지원 수업 이력만으로 권한을 얻지 않는다.

모든 보상 설정 변경(최초 설정 포함)에 대상 Trainer, 변경 항목, 변경 전 값, 변경 후 값, 변경 Actor, Actor의 권한 및 Branch Context, 변경 시점을 추적한다. 별도 Master Admin 승인 없이 변경 가능하며 변경 요청→승인 대기→승인→반영 절차를 추가하지 않는다. 이 결정은 추가실적 승인이나 월 정산 마감/확정 절차를 면제하지 않는다.

Rate/Fixed Amount의 적용은 BR-PAY-011을 따른다. Base Salary 변경 시 관리자가 미확정인 과거 월을 포함해 적용 시작 월을 지정하며(BR-PAY-014), 변경이 적용되는 수동 지정 없는 기존 미확정 정산의 기본급·합계는 자동 반영한다. 미래 적용 월의 입력 범위 등 남은 상세는 BR-012 OPEN이다. 추가실적 직접 등록의 Home Branch 대상 기준·관리 범위 안 본인 등록·해당 본인 건의 별도 승인 없음은 아래와 같이 확정했으며 추가실적의 남은 처리 정책 등은 BR-013, 정산 공개는 MB-006 OPEN이다. 설정 변경 권한으로 다른 업무를 자동 허용하지 않는다. 확정된 월의 기본급 오류 정정 경로는 해제·해당 월 기본급 정정·동일 월 재확정으로 확정했으며, 기본급 오류 정정의 확정 해제·재확정은 Master Admin에게 Organization 전체, Branch Admin에게 각 처리 시점 대상 Trainer의 현재 Home Branch가 자신의 관리 Branch인 경우 허용한다. 관리 범위 안 본인 건도 포함하며 별도 Master 승인 없이 처리한다. 확정된 월의 기본급 오류 정정에서 확정 해제와 해당 월 기본급 수정 모두 사유가 필수다. Master Admin·Branch Admin 및 관리 범위 안 본인 건에 동일하게 적용한다. 해제 사유·해제자·시점과 변경 전후 기본급·수정 사유·수정자·시점을 이력으로 남긴다. 기본급 오류 정정은 대상 Trainer의 해당 월 정산에만 적용하며 현재·미래 기본급 설정과 다른 월 정산은 유지한다. 지속적인 기본급 변경은 별도로 적용 시작 월을 지정하는 기존 흐름을 따른다. 미래 적용 월의 입력 범위 등 남은 정책은 BR-012 OPEN이다. 감사 조회를 포함한 우회 노출도 금지한다. [BR-PAY-010](business-rules.md#br-pay-010).

월별 적용 기본급: 추가 사용자 확정(2026-10-11): 해당 월 기본급은 권한 있는 관리자가 사유를 남기면 0원으로 명시적으로 수동 지정할 수 있다. 수동 지정한 0원은 미입력과 구분하며, 미입력이나 누락된 일반 설정을 자동으로 0원으로 대체하지 않는다. 해당 월 기본급에만 적용하고 다른 유효 지급·추가실적은 기존 규칙대로 합산한다. 미확정 월의 기본급을 최초 수동 지정하거나 다시 수정할 때 모두 사유가 필수다. 사유가 없는 요청은 거부하고 요청 직전의 수동 지정 여부·적용 금액·월 합계를 유지한다. 대상 Trainer·월, 지정/수정 전후 금액·사유·처리자·처리 시점을 이력으로 남긴다. 월별로 수동 지정한 기본급은 이후 일반 기본급 설정이 변경되어도 유지한다. 일반 설정 변경의 미확정 정산 자동 반영은 수동 지정이 없는 월에 적용하며, 수동 지정 월의 금액을 바꾸려면 관리자가 해당 월 금액을 직접 수정한다. 입사·퇴사·휴직이 있는 달의 적용 기본급은 관리자가 해당 Trainer·월의 금액을 직접 지정한다. 예를 들어 월 기본급 설정이 2,500,000원이어도 해당 월만 1,500,000원을 적용할 수 있으며, 이 지정으로 현재·미래 기본급 설정과 다른 월 정산은 변경하지 않는다. 이번 결정으로 설정 변경 권한을 전체 정산 조회·최초 확정 권한으로 확대하지 않는다. 미확정 월 기본급의 최초 수동 지정·수정은 Master Admin의 Organization 전체, Branch Admin의 각 처리 시점 대상 Trainer 현재 Home Branch가 관리 Branch와 일치하는 범위에서 허용한다. 관리 범위 안 본인 건도 포함하며 별도 Master 승인 없이 직접 처리한다. 관리자 권한 없는 Operator·Trainer는 수행할 수 없으며 직접 ID·위조 Branch Context·Performed Branch나 이전 소속을 근거로 권한을 우회할 수 없다. 최초 월 정산 확정 권한·전체 정산 공개 범위를 자동 허용하지 않으며 확정 월 정정은 위의 기존 승인 조건을 따른다. 미래 적용 월의 입력 범위와 금액 입력 제약은 관련 OPEN을 유지한다.

지원 수업 외 추가실적 등록·누락 후등록의 인가(2026-10-11 사용자 확정): 지원 수업 외 Additional Performance의 등록과, 확정된 발생 월의 누락분 반영을 위한 해당 Trainer·월 정산 확정 해제·재확정은 Master Admin에게 Organization 전체, Branch Admin에게 각 업무 처리 시점 대상 Trainer의 현재 Home Branch가 자신의 관리 Branch인 경우 허용한다. 등록·해제·재확정 요청마다 현재 소속과 관리 권한을 검증하고 최초 단계의 소속으로 후속 권한을 고정하지 않는다. 이전 소속·실적 발생 당시 소속·Performed Branch·클라이언트가 전달한 Branch Context만으로 권한을 부여하지 않는다. 9월 수원점 소속 때 발생한 회원 유지 실적을 10월 강남점 이동 후 처리하면 강남점 Branch Admin/Master가 담당하고, 별도 Master 권한 없는 이전 수원점 Branch Admin은 처리할 수 없다. 실적은 여전히 9월 정산·수원점 비용이며 이전 확정본과 감사 이력을 보존한다. 등록의 내용+양수 금액 필수·관리 범위 안 본인 등록·별도 승인 없음과 재확정의 기존 확정 조건/미입력 지원 수업 차단을 유지한다. 이 결정은 위 등록 및 누락분 후등록의 역할·관리 범위·소속 기준 시점에 한정한다. 누락분 반영을 위한 해제·재확정의 관리 범위 안 본인 건 허용·별도 승인 없음도 후속 사용자 결정으로 확정했다. 지원 수업 외 기존 실적의 정정/취소 권한·소속 기준 및 처리 절차는 별도 OPEN이다. 기존 지원 수업 보상/기본급 정정 권한이나 비용/조회 범위를 확대하지 않는다.

Master Admin은 Organization 전체, Branch Admin은 각 해제/정정/재확정 처리 시점 대상 Trainer의 현재 Home Branch가 관리 Branch인 경우 허용한다. 관리 범위 안 관리자·Trainer 겸임자의 본인 건도 포함하고 별도 Master/다른 관리자 승인 대기를 두지 않는다. 해제와 금액 정정 모두 사유가 필수이며 사유 없는 각 요청은 요청 직전 상태·금액·확정본/이력을 유지하고 거부한다. 해제 사유/처리자/시점과 정정 전후 금액/사유/수정자/시점을 감사 가능한 이력으로 남긴다. 정정 금액도 기존 등록/확정 전 수정과 동일하게 양수만 허용하며 0원·음수·금액 누락 요청은 사유가 있어도 거부한다. 재확정은 기존 승인 조건을 다시 검증하고 금액 미입력 지원 수업이 남으면 해당 Trainer·월을 확정하지 않는다. 정정 저장만으로 자동 재확정하지 않으며 현재 Rate/Fixed Amount/Base Salary로 과거 일반 지급/적용 기본급을 재계산하지 않는다. 실적의 발생 월 정산과 발생 당시 Home Branch 비용 귀속을 유지하고 다른 월/Trainer나 PT 진행 사실·Pass를 변경하지 않는다. 예를 들어 다른 구성 금액이 같고 기존 실적 100,000원을 120,000원으로 정정하면 이전 9월 확정 합계 3,850,000원을 보존하며 새 9월 합계는 3,870,000원이다. 금액 외 정보 수정·실적 취소·발생 시점 식별/월 경계·소급 기간·나머지 금액 제약은 별도 OPEN이다. 각 단계 계약/저장/버전·UoW·실패/재시도·이동/정산 경합은 PROPOSED이며 전체 흐름을 임의의 단일 commit으로 정하지 않는다.

Rate의 허용 값은 L2로 0~100% 정수다(BR-PAY-018). 명시적 0%와 미설정은 구분하고 기존 현재 Home Branch 기반 관리자 권한·감사/과거 지급 보존을 유지한다. 0%를 이유로 Operator/Trainer 단독에게 보상 설정 조회/수정 권한을 부여하지 않는다. [L 승인](product-decisions.md#review-20261013-l-batch).

Q1/Q2 최초/금액 경계: Trainer 신규 등록 완료에는 세 보상 값/기본급 시작 월 명시 입력과 등록/최초 보상 인가·감사가 필요하다. 일반 Fixed Amount/Base Salary의 명시적 0원 허용도 위 현재 Home 기반 관리 권한·본인 포함/타 지점 지원 및 Operator/Trainer 단독 접근 금지를 그대로 적용한다. 값이 0이라는 이유로 공개하거나 변경 권한을 확대하지 않는다. IAM 계정 발급/연결이나 이후 기본정보 수정의 보상 재입력/초기화와 구별한다(BR-OPS-028/PAY-022; [Q 승인](product-decisions.md#review-20261013-q-batch)).

S2 후속 확정: 세 보상 설정의 변경 이력 전후 값·변경자·시점은 현재 설정과 같은 Master Organization/조회 시점 Trainer 현재 Home Branch Admin 범위로 공개한다. 이전 소속 때의 변경도 현재 Home 관리자가 조회하고 이전 소속/Performed·원래 변경자만으로 접근하지 못한다. 최초 이전 값 없음과 0원을 구별하고 원래 Actor/Role/Branch Context·시점을 보존한다. Operator/Trainer 단독 금지와 관리 범위 안 본인의 독립 관리자 Scope를 유지한다. 현재 설정 변경 인가·과거 지급 불변성·C7 인증/계정 관리 감사 Master 전용과 구별한다(BR-PAY-023; [S 승인](product-decisions.md#review-20261013-s-batch); V-119 미구성·미실행).

## 추가실적 직접 등록

2026-10-11 사용자 확정(확정된 월의 누락된 지원 수업 외 추가실적 처리 질문의 1번 답변): 이미 확정된 발생 월의 누락된 지원 수업 외 Additional Performance는 해당 Trainer·월 정산의 확정 해제 → 누락 실적 등록 → 같은 발생 월 재확정으로 반영한다. 이전 확정본은 보존하고 재확정 결과와 구분한다. 확정 상태에 직접 추가하여 이전 확정본을 덮어쓰거나 등록 월/다른 월로 이월하지 않는다. 기존 직접 등록의 Master/Branch Admin 대상 범위·관리 범위 안 본인 등록·승인 생략·감사는 유지한다. 이번 흐름 선택만으로 이 후등록을 위한 정산 해제/재확정의 역할·Scope/소속 기준·본인 건/별도 승인·사유를 확정하지 않는다. 기존 지원 수업/기본급 정정의 승인된 권한은 유지하며 이 후등록의 남은 정책은 BR-009/013 OPEN이다.

2026-10-11 사용자 확정(지원 수업 외 추가실적을 반영할 정산 월 질문의 1번 답변): 회원 유지 등 지원 수업 외 Additional Performance는 실제 실적이 발생한 월의 Trainer 월 정산에 귀속한다. 9월에 발생한 실적을 10월에 등록해도 9월분이며 등록 월이나 금액 입력 월로 이월하거나 관리자가 반영 월을 임의 선택하지 않는다. 같은 실적을 9월·10월에 중복 합산하지 않는다. 기존 관리자 등록 Scope·본인 건·승인 생략·감사와 발생 당시 Home Branch 비용 귀속은 유지한다. 발생 월/당시 소속은 등록·정정 권한의 자동 근거가 아니다. 이동 시 인가 시점과 확정된 발생 월의 후등록/해제·재확정 절차는 관련 OPEN이다.

2026-10-11 사용자 확정(지원 수업 외 추가실적의 0원 등록 허용 여부 질문의 1번 답변): 회원 유지 등 지원 수업 외 Additional Performance의 등록 금액은 0원보다 큰 양수만 허용한다. 0원과 음수 입력은 등록을 거부하며, 사유를 남겨도 0원으로 등록할 수 없다. 기존대로 내용과 금액을 함께 입력해야 등록이 완료되고 누락 금액을 자동으로 채우지 않는다. 기존 관리자 대상 범위·본인 등록·승인 생략·감사는 유지하며 관리자 권한이나 사유가 있어도 비지원 실적의 0원 등록을 허용하지 않는다. 지원 수업의 사유 필수 0원 확정은 유지한다. 상한액·정밀도·정정/취소 등은 관련 OPEN이다.

2026-10-11 사용자 확정(지원 수업 외 추가실적의 등록 시점 질문의 1번 답변): 회원 유지 등 지원 수업 외 Additional Performance는 권한 있는 관리자가 실적 내용과 금액을 함께 입력해야 등록이 완료된다. 금액 미입력 요청은 등록을 완료할 수 없으며, 금액 없는 실적을 먼저 등록하고 나중에 금액을 입력하는 흐름은 v1에 두지 않는다. 누락 금액을 자동으로 0원이나 계산식 결과로 대체하지 않는다. 기존 관리자 등록 범위·본인 직접 등록·승인 생략·감사를 유지한다. Trainer의 PT 기록 등록과 지원 수업의 기록/차감 후 관리자 금액 저장 흐름은 유지한다. 입력 필수 요건으로 0원 허용·정정 권한·이동 시 인가 시점을 자동 확정하지 않는다.

2026-10-11 사용자 확정(Trainer의 별도 추가실적 신청 기능 질문의 1번 답변): v1 추가실적은 권한 있는 관리자의 직접 등록만 지원하고 Trainer의 시스템 내 별도 신청·승인/반려 흐름은 두지 않는다. Trainer는 실적 내용을 관리자에게 전달하며 기존 Master Admin/Branch Admin이 허용된 관리 범위에서 입력한다. Master Organization 전체/Branch Admin 대상 Trainer Home Branch 범위·관리 범위 안 본인 등록·별도 승인 없음·감사는 유지한다. 관리자·Trainer 겸임자는 관리 권한 범위 안에서 본인에게 직접 등록할 수 있으며 Trainer 역할만으로 등록 권한을 얻지 않는다. Trainer의 실제 PT 진행 기록 등록은 계속 지원하며 이를 추가실적 신청으로 취급하지 않는다. 지원 수업의 진행 기록·Pass 차감 완료 후 관리자 금액 저장 시 보상 확정과 미입력 지원 수업의 해당 Trainer·월 정산 확정 차단은 유지한다. 금액 산정·비용 귀속·기존 정정/확정/조회 권한은 변경하지 않는다. 추가실적의 남은 입력 제약/확정 시점·소속 이동 시 인가 시점·정산 월·정정/취소 등은 관련 OPEN이며 신청 기능의 향후 도입은 별도 결정 대상이다.

2026-10-11 사용자 확정(회원 유지 등 지원 수업 외 추가실적의 금액 산정 방식 질문의 1번 답변): 회원 유지 등 지원 수업 외 Additional Performance의 금액도 권한 있는 관리자가 실적 건별로 직접 입력한다. v1에서 유형별 사전 금액·산식으로 자동 계산하는 방식을 채택하지 않으며 일반 RATE/FIXED_AMOUNT 계산 결과로 입력액을 대체하지 않는다. 기존 Master Organization 전체/Branch Admin 대상 Trainer Home Branch 범위·관리 범위 안 본인 등록·별도 승인 없음·감사는 유지한다. 비용은 실적 발생 당시 Trainer Home Branch에 귀속하는 기존 기준을 따른다. 이 결정은 금액 산정 방식에 한정하며 지원 수업 외 실적의 금액 확정 시점·미입력/0원·입력 제약·정산 월·이동 시 등록/정정 인가 시점·Trainer 신청/승인·정정/취소 등 남은 정책은 관련 OPEN이다. 지원 수업에 승인된 기록/차감 후 보상 확정·사유 필수 0원·금액 미입력 월 정산 차단을 다른 실적에 자동 적용하지 않는다.

2026-10-10 사용자 확정: Master Admin은 Organization 전체 Trainer, Branch Admin은 자신의 관리 Branch를 Home Branch로 가진 Trainer에게만 추가실적을 직접 등록한다. 타 지점에서 수행한 수업도 Trainer 소속 지점 관리자 또는 Master가 등록한다. 지원받은 지점 관리자는 다른 Home Branch Trainer의 추가실적을 등록할 수 없다. 예를 들어 수원점 소속 Trainer의 강남점 지원 수업은 수원점 관리자 또는 Master가 등록하고 강남점 관리자는 등록할 수 없다. Backend에서 관리 Scope와 대상 Trainer의 Home Branch를 확인한다.

같은 날 추가 사용자 확정으로 Branch Admin이 본인이 아닌 자기 지점 소속 Trainer에게 직접 등록할 때는 별도 Master 승인이 필요 없다. Master 승인 대기를 추가하지 않으며 생성·변경 감사는 유지한다. 월 정산 확정으로 확대하지 않는다. 본인 건은 아래의 후속 결정을 따른다.

같은 날 본인 등록 질문의 2번 답변으로 관리자·Trainer 겸임자도 관리 범위 안이면 본인의 추가실적을 직접 등록할 수 있다. Master Admin은 Organization 범위 안의 본인, Branch Admin은 본인 Trainer의 Home Branch가 관리 Branch와 같을 때 허용하며 다르면 거부한다. Trainer 역할만으로 이 관리 권한을 얻지 않는다. 본인 등록도 동일하게 감사하며 등록 Actor와 대상 Trainer가 같은 사람임을 추적한다. 이 권한은 추가실적 업무의 별도 사용자 결정이다.

같은 날 본인 건 승인 질문의 1번 답변으로 관리 범위 안에서 직접 등록한 본인의 추가실적도 별도 승인 없이 처리한다. Master나 다른 관리자의 승인 대기를 추가하지 않으며 관리 권한·Home Branch 범위 검증과 본인 등록의 동일한 생성·변경 감사는 유지한다.

타 지점 지원 수업 보상 금액은 권한 있는 관리자가 수업 건별로 직접 입력한다(2026-10-10 금액 계산 질문의 3번 답변). Master/Branch Admin의 기존 대상 Home Branch 범위·본인 등록·승인 생략·감사 정책은 유지한다. 타 지점 지원 수업은 보상 금액 없이도 허용된 PT 진행 기록과 Pass 차감을 먼저 완료한다. 권한 있는 관리자가 나중에 수업 건별 금액을 저장할 때 해당 Additional Performance 보상을 확정한다. 금액 미입력은 확정된 0원과 구분하고 누락 건을 추적할 수 있어야 한다. 해당 Trainer의 해당 월 정산 대상 지원 수업에 금액 미입력 건이 하나라도 있으면 그 Trainer·월 정산을 확정할 수 없다. 타 지점 지원 수업 보상은 권한 있는 관리자가 사유를 기록하면 0원으로 명시적으로 확정할 수 있다. 사유 없는 0원 입력은 보상 확정이 불가하다. 사유를 남기고 확정한 0원은 금액 미입력이 아니므로 그 건으로 월 정산 확정을 차단하지 않는다. 다른 미입력 건이 남으면 기존 차단 조건을 유지한다. 월 정산 확정 전 지원 수업 보상 금액 수정은 Master Admin에게 Organization 전체, Branch Admin에게 대상 Trainer Home Branch가 자신의 관리 Branch인 경우 허용한다. 관리 범위 안의 본인 건도 허용하고 변경 이력을 남긴다. 월 정산 확정 전 지원 수업 보상 금액 수정은 Master Admin·Branch Admin 모두 관리 범위 안에서 본인 건을 포함해 별도 승인 없이 저장 성공 즉시 반영한다. Master나 다른 관리자의 승인 대기를 두지 않으며 권한 검증과 변경 이력을 유지한다. 월 정산 확정 전 지원 수업 보상 금액의 모든 수정에는 변경 사유가 필수다. 양수 간 변경·0원에서 양수로 변경·양수에서 0원으로 변경 모두 적용하며, 사유 없이는 금액을 수정할 수 없다. 변경 전후 금액·변경 사유·수정자·수정 시점을 이력으로 남긴다. 확정된 월 정산에서 지원 수업 보상 금액 오류를 발견하면 해당 Trainer·월 정산의 확정을 해제하고 금액을 정정한 뒤 해당 월 정산을 다시 확정한다. 이전 확정본은 이력으로 보존한다. 지원 수업 보상 금액 오류 정정의 월 정산 확정 해제·재확정은 Master Admin은 Organization 전체 Trainer, Branch Admin은 자신의 관리 Branch를 Home Branch로 가진 Trainer에 대해 허용한다. Branch Admin이 자신의 관리 Branch를 Home Branch로 가진 Trainer의 지원 수업 보상 정정을 위해 월 정산을 확정 해제·재확정할 때는 Master의 별도 승인을 두지 않는다. Master 승인 대기 단계 없이 관리 범위 안에서 직접 처리하며 이전 확정본과 해제·재확정 이력 및 감사를 유지한다. 지원 수업 보상 정정의 월 정산 확정 해제에는 사유가 필수이며, 사유 없이 해제할 수 없다. 사유·해제자·시점을 이력으로 남긴다. 과거 지원 수업 보상 정정·해당 월 정산 확정 해제/재확정에서 Branch Admin의 권한은 각 업무 처리 시점의 Trainer 현재 Home Branch를 기준으로 검증한다. 이전 소속만으로 권한을 유지하지 않으며 Master Admin의 Organization 전체 권한은 유지한다. 남은 정정·취소 절차는 BR-009/013 등 관련 OPEN을 따른다. Trainer 역할로 진행 기록을 등록하는 것은 관리자 금액 입력·수정 권한을 부여하지 않는다. 월 확정 전 금액 수정에서도 타 지점 지원 수업의 Performed Branch만을 근거로 다른 Home Branch Trainer에 대한 권한을 주지 않는다. 사유를 남긴 지원 수업 0원 확정에도 동일한 관리자 Scope·본인 등록·승인 생략·감사 정책을 적용한다. 미입력 건의 조회 범위와 남은 마감/정정 상세는 관련 OPEN을 따른다. 최초 월 정산 확정 권한은 아래 2026-10-11 별도 사용자 결정을 따른다. 지원 수업 보상 정정의 해제·재확정 권한은 금액 수정 권한에서 자동 상속한 것이 아닌 이번 별도 사용자 결정이다. Performed Branch만을 근거로 다른 Home Branch Trainer의 정산을 해제·재확정할 수 없다. 지원 수업 외 실적의 금액 외 정보 수정/취소의 소속 이동 시 Home Branch 권한 기준은 관련 OPEN이다. 이 확정 차단 조건으로 정산 열람·확정 권한을 새로 부여하지 않는다.

Operator의 남은 업무 권한, 지원 수업 외 실적의 금액 외 정보 수정/취소의 소속 이동 시 권한 기준 시점은 [BR-013](open-questions.md#br-013)의 남은 질문이다. 본인 건의 승인 생략을 월 정산 확정으로 확대하지 않는다. 등록 권한을 타 지점 전체 자료 열람으로 확대하지 않으며 비용 귀속·정산 공개는 MB-010/006에서 별도 결정한다. 생성·정정·취소의 감사 요구는 유지한다.

지원 수업 보상의 비용 귀속(2026-10-11 사용자 확정): 타 지점 지원 수업의 전체 보상으로 확정한 Additional Performance 금액은 해당 수업의 실제 Performed Branch 비용으로 집계한다. 금액 입력·정정·정산 확정 권한은 기존 관리 Scope를 유지한다. 수행 지점 비용으로 집계된다는 이유로 그 지점 관리자에게 다른 Home Branch Trainer의 금액 입력·보상 설정/전체 정산 열람 권한을 부여하지 않는다. v1 지점별 비용 보고서의 조회 역할은 아래 후속 결정으로 Master 전용이며 보고서 항목·집계/완전성·버전 등 남은 상세는 MB-010/006 OPEN이다.

이동월 기본급 비용 귀속(2026-10-11 사용자 확정): 월중 Trainer 지점 이동이 있는 달의 해당 월 적용 기본급 비용은 대상 월의 월말 Home Branch 한 곳에 전액 귀속한다. 이는 내부 비용 집계 기준이며 기존 정정·확정·조회 권한은 각 처리 시점 Trainer 현재 Home Branch로 인가한다. 대상 월말 비용 귀속 지점과 현재 관리 Branch가 다를 수 있으며 비용 귀속 사실만으로 권한을 부여하지 않는다. 예를 들어 10월말 강남 소속 Trainer가 11월 다른 지점으로 이동해도 10월 기본급 비용은 강남점에 남고 10월 정산 정정 인가는 기존 현재 Home Branch 기준을 따른다.

일반 PT 수당의 비용 귀속(2026-10-11 사용자 확정): 일반 Session Payment는 해당 PT 진행 기록의 실제 Performed Branch 비용으로 집계한다. 이미 확정된 수업별 지급액을 지점별로 합산하며 대상 월말 Home Branch로 전액을 모으지 않는다. 비용 귀속은 기존 관리 Scope와 별개다. 수행 지점 비용이라는 사실만으로 다른 Home Branch Trainer의 보상 설정/전체 정산 열람·정정 권한을 부여하지 않는다. Trainer 월 지급 합계·기존 처리 시점 Home Branch 인가·이동월 기본급의 월말 소속 귀속은 유지하며 비용 보고 공개/집계 상세는 관련 OPEN이다.

지원 수업 외 추가실적의 비용 귀속(2026-10-11 사용자 확정): 지원 수업 외 Additional Performance의 비용은 실적 발생 당시 대상 Trainer의 Home Branch에 귀속한다. 등록 시점·금액 확정 시점·대상 월말 또는 조회 시점의 소속으로 대체하지 않는다. 지급 금액·월 합산 횟수·기존 관리 권한은 유지한다. 비용이 발생 당시 소속 지점으로 잡혀도 그 지점 관리자에게 이후 다른 소속 Trainer의 등록·정정·보상 설정/전체 정산 열람 권한이 자동으로 생기지 않는다. 지원 수업 외 추가실적의 소속 이동 시 등록/정정 인가 기준 시점은 BR-013의 별도 미결정 사항이다.

2026-10-12 H2/H3=1: 지원 수업 외 실적 내용 수정/취소도 Master Organization/Branch Admin 각 처리 시점 Trainer 현재 Home Branch 범위에 허용한다. 본인 포함·별도 승인 없음·사유/전후 내용/상태·Actor/시점 이력·감사 필수다. 대상 Trainer/발생 날짜 오류는 취소 후 올바르게 재등록·연결하며 원래 대상 취소와 새 대상 등록/각 확정 월 해제·재확정은 각각의 현재 Scope로 판단한다. 과거 등록자/소속·지원받은 지점으로 권한을 유지하지 않고 비관리자에게 정정 권한을 추가하지 않는다. ## 월 정산 조회·최초 확정

2026-10-11 사용자 확정(지점별 비용 보고서 조회 권한 질문의 1번 답변): v1 지점별 비용 보고서는 Master Admin만 Organization 범위에서 조회한다(2026-10-11 사용자 확정). Branch Admin은 자기 지점 비용 합계도 이 보고서로 조회할 수 없으며 Master 권한 없는 Operator·Trainer도 불가하다. Branch Admin의 현재 자기 Home Branch 소속 Trainer 해당 월 정산 전체 금액·구성 내역 조회는 타 지점 지원 보상까지 포함하여 유지한다. 비용 귀속·지급액·기존 등록/정정/확정 권한은 유지하며 보고서 항목·대상 월·집계/완전성·버전 등 남은 상세는 MB-006/010 OPEN이다. Master Admin·Trainer 겸임자는 Master 권한으로 허용하며 Branch Admin·Trainer 겸임만으로는 보고서에 접근하지 못한다. Backend는 보고서의 개별·목록·검색·집계 요청에 현재 Master 권한과 Organization Scope를 적용한다.

2026-10-11 사용자 확정(지점장이 조회할 정산 내역의 범위 질문의 1번 답변): Branch Admin은 조회 시점에 자신의 관리 Branch를 Home Branch로 가진 Trainer의 해당 월 정산 전체 금액과 구성 내역을 조회할 수 있다. 해당 월 적용 기본급·일반 Session Payment·타 지점 지원 수업을 포함한 Additional Performance·월 정산 총액을 모두 공개하며, 수업의 Performed Branch가 다른 지점이라는 이유로 해당 금액을 제외하거나 숨기지 않는다. 관리 범위 안 본인 Trainer도 포함하고 Master Organization 전체 조회는 유지한다. 다른 Home Branch Trainer는 자기 지점에서 수업했다는 사실만으로 전체 정산을 조회할 수 없다. 대상 월·이전 확정본/세부 계산 근거·감사 공개 등 남은 상세는 MB-006, 비용 귀속은 MB-010 OPEN이다.

2026-10-11 사용자 확정(월 정산을 처음 확정할 권한 질문의 1번 답변): 월 정산의 최초 확정은 Master Admin에게 Organization 전체 Trainer, Branch Admin에게 확정 처리 시점 대상 Trainer의 현재 Home Branch가 자신의 관리 Branch인 경우 허용한다. 관리 범위 안 본인 건도 포함하며 별도 Master 승인 없이 직접 확정한다. 관리자 권한이 없는 Operator·Trainer는 수행할 수 없으며, 수행 지점이나 과거 소속만으로 다른 현재 소속 Trainer의 최초 확정 권한을 얻지 않는다. 지원 수업 미입력 차단 등 승인된 확정 조건은 유지한다. 전체 정산 공개 범위는 MB-006, 지점 비용 귀속은 MB-010으로 별도 결정한다.

2026-10-12 H4=1: 관리자 권한 없는 Trainer의 본인 월 정산 시스템 조회는 v1 제외이며 관리자가 안내한다. 기존 본인 PT 진행 내역 조회는 유지하고 이를 정산 총액/구성 또는 보상 설정 읽기로 확대하지 않는다. Master/Branch Admin 겸임자는 기존 독립 현재 관리 Scope에 따라 본인 포함 정산을 조회할 수 있다. 화면뿐 아니라 Backend의 직접 ID/API/집계 요청도 같은 권한을 검증한다. 별도 급여 안내/발송 기능 승인이 아니다. [2026-10-12 H 일괄 승인](product-decisions.md#review-20261012-h-batch).

확정 가능 월 추가(L1): 현재 허용된 관리자도 한국 시간 기준 종료된 월만 확정/재확정할 수 있다. 당월은 기존 범위 안 미확정 조회/검토하며 비관리자 Trainer 월 정산 조회는 v1 제외를 유지한다. 시간 조건만으로 확정 권한·다른 필수 조건/미입력 지원 보상 차단을 면제하거나 자동 확정하지 않는다(BR-PAY-020; [L 승인](product-decisions.md#review-20261013-l-batch)).

S1 후속 확정: 이전 월 정산 확정본과 확정 해제·재확정 이력은 Master Organization/각 조회 시점 Trainer 현재 Home Branch Admin이 조회한다. 이전 소속 이력도 현재 관리자가 확인하고 이전 소속 관리자/Performed만으로 권한이 남지 않는다. 당시 금액/구성·이전 버전·정정 이유/변경자/시점은 보존한다. 기존 전체 정산 공개·본인 독립 관리자 Scope·H4 비관리자 Trainer 제외·N1/N2 기밀성 및 지점 비용 보고 Master 전용은 유지한다. 쓰기/확정 해제·재확정 권한과 다른 업무 원본/Audit 전체 열람은 추가하지 않는다. 위 과거 문단의 이전 확정본/감사 공개 미정 중 이 범위만 해결하며 추가 필드/계산 근거/계약은 후속이다(BR-PAY-023; [S 승인](product-decisions.md#review-20261013-s-batch); V-118 미구성·미실행).

## 계정 수명과 감사

Master Admin이 Branch Admin과 계정/권한을 관리한다. 관리자 발급 방식은 유지하며 Trainer 직접 로그인 계정을 포함한다. Branch Admin은 자기 단일 관리 Branch의 새 Operator 계정을 발급하고 최초 업무 Branch를 지정할 수 있다(2026-10-12, BR-OPS-011). 기존 Operator 업무 Branch 변경은 Master Organization 범위 전용이며 Branch Admin은 불가하다(2026-10-12, BR-OPS-011). 신규 Trainer 로그인 계정 발급은 Master Organization 전체/Branch Admin 대상 Trainer의 현재 Home Branch 관리 범위에서 승인됐다(2026-10-12, BR-OPS-012). E5로 기존 계정 Operator·Trainer 역할 추가/회수의 Branch Admin 관리 범위는 승인됐다(BR-OPS-019). 다른 역할/Scope·계정 수명 위임과 구체 상태/연결/재부여·계약은 후속이다. 초기 Master Admin, 비밀번호 설정/재설정, 계정 중단, 마지막 Master Admin 보호, 접근 종료/만료는 ARCH-002에서 상세화한다. 기존 계정·암호는 이관하지 않는다.

2026-10-10 최초 비밀번호 설정 결정: Master가 일회용 비밀번호 설정 링크를 대상자에게 전달하고 대상자가 직접 설정한다. 전달 채널·유효기간·재발급·활성 계정 재설정은 [ARCH-002](open-questions.md#arch-002)의 남은 질문이다.

중요 관리 행위는 필요 시 Actor, Actor Role, Branch Context, 대상 데이터, 행위, 변경 전후 값, 수행 시점을 식별해야 한다. 비활성화 이후 과거 이력 조회에도 Data Scope와 기밀성 제한을 유지한다. 감사 schema는 여기서 정의하지 않는다.

추적: [PR-001/008/020/021/027/029/030](requirements.md), [PD-001–006/019/022](product-decisions.md), [MB-001–008 및 ARCH-001/002/LEGAL-001](open-questions.md), [Architecture 인계](architecture-handoff.md).

2026-10-12 사용자 확정(Operator 계정 발급과 최초 지점 지정 권한 질문의 1번): Master Admin은 자신의 Organization 범위에서, Branch Admin은 자신의 단일 관리 Branch 범위에서 새 Operator 계정을 발급하고 그 한 지점을 최초 업무 Branch로 지정할 수 있다. Branch Admin의 타 지점 Operator 발급은 허용하지 않는다. Backend는 처리 시점의 검증된 현재 Caller 역할/Organization·관리 Branch와 대상 Branch의 실제 Organization 관계를 확인하며 직접 ID·위조 role/branch_id·과거 권한으로 범위를 우회할 수 없다. Operator 단독·Trainer 단독의 로그인 계정 발급은 허용하지 않는다(BR-OPS-011, PD-019, PR-021/030, NFR-001/004, MB-004, ARCH-001/002).

승인 범위: 새 Operator 계정 발급과 단일 Branch의 최초 지정이다. Branch Admin의 Master/Branch Admin 역할 발급, 기존 계정의 역할 추가·변경·계정 중단/복구·비밀번호 재설정 권한을 추가하지 않는다. 신규 Trainer 계정 발급은 별도 후속 승인된 BR-OPS-012의 현재 Trainer Home Branch 규칙을 적용한다. 기존 Operator Branch 변경은 별도 후속 승인된 Master 전용 규칙을 적용한다. 기존 겸임 역할의 독립 Scope·Trainer Home Branch 및 민감 보상 접근 제한을 유지한다. 계정 발급과 새 Pass 발급은 서로 다른 업무이며 Operator의 Pass 발급 허용을 계정 발급 권한으로 해석하지 않는다.

기존 사용자 일관성 지시(2026-10-11) 적용: 이번에 허용된 Operator 발급에도 기존 최초 비밀번호 설정 방식을 사용한다. 권한 있는 발급 관리자가 일회용 비밀번호 설정 링크를 대상자에게 전달하고 대상자가 직접 설정한다. 허용 범위 내 Branch Admin 발급에 별도 Master 승인 대기를 추가하지 않는다. 고정/임시 평문 비밀번호를 계정에 넣거나 긴 토큰 수동 입력을 기본 흐름으로 요구하지 않는다. 최초 설정 링크 30분/단일 사용·재발급 시 이전 링크 폐기는 A4로 해결됐다. 전달 채널/수신자 확인·활성 계정 재설정·나머지 계정 수명 상세는 ARCH-002의 게이트를 유지한다.

기존 중요 계정/권한 변경의 감사·일관성 원칙 적용: 대상 계정·Operator 역할·최초 업무 Branch·발급 Actor/현재 권한·Branch Context·시점을 추적한다. 비밀번호/해시·설정 토큰·전체 설정 링크를 일반 로그/감사에 복사하지 않는다. 거부·실패 시 계정/역할/최초 Scope·필수 감사 중 일부만 확정되는 상태를 남기지 않는 경계를 설계한다. 구체 감사 저장/열람·보존, 계정 활성화·역할/Scope 표현·UoW/동시성은 후속이며 새로운 필수 입력 사유를 추가하지 않는다.

2026-10-12 사용자 확정(기존 Operator의 근무 지점 이동 권한 질문의 1번): 기존 Operator의 단일 업무 허용 Branch 변경은 Master Admin만 자신의 Organization 범위에서 수행할 수 있다. Branch Admin은 변경 전/후 지점 관리자이거나 해당 계정의 최초 발급자여도 변경할 수 없다. Operator·Trainer 단독도 불가하며 겸임자는 현재 Master 권한이 있을 때만 그 관리 Scope로 처리한다(BR-OPS-011, PD-019, PR-021/030, NFR-001/004, MB-004, ARCH-001).

업무 지점 변경은 기존 저장 후 현재 Scope 반영·실패 보존·계정/권한 감사 원칙을 적용한다. 계정의 다른 관리/Trainer 역할·Trainer Home Branch 및 기존 업무 이력을 자동 변경하지 않는다. 대상 Branch/계정 상태·역할/계정 수명·저장/철회 계약은 해당 기존 게이트를 유지한다(BR-OPS-011).

2026-10-12 사용자 확정(신규 Trainer 로그인 계정 발급 권한 질문의 1번): Master Admin은 자신의 Organization 전체 Trainer, Branch Admin은 발급 처리 시점 대상 Trainer의 현재 Home Branch가 자신의 단일 관리 Branch인 경우 신규 Trainer 로그인 계정을 발급할 수 있다. Branch Admin은 타 지점 소속 Trainer 계정을 발급할 수 없다. 타 지점 지원 수업·담당 회원/Pass·Performed Branch·Operator 업무 Branch·최초 발급자/과거 소속 사실만으로 이 권한이 생기지 않는다. Operator·Trainer 단독은 본인 포함 로그인 계정 발급 불가이며 관리자 겸임은 현재 관리자 역할의 독립 Scope로 판단한다(BR-OPS-012, PD-019, PR-021/029/030, NFR-001/004, MB-004, ARCH-001/002).

신규 Trainer 발급에도 기존 일회용 최초 비밀번호 설정 링크·대상자 직접 설정/계정 권한 감사·실패 일관성 원칙을 적용한다. 기존 계정 역할 추가/재연결·Trainer 소속 이동·수명 업무 위임은 별도이며 실제 연결/저장/보안 계약은 후속이다(BR-OPS-012).

2026-10-12 일괄 승인 반영: Trainer 재활성화는 Master Organization/Trainer 현재 Home Branch Branch Admin이 처리하고 다른 활성 역할 없는 비활성 Trainer는 로그인 불가/재활성화 후 이용한다. 독립 관리자 겸임 역할은 유지한다. 계정 전체 차단/복구·관리자 비밀번호 재설정은 같은 Organization Master만 가능하며 지점 관리자 발급 권한을 전체 계정 복구 권한으로 확대하지 않는다. 여러 Master를 허용하되 마지막 사용 가능한 Master 차단/권한 제거는 금지한다. 관리 역할/관리 지점 변경 시 기존 로그인 모두 종료, 복수 기기·일반 logout 현재 로그인만 종료, 모든 역할 idle 30분/absolute 8시간, 최초 설정 링크 30분/단일 사용/재발급 이전 링크 폐기. 관리자 MFA는 운영 전 필수다. [2026-10-12 일괄 승인](product-decisions.md#review-20261012-batch).

2026-10-12 C 일괄 승인 반영: C1은 유효 로그인/현재 행위·Scope 안에서 추가 비밀번호 재확인 없이 계정 관리 허용이다. 본인 암호 변경은 현재 암호 확인 후 현재 포함 전 로그인 종료(C3). 계정당 15분 5회 실패 후 15분 대기(C2), Master reset 확정 즉시 기존 자격/로그인 무효·마지막 Master 일반 reset 금지(C4/C5), Master Login ID 변경/전 로그인 종료(C6), 자기 Organization Master만 인증/계정 관리 감사 열람(C7), 로그인 최소 기록/원문 IP·브라우저 제외(C8)를 적용한다. 기존 계정 발급 Scope/관리자 겸임·보상 정보 제한/다른 업무 감사 권한·운영 전 MFA는 유지한다. [2026-10-12 C 일괄 승인](product-decisions.md#review-20261012-c-batch)

2026-10-12 E 일괄 승인 반영: E1–E4/E6은 최초1회 설치 명령/본인 암호 설정, 관리자 본인 확인·대면/확인된 1:1 링크 전달, Login ID 대소문자 미구별·이전 ID 원래 계정 예약/다른 계정 재할당 금지·현재 ID만 로그인, Master 일반 계정 차단 해제 시 유효 기존 암호 재로그인이다. E5는 Master Organization/Branch Admin 자기 관리 범위에서 기존 Operator·Trainer 역할만 추가/회수 허용(BR-OPS-019)이다. 대상 역할의 지점 Scope를 따로 검증하고 독립 관리 역할/다른 Scope·연결/이력은 보존한다. 계정 차단/복구·관리자 reset/ID 변경·인증 감사 열람 및 기존 지점 이동의 Master 전용은 유지한다. 차단 해제가 옛 인증/무효 암호·회수한 역할·MFA/Trainer 상태를 복원하지 않는다.
