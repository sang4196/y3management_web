# Architecture 설계를 위한 Product Input Baseline

현재 후속 정책: [2026-10-13 AB 승인](product-decisions.md#review-20261013-ab-batch)의 AB1–AB6 모두 1번이다. 월 정산 대상은 적용 기본급/월별 지정·유효 PT/보상대기 지원 PT/추가실적 등으로 자동 선정하며, 한 달 전체 Trainer 비활성·명시 기본급0·무활동·정정 대기 없는 경우 새 정산 확정 의무에서 제외한다. 기존 이력/미완료와 비활성만으로 기본급을 자동0으로 바꾸지 않음은 유지한다. 후속 reset 링크30분·운영 관리자 비밀번호 뒤 Passkey·업무책임자 승인/별도 운영담당자 비상 복구·Chrome/Edge/Safari 최신2개 안정 주버전을 선택했다. K3/X1 첫 IAM/별도 구현 지시·구체 계약 PROPOSED와 22 OPEN/8 CLOSED는 유지한다.

2026-10-12 일괄 승인 반영: B1–B7/A1–A10의 선택은 [2026-10-12 일괄 승인](product-decisions.md#review-20261012-batch)을 따른다. A4/A5만 2번으로 최초 설정 링크 30분 및 전 역할 공통 idle 30분/absolute 8시간이다. 다른 항목은 1번이며 v1 PG AuthSession+opaque Cookie 방식은 ADR-0004 ACCEPTED, JWT는 후속 버전의 재검토 후보다. 새 Pass 활성 담당 필수/상품 횟수 최초 부여·인가 관리자 발급 횟수 초과 추가, Trainer 재활성화/비활성 전용 로그인 제한, 데이터 있는 Branch 비활성화/신규 업무 차단·원본 보존, 공통 한국 시간도 확정됐다. 모듈·저장/계약/UoW·경합의 기술 제안/남은 Product OPEN은 유지하며 코드/migration·의존성·실행 검사는 변경/수행하지 않았다. 앞선 PROPOSED/미결정 기록은 당시 이력이고 이번 승인 범위에 한해 대체한다.

2026-10-12 사용자 확정(비활성화 전 누락 수업 대행 등록의 Branch Admin 기준 질문 1번): Master Admin은 자신의 Organization 전체, Branch Admin은 처리 시점 현재 관리 Branch가 실제 수업의 Performed Branch인 경우에만 대행 등록할 수 있다. Trainer 현재 Home Branch가 다른 지점이어도 실제 수업이 자신의 관리 지점에서 진행됐다면 허용한다. Trainer Home Branch·Member Home Branch·Pass Issued Branch 또는 과거 관리자 Scope만으로 대행 권한을 얻지 않는다(BR-OPS-015). 현재 비활성/담당·Pass/보상/진행 월 정산과 별도 민감정보 접근 제한은 유지한다. 과거 사실 확인/선택 계약·구체 저장/경합은 후속이며 ADR-0004/Architecture PROPOSED·IAM-001 S1 범위와 OPEN 상태는 유지한다.

비활성 전 누락 수업 관리자 대행 승인(2026-10-12, BR-OPS-015): Trainer 비활성 상태/현재 담당을 유지하고 실제 수행자/수업일로 대행 등록하는 경로를 허용한다. 입력 관리자와 수행자·기록 시점/진행일을 분리하며 기존 Pass 차감/생성 시점 수행 Trainer 설정·진행 월 정산/민감 정보 경계를 적용한다. 현재 대행 인가 검증·비활성 전 사실/시점 판정·선택/증빙·계약/UoW/경합은 후속이다. PROPOSED/S1 범위 유지, V-69는 미구성·미실행 계획이다.

새 담당 Trainer 활성 조건 승인(2026-10-12, BR-OPS-008/014): 최초 담당 지정이 허용되는 흐름/기존 교체에서는 실제 활성 Trainer만 지정한다. 같은 Organization의 타 지점 활성 Trainer는 기존 조건에서 가능하며 현재 사실/Caller 인가·지정/비활성화의 확정 순서를 검증해야 한다. 이후 비활성화된 기존 담당 정보는 유지/접근 차단한다. 최초 담당 필수는 해결됐고 계정/Branch 상태 조합·비활성 전 수업/재활성화·최소 공개 계약/저장/UoW·경합은 후속이다. PROPOSED/S1 범위 유지, V-68은 미구성·미실행 계획이다.

잔여 Pass 보유 Trainer 비활성화 승인(2026-10-12, BR-OPS-008/014): 잔여 Pass가 있어도 허용하며 기존 Assigned Trainer 정보 유지/자동 해제·재배정 및 사전 일괄 교체 없음. 비활성 Trainer 접근 차단·Pass 잔여/이력 보존, 후속 교체는 Member 현재 Home Branch 관리자 인가로 별도 수행한다. Trainer 비활성화의 Trainer Home Branch 권한과 분리한다. 개별 지원·재활성화·저장/계약/UoW·경합은 후속이며 PROPOSED/S1 범위 유지. V-67은 미구성·미실행 계획이다.

Trainer 비활성화 Actor 추가 승인(2026-10-12, BR-OPS-014): Master Organization 전체/Branch Admin 처리 시점 현재 Trainer Home Branch 범위에서 비활성화를 허용하며 실제 현재 Caller/대상 사실을 Backend 검증한다. 겸임 관리자 역할/Scope 유지·전체 계정 차단 분리는 유지한다. 재활성화·Trainer 단독 로그인·개별 지원·재활성화/상태 처리·계약/저장/UoW·동시성은 후속이고 IAM-001 S1/PROPOSED 상태 유지. V-66은 미구성·미실행 계획이다.

Trainer 비활성화 추가 승인(2026-10-12, BR-OPS-014): 겸임 계정은 Trainer 권한만 중단하고 독립 관리자 역할/Scope와 관리 업무를 유지한다. 계정 전체 차단과 분리하며 실제 Trainer 상태 기반 인가·과거 이력 보존을 적용한다. 재활성화·Trainer 단독 로그인·관계 처리·비활성 상태 예외 및 역할/상태 저장·Caller/AuthSession·UoW/동시성은 ARCH-001/002·MB-001 후속이다. IAM-001 S1 범위와 PROPOSED 기술 상태는 유지하며 V-65는 미구성·미실행 계획이다.

상태: **2026-09-17 지점 관계·추가실적·월 기본급·보상 설정 권한 개정**. 공통 Architecture 검토의 입력이며 모든 상세 업무 정책이 결정되었다는 뜻이 아니다. [결정](product-decisions.md), [요구사항](requirements.md), [업무 규칙](business-rules.md), [권한표](users-and-roles.md), [OPEN](open-questions.md)을 함께 따른다.

추적: BR-PAY-001–013, BR-OPS-001. 위 지급 계산·등록 시 확정은 일반 Session Payment 적용 대상의 규칙이다. 2026-10-10 사용자 정정(MB-009 CLOSED)으로 타 지점 수업은 일반 PT 수당 대신 해당 수업의 보상 전체를 Additional Performance로 처리한다. 같은 수업의 일반 Session Payment를 정산에 별도로 더하지 않는다. 실제 수업 기록·Pass 차감·감사는 유지한다. 타 지점 지원 수업은 보상 금액 없이도 허용된 PT 진행 기록과 Pass 차감을 먼저 완료한다. 권한 있는 관리자가 나중에 수업 건별 금액을 저장할 때 해당 Additional Performance 보상을 확정한다. 금액 미입력은 확정된 0원과 구분하고 누락 건을 추적할 수 있어야 한다. 해당 Trainer의 해당 월 정산 대상 지원 수업에 금액 미입력 건이 하나라도 있으면 그 Trainer·월 정산을 확정할 수 없다. 타 지점 지원 수업 보상은 권한 있는 관리자가 사유를 기록하면 0원으로 명시적으로 확정할 수 있다. 사유 없는 0원 입력은 보상 확정이 불가하다. 사유를 남기고 확정한 0원은 금액 미입력이 아니므로 그 건으로 월 정산 확정을 차단하지 않는다. 다른 미입력 건이 남으면 기존 차단 조건을 유지한다. 월 정산 확정 전 지원 수업 보상 금액 수정은 Master Admin에게 Organization 전체, Branch Admin에게 대상 Trainer Home Branch가 자신의 관리 Branch인 경우 허용한다. 관리 범위 안의 본인 건도 허용하고 변경 이력을 남긴다. 월 정산 확정 전 지원 수업 보상 금액 수정은 Master Admin·Branch Admin 모두 관리 범위 안에서 본인 건을 포함해 별도 승인 없이 저장 성공 즉시 반영한다. Master나 다른 관리자의 승인 대기를 두지 않으며 권한 검증과 변경 이력을 유지한다. 월 정산 확정 전 지원 수업 보상 금액의 모든 수정에는 변경 사유가 필수다. 양수 간 변경·0원에서 양수로 변경·양수에서 0원으로 변경 모두 적용하며, 사유 없이는 금액을 수정할 수 없다. 변경 전후 금액·변경 사유·수정자·수정 시점을 이력으로 남긴다. 확정된 월 정산에서 지원 수업 보상 금액 오류를 발견하면 해당 Trainer·월 정산의 확정을 해제하고 금액을 정정한 뒤 해당 월 정산을 다시 확정한다. 이전 확정본은 이력으로 보존한다. 지원 수업 보상 금액 오류 정정의 월 정산 확정 해제·재확정은 Master Admin은 Organization 전체 Trainer, Branch Admin은 자신의 관리 Branch를 Home Branch로 가진 Trainer에 대해 허용한다. Branch Admin이 자신의 관리 Branch를 Home Branch로 가진 Trainer의 지원 수업 보상 정정을 위해 월 정산을 확정 해제·재확정할 때는 Master의 별도 승인을 두지 않는다. Master 승인 대기 단계 없이 관리 범위 안에서 직접 처리하며 이전 확정본과 해제·재확정 이력 및 감사를 유지한다. 지원 수업 보상 정정의 월 정산 확정 해제에는 사유가 필수이며, 사유 없이 해제할 수 없다. 사유·해제자·시점을 이력으로 남긴다. 과거 지원 수업 보상 정정·해당 월 정산 확정 해제/재확정에서 Branch Admin의 권한은 각 업무 처리 시점의 Trainer 현재 Home Branch를 기준으로 검증한다. 이전 소속만으로 권한을 유지하지 않으며 Master Admin의 Organization 전체 권한은 유지한다. 남은 정정·취소 절차는 BR-009/013 등 관련 OPEN을 따른다. 미입력 건의 추적 표현·정정 연동·지원 수업 외 추가실적의 남은 입력 제약·진행 기록 연계 상세·정정은 BR-013, 교차 업무 접근과 지점 귀속/공개는 관련 OPEN을 따른다. 예시 월 합계 2,500,000 + 1,200,000 + 150,000 = 3,850,000원은 유효 구성 합계 예시이며 타 지점 수업 보상액이나 지급 공식의 기본값이 아니다.

## Future 및 제외 경계

Member 로그인/Self-Service, 일정 조회·예약/취소, Member/Trainer Schedule 확장, Mobile App은 명시적 Future Scope다. v1에 예약 Domain·Member 로그인·App을 구현하지 않는다. 향후 도입을 불필요하게 어렵게 하는 구조적 제약과 Business Logic의 특정 Web UI 종속을 피해야 한다(NFR-013). 현재 API/Client 기술 선택은 없다.

기존 가계부·락커·수동 매출·고정 거래·계약/출석/고객 결제/환불/회원권/상담·migration tooling 제외를 유지한다. I3/I4로 여러 날짜 일괄 입력과 추가 연간 통계는 v1 제외/후속 보류이며 필수 월 정산·기존 Master 전용 지점 비용 보고서는 유지한다. 미확인 연동·import/export는 필수로 자동 승격하지 않는다. 빈 급여 팝업을 구현하는 요구와 승인된 기본급/추가실적은 구별한다.
