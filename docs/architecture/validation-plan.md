- 향후 서비스 계약/운영: 네트워크 실패·호환성·데이터 이전 대사. 현재 서비스는 없으며 추출 결정 후 수행한다.

## 검증 매트릭스

V-01/02/04/11의 일반 지급 계산·등록 시 지급 확정 검증은 일반 Session Payment 적용 대상을 전제로 한다. MB-009의 타 지점 수업 보상 전체는 V-15에서 추가실적으로 다루며 동일 수업의 일반 Session Payment를 별도 합산하지 않는지 검증한다. 타 지점 지원 수업 금액은 관리자 건별 수동 입력으로 확정했다. 타 지점 지원 수업은 보상 금액 없이도 허용된 PT 진행 기록과 Pass 차감을 먼저 완료한다. 권한 있는 관리자가 나중에 수업 건별 금액을 저장할 때 해당 Additional Performance 보상을 확정한다. 금액 미입력은 확정된 0원과 구분하고 누락 건을 추적할 수 있어야 한다. 해당 Trainer의 해당 월 정산 대상 지원 수업에 금액 미입력 건이 하나라도 있으면 그 Trainer·월 정산을 확정할 수 없다. 타 지점 지원 수업 보상은 권한 있는 관리자가 사유를 기록하면 0원으로 명시적으로 확정할 수 있다. 사유 없는 0원 입력은 보상 확정이 불가하다. 사유를 남기고 확정한 0원은 금액 미입력이 아니므로 그 건으로 월 정산 확정을 차단하지 않는다. 다른 미입력 건이 남으면 기존 차단 조건을 유지한다. 월 정산 확정 전 지원 수업 보상 금액 수정은 Master Admin에게 Organization 전체, Branch Admin에게 대상 Trainer Home Branch가 자신의 관리 Branch인 경우 허용한다. 관리 범위 안의 본인 건도 허용하고 변경 이력을 남긴다. 월 정산 확정 전 지원 수업 보상 금액 수정은 Master Admin·Branch Admin 모두 관리 범위 안에서 본인 건을 포함해 별도 승인 없이 저장 성공 즉시 반영한다. Master나 다른 관리자의 승인 대기를 두지 않으며 권한 검증과 변경 이력을 유지한다. 월 정산 확정 전 지원 수업 보상 금액의 모든 수정에는 변경 사유가 필수다. 양수 간 변경·0원에서 양수로 변경·양수에서 0원으로 변경 모두 적용하며, 사유 없이는 금액을 수정할 수 없다. 변경 전후 금액·변경 사유·수정자·수정 시점을 이력으로 남긴다. 확정된 월 정산에서 지원 수업 보상 금액 오류를 발견하면 해당 Trainer·월 정산의 확정을 해제하고 금액을 정정한 뒤 해당 월 정산을 다시 확정한다. 이전 확정본은 이력으로 보존한다. 지원 수업 보상 금액 오류 정정의 월 정산 확정 해제·재확정은 Master Admin은 Organization 전체 Trainer, Branch Admin은 자신의 관리 Branch를 Home Branch로 가진 Trainer에 대해 허용한다. Branch Admin이 자신의 관리 Branch를 Home Branch로 가진 Trainer의 지원 수업 보상 정정을 위해 월 정산을 확정 해제·재확정할 때는 Master의 별도 승인을 두지 않는다. Master 승인 대기 단계 없이 관리 범위 안에서 직접 처리하며 이전 확정본과 해제·재확정 이력 및 감사를 유지한다. 지원 수업 보상 정정의 월 정산 확정 해제에는 사유가 필수이며, 사유 없이 해제할 수 없다. 사유·해제자·시점을 이력으로 남긴다. 과거 지원 수업 보상 정정·해당 월 정산 확정 해제/재확정에서 Branch Admin의 권한은 각 업무 처리 시점의 Trainer 현재 Home Branch를 기준으로 검증한다. 이전 소속만으로 권한을 유지하지 않으며 Master Admin의 Organization 전체 권한은 유지한다. 남은 정정·취소 절차는 BR-009/013 등 관련 OPEN을 따른다. 두 단계 각각의 원자성·연계·재시도 검증을 계획하며 미입력 지원 수업이 남은 해당 Trainer·월 확정 차단은 V-12/15에서 검증을 계획한다. 나머지 월 귀속·마감/정정의 기대 결과는 관련 게이트 해소 후 상세화한다. 아래 항목은 실행 결과가 아닌 계획이다.

## 현재 검사 장치 상태

backend/에 Ruff/mypy/pytest/Import Linter 및 Alembic 실행 환경을 구성했다. [실제 명령](../../backend/README.md)과 현재 [WSL 이전 검증 기록](wsl-migration.md)을 따른다. [FOUNDATION-001](foundation-001.md)의 Windows 당시 결과는 이력으로 유지한다. WSL에서는 빠른 검사와 실제 PostgreSQL 기반 검사 3개가 통과했다. V-16/17의 기반 코드 검사는 실행 가능하지만 미래 업무 모듈 전체를 검사한 것은 아니다. Alembic 온라인 `current`까지 확인했으며, V-18의 업무 schema migration과 지급 계산·업무 동시성·운영 배포 준비 검증은 미완료다. 위 V-01–20 업무·운영 검증 계획을 일괄 완료 처리하지 않는다.

다음 문단은 Architecture 1차 설계 당시 기록이다.

작업 시작 시 저장소에는 Product/AS-IS 문서와 루트 README만 확인되었다. 애플리케이션, pyproject/requirements, 테스트 코드, Alembic 환경, CI, 타입/의존성 검사 설정이 없다. 이번 작업에서도 만들지 않는다. 실행 가능한 pytest/lint/migration 명령으로 안내할 항목은 아직 없다.
