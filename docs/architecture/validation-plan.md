# 후속 검증 계획

Status: PROPOSED — 테스트 코드·자동 검사 구성·실행 결과가 아닌 계획
작성일: 2026-09-17
타입 검사·모듈 의존성 검사·업무/권한/동시성 테스트를 포함하는 방향 자체는 사용자 승인이다. 도구·구체 설정·아래 상세 검증 방식은 후속 검토한다.

관련 원본: [Requirements](../product/requirements.md), [Business Rules](../product/business-rules.md), [NFR](../product/non-functional-requirements.md), [결정 게이트](decision-gates.md), [트랜잭션 초안](data-and-transactions.md).

## 수준 구분

- 단위: DB 없는 계산·정책 함수. 결정된 입력/결과만 검증한다.
- Use Case/계약: 인가·오류 전파·민감 필드·모듈 계약을 검증한다. test double만으로 DB 원자성/동시성 증명이 되지 않는다.
- PostgreSQL 통합/동시성: 선택한 실제 버전·드라이버에서 독립 연결/UoW의 실행 순서를 제어하고 commit/rollback 후 원본·잔여·금액·감사를 대사한다. SQLite/in-memory 대체로 완료 처리하지 않는다.
- 정적/구조: 타입·금지 import·순환·Framework/ORM 경계 검사. 문서 DAG 확인과 실제 코드 검사 결과를 구별한다.
- 향후 서비스 계약/운영: 네트워크 실패·호환성·데이터 이전 대사. 현재 서비스는 없으며 추출 결정 후 수행한다.

## 현재 검사 장치 상태

backend/에 Ruff/mypy/pytest/Import Linter 및 Alembic 실행 환경을 구성했다. [실제 명령](../../backend/README.md)과 현재 [WSL 이전 검증 기록](wsl-migration.md)을 따른다. [FOUNDATION-001](foundation-001.md)의 Windows 당시 결과는 이력으로 유지한다. WSL에서는 빠른 검사와 실제 PostgreSQL 기반 검사 3개가 통과했다. V-16/17의 기반 코드 검사는 실행 가능하지만 미래 업무 모듈 전체를 검사한 것은 아니다. Alembic 온라인 `current`까지 확인했으며, V-18의 업무 schema migration과 지급 계산·업무 동시성·운영 배포 준비 검증은 미완료다. 위 V-01–20 업무·운영 검증 계획을 일괄 완료 처리하지 않는다.

다음 문단은 Architecture 1차 설계 당시 기록이다.

작업 시작 시 저장소에는 Product/AS-IS 문서와 루트 README만 확인되었다. 애플리케이션, pyproject/requirements, 테스트 코드, Alembic 환경, CI, 타입/의존성 검사 설정이 없다. 이번 작업에서도 만들지 않는다. 실행 가능한 pytest/lint/migration 명령으로 안내할 항목은 아직 없다.

루트 [AGENTS.md](../../AGENTS.md)는 사람이 읽는 작업 규칙이다. 위 검사 장치를 구현하거나 자동 통과시킨 것이 아니다. 구현 시 승인된 대상 기능의 게이트를 먼저 확인하고 그 기능에 필요한 검증부터 구성한다.

## 이번 단계의 문서 검증 기록

문서 링크/앵커 검사와 설계 검토는 별개다. 완료 시 Architecture README에 실제 수행 결과를 기록한다. 공식 문서 읽기는 실행/호환성 시험이 아니며, 위 V-01–20은 후속 계획으로 유지한다.
